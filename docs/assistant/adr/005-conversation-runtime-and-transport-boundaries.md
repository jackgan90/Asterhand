# ADR-AST-005：持续会话的运行时、存储与通信边界

- 状态：accepted（架构决策已采用；产品验收见功能验证说明）
- 日期：2026-10-27
- 所属领域与需求：助手 AST-CHAT-01—08；执行器、节点、Web、安装与测试的关联要求见[功能计划](../../development/features/local-node-chat/plan.md)。
- 替代关系：新增持续会话路径；[ADR-AST-002](002-agent-exec-runtime.md) 对既有任务执行继续有效。[输入宿主 ADR](../../installation/adr/007-quick-input-process-isolation.md)的隔离和草稿恢复原则保留，本次聊天扩展其“仅输入”能力集，保留权限与生命周期约束。

## 背景

快捷输入已提供全局热键、独立非提权 WebView2 宿主和内存草稿。当前每个任务独立调用 `agent exec`，没有持续多轮聊天。产品需要本机文本对话、可展开的聊天展示和持久历史，并希望后续接入其他 harness、可执行任务的 session、多节点、多角色及跨机器聊天。

聊天记录优先使用 harness 自己的存储，避免 agentd 维护重复的完整正文数据库。入口未来可以通过 `@` 选择任意位置的节点/角色，首版仅当前节点与默认角色。

## 决策

1. 增加独立于任务队列的会话服务和会话运行时能力接口。会话、轮次、消息和任务有不同身份与生命周期；首版只开放文本交流，工具关闭。
2. UI 经封闭原生桥和本机会话客户端访问 agentd，agentd 负责目标、授权、请求身份和对账；厂商 RPC、凭据与路径仅在后端适配器中使用。
3. 首个适配器拟使用受管 OpenClaw Gateway，独立持久 state，与现有一次性任务状态隔离。Gateway 不是公共接口要求；后续适配器可采用其他正式接口。
4. 目标节点拥有会话权威，harness 持有正文与原生上下文。agentd 只保存稳定会话目录、角色/runtime 绑定与必要的请求恢复元数据；不保存完整正文副本或每个 token 的持久日志。
5. 公共操作显式使用 node/role/conversation 身份；runtime 原生引用和分页游标保持不透明。首版只实现本机通信，保留远程同语义接入点。
6. 发送去重、可靠接收、取消与事件恢复依赖已验证的运行时证据；未知结果不自动重放。UI 生命周期不控制轮次生命周期。
7. 当前默认 runtime 变化不改绑旧会话。跨 harness 历史迁移和续聊单独设计，不承诺原生上下文、工具状态和 memory 无损迁移。

这些决定确定规划方向。锁定依赖的能力验证与 UI 组件评估是正式实现前的门槛；验证失败需修订设计和范围，不临时改为直连 LLM、自建完整历史库或关闭安全边界。

## 备选与后果

| 方案 | 收益 | 代价 / 选择 |
|---|---|---|
| UI 直连 Gateway | 少一层转换，直接消费原生事件 | UI 接触厂商协议和认证，改变当前禁网边界；不采用为首版默认 |
| 普通聊天复用 route job | 可复用现有提交入口 | 缺少连续上下文，受任务槽/待核对阻塞，重复保存正文；不采用 |
| agentd 直接调用 LLM 并保存历史 | 容易统一消息库 | 绕过 harness 会话与记忆，新增完整存储及工具循环责任；不采用 |
| 会话服务 + 运行时适配器 | 保留安全与产品边界，便于替换 harness 和远程接入 | 增加 Gateway 生命周期、状态核对和事件适配；选定方向 |

不建立通用插件市场、DAG、自动 placement 或全网聊天同步。类型化内容块和可替换传输有明确后续需求支撑，但首版不实现未来媒体和工具分支。

历史归 harness 管理使运行时退出/卸载后的读取和迁移依赖原适配器；需要明确保留策略、配置绑定及旧格式诊断。可靠接收前的草稿仅存内存，节点崩溃可能丢失未确认正文；该边界必须在 UI 和验收中可见。
