# ADR-AST-009：模型按需配置，诊断与功能准入分离

状态：接受。细化 ADR-AST-001，并替代 [ADR-AST-003](003-provider-runtime-bundle-boundaries.md) 中“新候选必须先重新 probe 才能使用”的运行时策略；保留依赖兼容验证和发布证据绑定。

## 原因

真实工具 probe 能检查模型、插件与回调链路，但独立运行时启动和模型工具往返会阻塞日常迭代。将源码摘要绑定的诊断结果作为全局能力门槛，还会使 UI 修改后必须重新调用模型，并误把不需要模型的基础节点标为不可用。

## 决定

- 节点运行、功能本地配置和手动诊断分别表示。启动、设置、托盘、快捷输入及任务记录不要求模型凭据或模型调用。
- 聊天和模型任务只在实际使用时检查自己的必要配置；直接执行真实请求，不额外发起测试请求。未来确定性脚本依赖自己的执行能力，本次不实现脚本。
- 能力状态由 executor 根据配置、可读取凭据与本地安装条件计算；查询不启动子进程、不遍历整个依赖树。聊天不依赖文件工具和授权目录。
- 任务接收先保持原子去重与取消墓碑，再对全新未取消请求做准入。已有接收记录和已取消请求不因模型配置缺失而丢失确认语义。缺配置的明确拒绝绑定 origin/request ID/摘要并持久保存独立 receipt；提交成功后才返回终局拒绝，确保恢复配置后旧迟到请求仍不能执行。数据库升为 schema 2 阻止旧程序忽略拒绝屏障；已有任务/事件结构保持。超时及未知响应仍按原目标/ID 对账。
- 手动模型工具测试继续可用，成功证据绑定源码、依赖及有效配置，改变后只标诊断过期。发布与依赖升级的真实验收继续执行，不以功能可尝试使用替代兼容验证。
- 旧 ready 保持手动诊断通过的含义，新 UI 优先使用能力字段；旧节点继续使用旧门槛并提示验证或升级。

## 影响与验证

首次真实操作可能报告凭据、网络或运行时错误；这些错误归属于该操作，不阻断节点其他功能。首次 Gateway 冷启动和模型响应延迟仍存在。权限检查、固定目标、请求幂等、取消和重启对账保持。

明确拒绝后需要新请求 ID。Web 校验请求归一化摘要，保留草稿并释放原 pending 身份；未知响应继续保留身份。schema 2 任务库不支持旧二进制原地回退，旧程序会明确拒绝打开；避免出现界面已停止投递、目标仍执行的分歧。

覆盖无凭据启动、无 probe 的真实入口、诊断过期、缺配置拒绝、先取消后提交、响应丢失后配置变化、旧 peer 与离线缓存；方法见 [功能计划](../../development/features/on-demand-model-readiness/plan.md)。
