# ADR-AST-010：跨 harness 工具能力与本机优先

- 状态：accepted；首批以正式文件 I/O 桥接实现。下文默认关闭策略已由 [ADR-AST-011](011-default-assistant-tools.md) 替代，其他决定保留。验证边界见功能计划。
- 所属需求：AST-TOOLS-01—06、EXEC-TOOLS-01—06。
- 设计：[本机工具能力](../runtime-capabilities.md)；[计划](../../development/features/local-runtime-tools/plan.md)。
- 替代关系：替代 ADR-AST-005 的永久零工具限制，保留默认关闭；其会话权威、目标身份与恢复原则保留。旧任务路径的 ADR-AST-002 仍用于兼容，不再作为新工具能力的主入口。

## 背景

产品方向是通过持续聊天让所属节点的助手工作，并在会话中观察进度与结果。当前先完善本机节点，逐步接近原生工具能力，再评估远程聊天。OpenClaw 是首个实现，后续 Hermes、DeepSeek Harness 或自定义 harness 需要保留各自工具循环与上下文优势。

## 决策

1. 公共层统一语义能力、工作区身份、授权约束、执行观察、产物和恢复；原生工具名称、配置、RPC、工具循环与正文留在 adapter/harness。
2. 原生能力优先；必须有执行处约束，可使用正式 hook/插件和窄共享服务补齐。缺失约束时关闭对应能力，不用提示词模拟限制。
3. 第一批仅本机文件/发现/记忆/进度/产物与文件恢复，不执行代码或脚本。网络、隔离执行、委派、后台任务等分批实现；远程聊天排在本机能力完善之后。
4. 逻辑工作区与 runtime state/秘密/控制文件分离。允许工作区人格和记忆演化，执行权限始终由节点控制。
5. 首批工作区内工具轮次串行，所有修改有前像及逐项结果；未知副作用先核对，不自动重试或回滚。
6. 公共日常操作覆盖 UI/CLI/MCP；内置助手单独持有窄授权，禁止全量自动化工具回流形成脚本执行旁路。

## 备选与取舍

| 方案 | 结论 |
|---|---|
| 只改 OpenClaw 工具白名单 | 开发少，但无法覆盖展示、恢复、文件保护和后续 harness；不采用 |
| 所有 harness 都调用重新实现的统一文件工具 | 容易统一但损失原生能力并扩大维护；仅对缺口补小服务 |
| 一开始实现通用 sandbox 和所有工具 | 超出第一批开发量；按真正需要执行代码的批次加入 |
| 小的公共契约 + 原生适配 + 受限补充服务 | 采用；需对每个支持的版本和约束做真实契约验证 |

## 后果

第一批不是完整 OpenClaw 功能集合；原生能力扩展通过后续批次逐步达成。需要少量事件/文件版本元数据，但不接管会话正文。原生 hook 不足是明确的实施门槛，不以未经验证的 SDK 名称掩盖成本。
