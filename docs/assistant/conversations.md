# 持续会话设计

状态：当前源码已接入，工程验证与产品验收分开记录。首个交付为 Windows 快捷输入中的本机文本聊天；远程聊天、多角色、多节点和其他 harness 仅保留边界。需求见[助手需求](requirements.md)，实施与验收见[本机持续聊天计划](../development/features/local-node-chat/plan.md)及[验证说明](../development/features/local-node-chat/validation.md)。架构取舍见 [ADR-AST-005](adr/005-conversation-runtime-and-transport-boundaries.md)。

## 目标与现有路径

快捷输入是多功能入口，聊天是第一个可执行操作。当前 [Executor](../../internal/executor/executor.go) 每 attempt 启动独立 `agent exec`，现有 Web 输入形成 route job；两者保持原任务语义。本功能增加持续会话路径，不把每条普通聊天消息包装成任务，不把快捷输入永久定义为聊天专用组件。

本文的 agentd 指 Asterhand 节点核心服务，不新增一个名为 agentd 的独立程序。harness/runtime 指承担模型会话和工具循环的运行时；LLM provider 与运行时继续按[助手设计](design.md)分层。

```text
快捷输入 / 聊天面板（非提权 UI）
              ↕ 有界、封闭的原生桥与 IPC
会话客户端 → 目标解析 / 通信适配 → 目标节点的会话服务
                                    ↕ 会话运行时适配器
                            本机 OpenClaw Gateway
                                    ↕
                            LLM / 原生会话存储
```

首版目标解析仅接受当前节点和默认助手；通信为本机路径。目标节点拥有会话权威，即使未来入口和目标不在同一台机器也保持此规则。公共层不暴露 Gateway RPC、原生 session key、内部路径或模型凭据。

## 职责与依赖方向

| 模块 | 职责 | 不承担的职责 |
|---|---|---|
| 输入编辑器 | Unicode、IME、草稿修订、显式发送意图 | 推断节点身份、执行文本或持有凭据 |
| 会话客户端 / 展示 | 当前目标、会话选择、消息合并、分页、状态与资源释放 | 解释厂商 session 格式、决定运行是否已停止 |
| 目标解析与通信 | 将稳定目标定位到连接；认证上下文、超时和连接状态 | 从显示名推断权限、失败后换目标重发 |
| 节点会话服务 | 会话归属、能力与授权检查、绑定目录、请求身份、内存待发队列、轮次准入和对账 | 持久保存完整聊天正文或接管模型工具循环 |
| 会话运行时适配器 | 原生会话映射、历史、实时事件、取消、持久接收证据、运行时生命周期 | 假装支持缺失能力、修改任务协议 |
| 任务服务 | job/attempt、受限工具、产物、任务恢复 | 调度首版普通聊天 |

会话能力与 `Executor.Execute` 并列，避免向一次性任务接口塞入聊天状态。可以复用运行时选择、配置描述与凭据边界；不要求只提供会话的未来适配器实现无意义的任务方法。当前唯一生产实现仍为 OpenClaw。模型/provider 不随 UI 组件选择改变。

## 领域对象与稳定身份

| 对象 | 必要信息与不变量 |
|---|---|
| ChatTarget | `node_id`、`role_id`；首版解析为当前节点与稳定默认角色 ID，显示名只用于展示 |
| Conversation | Asterhand `conversation_id`、目标、创建时间、角色配置修订、运行时绑定引用；由目标节点分配并维护 |
| RuntimeBinding | runtime 类型、逻辑实例/配置引用、原生会话引用与存储代次；适配器私有，独立于进程 PID 和临时端口 |
| Submission | `request_id`、conversation、已认证发起身份、规范化内容摘要；确认丢失时保持相同身份 |
| Turn | 一次用户提交产生的处理过程；公共 `turn_id` 与原生 run ID 可不同，由适配器关联 |
| Message | 稳定 `message_id`、发送者、时间、所属轮次、类型化内容块；首版只有文本块 |
| Event / Snapshot | 会话/运行时绑定代次、事件身份或顺序、消息修订及恢复游标；快照与增量有明确衔接点 |

创建会话也需要稳定操作 ID：先记录待创建元数据并返回稳定 conversation ID，原生创建/打开按队列顺序完成；响应丢失后按原标识核对，不生成第二个底层会话。返回 `creating` 表示已经分配身份，可以提交依赖它的待发消息；只有确认原生绑定并持久写入目录后才报告 `ready`。创建失败将依赖消息记录为明确未送达，并释放待发队列；之后主动发送的新消息会重新准备同一会话，旧失败消息保持终态。读取未准备或创建失败的会话不自动重试创建。

会话目录保存目标、角色修订、runtime 绑定、时间和必要恢复元数据；当前选择与待确认提交保存在主进程 RAM，UI 重建恢复选择，节点重启默认打开最近更新的会话。不复制正文、完整工具日志或 token 流。首版标题使用“对话 + 创建时间”等非正文元数据，不另加模型生成标题调用。UI/连接/session 的临时代次与业务 conversation ID 分开，旧页面的迟到回复不能覆盖新页面或其他会话。

选择器变化只影响新目标或新会话。已有会话始终使用原目标与 runtime 绑定，不在每轮重新读取“当前默认 runtime”后静默改绑。首次创建固定当前角色修订；首版默认角色没有编辑功能。未来角色更新、权限收紧和会话迁移遵循下文边界。

## 最小会话契约与能力声明

下表定义产品语义，封闭请求、响应和错误的字段权威是 internal/conversation/wire/protocol.go，首版没有独立 HTTP 聊天路径。原生会话 ID 与生命周期留在适配器绑定中；消息 ID 作为不透明引用，首个适配器将服务分配的 turn ID 用作原生幂等 run ID。

| 操作 | 语义 |
|---|---|
| Describe / Readiness | 声明持久会话、历史分页、流式事件、取消、状态核对及输入/输出限制；区分静态能力和当前就绪 |
| Create / Open / List | 创建、恢复、分页列出当前主体有权访问的会话；列举只读元数据，不调用 LLM |
| Submit | 提交明确会话的文本，返回拒绝、送达待确认或可靠接收凭据；可异步运行 |
| Observe / Reconcile | 订阅事件，查询指定请求/轮次的真实状态；游标失效返回需要新快照，不能伪造连续流 |
| ReadHistory / ReadMessage | 有界分页读取可见历史；超大单条消息通过有界片段读取完整可见正文 |
| CancelTurn | 请求停止指定已确认接收的模型轮次，保留用户消息，不暂停后续队列；迟到取消不能取消新的轮次 |
| Prepare / Enqueue | 登记异步创建和绑定明确会话的待发文本，返回节点内存托管状态 `queued` |
| Queue / QueueItem | 读取带单调修订号的节点队列及近期失败快照；单条读取正文或已离队操作的真实轮次，供宿主重建和回执补读；不暴露撤回、暂停或恢复队列操作 |

持久会话、历史访问和发送结果核对是聊天基础要求。首个 OpenClaw 适配器必须验证流式回复和停止；其他 harness 通过能力协商暴露差异，不使用空实现宣称支持。未知能力、协议版本或 runtime 返回可诊断的不支持错误，不回退另一节点、模型或运行时。

分页游标保持不透明，绑定 conversation、runtime 存储代次和查询条件；运行时升级或重建后不能当作普通 offset 继续使用。扩展字段按协议版本协商，首版仍执行已知消息类型及字段的封闭校验。

## 发送、去重和草稿

1. 编辑器在首次跨越可能丢失响应的通信边界前，为发送意图取得稳定操作 ID，连同已完成 IME 的文本快照及草稿修订提交。原生主进程在转交会话服务前绑定该 ID、会话、快照和修订；服务端校验身份、会话、能力、大小和执行槽。
2. 每节点最多一个聊天生成轮次，独立于任务执行槽；启动、创建或已有生成期间，发送进入节点主进程的有界内存 FIFO。新建依赖先执行，每条固定提交时的目标、操作 ID、正文及草稿修订；切换界面不改目标。读取历史和列表不占生成队列。
3. 在交给 runtime 前持久保存请求元数据（ID、摘要、会话、绑定和待确认状态）。正文在接收确认前保留在原生内存草稿/有界发送快照中。
4. 只有已验证的 runtime 持久接收凭据才可映射为 accepted。网络响应、run ID、started 字样或屏幕上出现文本本身均不足以证明已持久接收。
5. 发送意图生效时立即将输入区显示转移到临时气泡。节点确认 `queued` 后可清除该修订的编辑器恢复快照，由节点队列继续托管正文；这与 runtime 的持久 `accepted` 分开。用户后来输入的新内容及新修订保持，迟到确认和失败恢复都不得覆盖。UI 中的临时气泡按请求身份合并为原生消息，不按文本相等去重。
6. 响应丢失先按原目标、会话和 request ID 查询；确认未接收时才允许使用同一 ID/正文重试。相同 ID 不同摘要拒绝。已接收、完成或未知状态均不生成新 ID 自动重发。

队列默认最多 8 条待发消息、正文合计 128 KiB，创建与发送操作合计最多 16 项；每条仍为 16,000 UTF-8 字节。上限为初始资源预算，调整依据队列峰值、等待时长与使用数据。队满拒绝新增并保留新草稿，不淘汰已收下的消息。UI 的 16 项展示快照预算包含待发、在途和近期结果，尚未确认的项不被淘汰。

这些内部状态不要求用户区分。点击发送即显示普通用户消息，初始化、排队、派发和生成统一呈现回复等待，不显示队列数量、准备阶段或逐条撤回按钮。后端保留准确的接收事实，实际异常在对应消息旁提示未送达、送达待确认或回复失败。展示契约见[Web 聊天设计](../web/design.md)。

“停止回复”只针对已确认接收且尚未结束的轮次，直接按原操作身份请求停止；不删除用户消息、不暂停后续派发，也不提供停止发送、取回、撤回或继续队列功能。明确启动或发送失败先持久记录终态，再释放待发队列；元数据写入失败只重试记录，不再次提交正文。未知结果保留同一操作并阻止重复派发，确认接收后离队；已确认轮次停止但接收仍未知时释放调度，保留未知事实，不能误报未送达。

近期失败操作最多保留八项有界 RAM 快照，单条正文遵守既有输入上限，独立于待发容量与配置/退出忙状态。队列响应只携带失败身份和结果，宿主按单条读取失败正文；失败快照淘汰后终态元数据仍可查询，已在界面恢复的正文不主动删除。历史正文仍以原生运行时为权威，不新增本地持久离线队列。实现见[聊天发送与停止回复](../development/features/chat-send-intent/plan.md)。

主进程保存正文 RAM，元数据目录只记录摘要和身份。窗口隐藏、关闭或宿主重建保留队列，重建按单条恢复正文；正常退出明确确认丢弃待发内容，崩溃或退出后不自动续发。恢复时只有入队元数据、没有提交记录的操作标记为未派发取消；已有提交记录继续原有对账。模型、凭据与运行时配置变更在队列非空时拒绝，外观设置独立。实现与验证见[聊天操作队列](../development/features/chat-operation-queue/plan.md)。

稳定的请求身份必须贯通 runtime 去重和持久收据，而非只在 agentd 内维护内存去重。重启后去重有效期/历史清理后的行为需要原生证据；超出可确认窗口返回结果未知并禁止自动重放。两条刻意重复的相同文本使用不同 request ID，视为两次输入。

操作 ID 可直接作为 request ID；若业务 request ID 由服务端分配，必须能按原操作 ID 重查映射。UI 重建先读取主进程登记的待确认提交及草稿修订，不凭文本猜测或生成新 ID 补发；未登记的旧宿主代次消息拒绝。该关联在调用 runtime 前随请求元数据持久化，正文仍遵守内存草稿边界。

发送元数据不保存完整正文，因此主进程在 runtime 持久接收前崩溃时，未确认正文可能与草稿一起丢失。重启仍按请求元数据核对并显示送达状态；不把丢失草稿承诺为可恢复消息，也不提示用户在未知结果时盲目重发。已被 runtime 可靠接受的输入必须可恢复。首版不实现持久离线发送队列。

## 历史、持久化和恢复

- 聊天正文、原生上下文和模型内部压缩由 harness 保存；目标节点上的稳定数据目录是唯一正文权威。agentd 不直接改写其数据库，也不通过监视内部文件重建另一份完整历史。
- 打开会话恢复最近一页，默认最多 50 条可见消息，按字节预算提前截断页面并提供续页；向上翻页加载更早内容，不以“今天”作为默认过滤条件。会话列表也分页。
- 历史展示与模型上下文分开。压缩模型上下文不意味着删除可见聊天；实现前验证压缩、reset、归档和维护策略，确保应用拥有的会话不会因默认年龄/数量策略被静默删除。首版不提供删除/自动清理；容量不足明确拒绝新写入并保留已有数据。
- 只读取当前用户可见的 user/assistant 内容，不泄露 system prompt、凭据、隐藏推理或内部控制消息。历史接口可能返回截断预览；完整内容通过 ReadMessage 获取，无法获取时显示原因。
- 实时片段只是暂态展示。完成状态分别表达运行结果和正文保存状态；已停止但部分回复未保存时显示“部分内容未保存”，不能在重开后伪造完整回复。
- UI 收起、关闭或崩溃只结束展示/订阅，不取消生成。重建后先订阅并取得一致快照，或采用带水位的等价协议，再合并后续事件；处理重复、迟到、快照期间完成与游标失效。
- Gateway 或节点退出后，已保存会话可重开；在途轮次先核对。确认完成/失败/停止后显示真实结果；确认进程已结束且没有恢复运行时标为 interrupted，尚不明确时保持 unknown。两者均不自动重跑用户消息。下一轮只在确认旧轮次已停止后允许发送。
- 运行是否仍可能继续、请求是否曾被接受、正文是否保存分别记录。证据确认旧轮次已停止且不会恢复执行后，释放生成槽及配置 busy；历史收据或保存状态仍未知时保留诊断，不自动重放原消息，也不永久占用运行槽。仅进程断连或查询超时不足以释放槽。
- 仅订阅重连允许有界退避；重连和只读操作不能暗中启动模型。停止请求与完成竞争按运行时事实裁决，超时不能直接记 cancelled。

请求/会话目录与 harness 数据无法跨数据库原子提交，适配器需提供可重复的收据查询和绑定恢复。启动后先核对目录中的 creating/pending/running 项；保存目录失败不继续发送，runtime 接受后目录回写失败保留原 ID 并转待核对，不伪造失败后重试。

## OpenClaw 首个适配器

采用受 agentd 管理的本机 Gateway，按首次打开历史或发送需求启动，并在节点运行期间复用。Gateway 是本适配器的内部选择；其他 harness 可以使用 SDK 或受管子进程。

使用[依赖清单](../../packaging/dependencies.json)锁定版本。包内 `docs/web/webchat.md`、`docs/cli/agent.md` 和客户端实现是验证入口；官方 [WebChat](https://docs.openclaw.ai/web/webchat) 与 [Gateway 协议](https://docs.openclaw.ai/gateway/protocol)仅作为上游资料。隔离验证确定以下内部映射；它们不进入公共客户端契约：

- `sessions.create` 使用由持久会话 ID 派生的固定 key，重试保持 key，并核对返回的原生 session ID。
- `chat.send` 的 `idempotencyKey` 在分派前写入请求元数据。`messageSeq` 可证明用户消息已提交；只有 `started` 时继续查询 `chat.history` 的收据和用户消息身份，不提前丢弃待确认恢复快照；输入区显示已在发送时清空。锁定版本的 `INVALID_REQUEST` 加 `active-leaf-changed`、`session-settings-changed`、`session-routing-changed` 明确表示接收前拒绝，映射为 rejected 并释放槽、保留草稿；重连失败或传输层在写出前因连接状态/容量明确拒绝，同样映射 rejected；写出已尝试后的异常、响应超时及其他原生错误维持 unknown，不自动重发。
- `chat.history` 以 `inputRunIds` 核对待处理收据，以消息的稳定身份和原始提交身份匹配已提交消息。历史页使用 `nextOffset`，原生游标失效时重取快照。
- `chat.message.get` 读取单条完整显示正文；后端按公共片段预算切分。适配器仅在 RAM 缓存一条原生读取结果，最多 32 MiB、30 秒，绑定会话/session/生命周期/message ID；每次读取仍核验原绑定。超出原生 8,000,000 字符读取限额或可见正文仍截断的结果拒绝当作完整正文。整体 display-cap 标记可能来自非展示字段，由适配器按锁定版本的文本预算规则解释；仅在片段恰好耗尽共享预算时追加包含块间分隔预算的有界探测；正文相同且探测本身确认完整才清除截断状态，不批量读取全文。运行时返回 `oversized` 或 `not_found` 时明确显示不可用，不把预览冒充完整正文。
- `chat.abort` 只针对原会话和原 run ID，停止模型回复并保留用户消息；不设置 `discardPendingInput`。锁定版本的该参数专用于撤回待处理输入，运行中的轮次会被跳过。停止响应不直接等同于轮次结束，随后查询运行状态，确认结束才释放生成槽。Gateway 重启不重新提交历史未知请求。

Gateway 连接只取得 `operator.read` 与 `operator.write`。`sessions.compact(maxLines)` 是管理员截断接口，会使旧消息无法通过当前历史接口读取；产品不调用或暴露此接口，也不开放 reset、delete 或管理命令。正常模型上下文压缩已验证保留正文。reset 会改变原生生命周期版本并切换当前历史视图；适配器绑定同时核对 session ID 与生命周期版本，遇到变化明确拒绝继续写入原会话。会话维护固定为 `warn`，reset 固定为 `none`。

会话配置/state/workspace 位于节点数据目录内独立且受保护的子目录，与现有 `runs/<attempt>/state`、个人 OpenClaw home 和其他节点的数据目录隔离。Gateway 和一次性执行不共享需要独占写入的 state。地址由实例管理分配并认证，不能固定全机唯一端口或接管已存在的不明 Gateway。

配置继承当前节点选择的 provider/model/credential_ref；密钥由适配器在后端注入，UI、任务文本、会话目录和诊断中不出现明文。默认聊天角色禁用所有工具、shell、skills 执行、任意插件发现、外部渠道发送与自动任务。只加载所需模型 provider 和应用自带的可信聊天提示词插件，关闭默认 memory 插件槽，并以真实有效工具集合和拒绝用例验证。OpenClaw 配置同时设置 `tools.deny: ["*"]`、`tools.toolSearch: false` 和 `tools.codeMode.enabled: false`；仅 deny 列表不足以移除模型请求中的包装工具。管理命令设置 `commands.allowFrom: {"*": []}`，适配器另行拒绝去除前导空白后以 `/` 开头的输入并保留草稿。

普通文本不进入 runtime 管理命令分派。优先使用已验证的纯文本调用入口；若该版本不能可靠关闭命令/skill 语法，相关输入在适配器调用前明确拒绝且保留草稿，不静默执行 `/reset`、`/new` 或配置命令。应用“新对话”调用自身受限操作，不借用户文本绕过权限。

## 安全、生命周期与资源

沿用独立非提权 UI、可信静态资源、禁止直接联网和受限原生桥；IPC 仅增加会话列举/创建/读取/提交/订阅/停止等明确能力，不提供任意 URL、路径或 Gateway RPC 代理。宿主身份/代次、消息大小和会话归属在主进程校验。富文本不可信，渲染规则见 [Web 设计](../web/design.md)。

聊天配置状态独立于文件工具诊断：仅检查凭据可读取、所选模型/runtime 有效及固定运行时/provider 的本地安装条件，不要求任务工具插件或文件任务授权目录。检查不启动进程、不调用模型；首条真实消息按需启动 Gateway。`ModelVerified` 仅代表手动诊断证据，详见 [ADR-AST-009](adr/009-on-demand-model-readiness.md)。凭据/provider/model/runtime 有效变化后重新检查本地配置；无凭据仍可读取已有历史，读取不调用模型或工具诊断。

首版有效模型/runtime/凭据配置变更在本机有聊天在途或尚未能证明停止时返回 busy，要求先停止并核对；不能无提示地重启 Gateway。已确认停止的历史送达/保存未知不单独阻止配置变更。空闲时重载后按新配置判断能力，不要求额外模型测试；同 runtime 的新轮次可使用新模型并记录有效选择。更换 runtime/状态目录时新会话采用新绑定，旧会话保留原绑定，只读不可用时给出明确原因，不静默重定向。回退安装旧版本不得删除新会话数据或盲目写入较新 schema。

节点关闭先停止会话准入，再请求停止本机轮次并有界收尾、保存可确认状态，最后停止自有 Gateway 与 UI；托盘忙时确认覆盖聊天。强制退出后的不明状态由下次启动核对。UI 故障、聊天运行时故障和任务执行隔离；后台回复不得抢焦点。首版 Gateway 初始化失败只使聊天不可用，输入草稿、设置和既有任务服务继续。

输入沿用 16,000 UTF-8 字节上限。IPC 单帧保持 128 KiB 硬限，历史页/事件批次以序列化后的 64 KiB 为目标，超大单条文本用有界片段，禁止为传全量历史解除帧限。首版可见消息缓存最多 200 条且正文合计不超过 2 MiB；超长正文按需加载片段，淘汰后可重新读取，不能删除权威历史。事件缓冲按序列化字节限制到 1 MiB；压力下合并文本更新或通知 resync，不丢弃关键状态后伪装连续。

首版单轮生成墙钟预算为 10 分钟，超时走停止和核对。Gateway 按需启动由节点运行时持有独立的 180 秒总预算，覆盖本地依赖检查、进程启动和认证；历史查询与发送共享一次启动，某个调用者取消或等待超时只结束该调用者的等待，保留正在进行的恢复。启动预算是资源回收上限，不是响应速度目标；旧进程租约触发的数据库完整性检查允许在此期间完成。节点关闭会取消启动并等待自有进程回收，不留下后台启动。配置变化后重新核验有效配置摘要，旧配置完成的启动不会被新请求直接采用。

队列模式先确认节点托管，后台准备最多等待 210 秒，覆盖运行时独立的 180 秒启动预算及会话准备；成功后按顺序派发。原生提交从准备完成后开始计算 90 秒预算，快捷入口单次请求仍为 95 秒。准备失败记录未送达终态并离队，近期失败正文留在独立展示快照中，后续消息继续；兼容的直接提交入口失败时保留草稿。Gateway 查询与停止请求各 15 秒，提交 RPC 等待 30 秒；写出后的超时仅改变确认状态。关闭先请求停止，最多等待 15 秒，再回收自有 Job，进程退出核对最多 5 秒。连接就绪要求 WebSocket 和 connect 认证均完成；并发调用共享握手结果，断开立即撤销认证就绪。连接恢复最多三次，间隔 0.5、1、2 秒；耗尽后等待显式刷新或下一次访问。已持久记录为 rejected 的操作保持终态，用户之后主动发送使用新操作身份；未知写入不得自动重发。隐藏 UI 暂停渲染，不积累完整 token 队列。既有 UI 性能门槛保持，新增 Gateway 的冷启动、稳态内存/CPU 和首字延迟单列测量，不把网络模型延迟计入热键输入响应。

启动诊断保存在节点数据目录的 `conversations/runtime-<binding>/startup-diagnostic.json`，其中 `<binding>` 是适配器的稳定运行时绑定；另保留一份 `startup-diagnostic.previous.json`。报告记录 UTC 起始时间、最多 48 个白名单阶段及相对耗时、启动结果、可获得的桥进程与 Gateway 退出码。原始 stdout/stderr 只在内存中被有界过滤，不写入诊断文件；单行最多 8 KiB，启动桥最多转发 256 KiB，单份报告不超过 16 KiB。凭据、令牌、路径、提示词和聊天正文不进入报告。`ready` 表示 Gateway 连接认证成功，原生会话数据库可能仍在完成后台准备，由已有只读准备等待机制处理。诊断写入失败不阻断功能。验证入口见[启动恢复计划](../development/features/chat-startup-recovery/plan.md)。

### 发送响应与持久收据衔接

成功的 `chat.send` 响应没有 `messageSeq` 时，适配器在本次 Submit 返回前按同一绑定与 `inputRunIds` 查询一次历史接收证据，复用 Observe 的持久收据/用户消息身份匹配规则。查询确认后直接返回 accepted，即使用户消息还没进入可见历史也不经过虚假的 unknown 展示。查询失败或缺少匹配证据仍返回待核对，保留恢复快照并由既有核对路径继续处理；不重发 `chat.send`，不凭 `status: started` 或运行身份推断持久接收。

验证使用锁定 OpenClaw 与本地暂停响应的模型服务：[发送前回复专项](../../internal/executor/conversation_send_test.go)检查无正文阶段的可靠接收；[前端状态测试](../../tests/chat-ui.test.mjs)检查历史为空时气泡及等待提示保持稳定，并保留真实 unknown 的警告。

## 后续扩展边界（不进入首版）

### 新 harness 与历史迁移

Hermes、DeepSeek harness、Pi 等仅为候选，不声明已支持。每个适配器独立验证持久化、历史、取消、收据和工具边界。新默认 runtime 只决定新会话；旧会话通过原适配器/只读归档访问。跨 harness 续聊需要显式导出、导入与上下文重建，原生工具状态和 memory 不保证无损迁移。本功能不自建通用历史库或预装其他 harness。

### 工具、代码与任务

Conversation / Turn / Task 分离。未来轮次可以产生工具活动、问答、审批、产物和关联任务块，按真实事件渲染；Task 仍由目标节点的任务契约管理。聊天轮次停止与任务取消是不同操作。工具循环留给 harness，权限、执行范围、去重与产物证据在执行边界落实；允许经过验证的 harness/worker 实施动作，不要求每个副作用都由 agentd 亲自执行。首版不实现这些事件的业务处理或放开权限。

### 单机多节点与角色

物理机器不作为节点唯一身份；路径、凭据、会话目录、缓存、端口和运行时实例按 node_id/节点数据目录隔离，同机也校验身份。首版不建设多节点安装/发现/管理。快捷入口通过会话客户端访问目标，不直接依赖全局任务引擎；未来可提取每用户桌面的共享入口，解决多个节点争抢相同热键，当前不实现全机协调器。

角色是行为、模型偏好、工具策略、memory scope、预算和能力要求的配置，不强制一角色一进程。首版只绑定默认角色。未来切角色默认打开另一个会话，记忆按节点/角色/会话有明确作用域；权限收紧执行时生效，扩大权限需明确授权。角色与工程治理文档分离，不自动共享原生 memory，也不将角色 ID 写成 OpenClaw agent key。

### 跨机器聊天与通信

未来 `@节点/角色` 经候选选择解析稳定目标；重名显示所属节点，名称变更不改绑定。远程实现相同会话客户端契约，由本地节点经认证信道访问目标节点会话服务，harness 管理接口仍留在目标节点。配对信任不自动授予全部会话读取、发送、停止或审批权限；目标节点校验用户/peer、角色及会话归属，撤销后停止后续访问和订阅。

远程会话正文在目标节点；入口只保存引用、未确认元数据和必要缓存，不同步活跃数据库。入口退出或断网不取消目标已接受轮次。重连使用稳定请求 ID、快照/游标补读和状态核对，未知提交只对原目标处理。传输的认证握手、版本协商、背压、超时与撤销需要单独验证；SSE/WebSocket 等具体协议留待该 feature 选择。

本地/远程使用相同布局和操作，远程延迟或离线通过连接/待确认状态呈现，不承诺相同物理延迟。首版仅以隔离 fixture 验证显式目标、错身份拒绝、游标失效与不换目标规则；不开放远程聊天端点、`@` UI、离线队列或跨节点审批。

## 默认聊天提示词与降级

节点已有的后台核对在轮次首次转换为 accepted/completed 时发出本地完成回调，应用将其连接到桌面宿主的提醒入口。回调在会话状态锁之外执行，通知接收方只作有界投递；不增加模型请求、正文副本或轮询。运行完成与持久保存状态分别处理，保存失败仍可提示运行完成。读取已有 completed 轮次、失败、取消或 unknown 不触发；通知是当前进程内的桌面提示，不是可恢复事件日志。

提示词管理以原生设定为基础：保留 harness 的身份、人格、语气、行为和上下文组装，仅适配与当前工具、入口和展示能力冲突的内容。独立提示词计划组装版本化的差异规则与当前有效配置，不重新定义统一人格。当前文本聊天没有文件、命令、浏览器、定时任务或外部消息工具；建议和示例不描述为已执行结果。工具清单与定义由运行时有效策略生成，角色文本不授予权限。

完整覆盖、补充和不支持分别声明；实际应用待确认、已应用和降级分别报告。不支持或应用失败继续使用原生提示词聊天；应用状态保留在轮次元数据，不显示在聊天界面。append 已确认是正常成功。展示决策见[提示词诊断分离 ADR](adr/008-keep-prompt-diagnostics-out-of-chat.md)。OpenClaw 首个适配器通过可信插件的 appendSystemContext 补充当前入口约束，保留原生系统提示词，并通过模型输入事件确认版本与内容；插件内存只保存最多 16 轮的请求/会话身份、版本和状态，通过已有认证 Gateway 的私有只读方法查询，不保存提示词、用户正文或隐藏推理。每次模型输入先撤销前次观察，查询失败或匹配失败不复用旧确认。

本地预发送气泡仅为内存展示，先于冷启动与新会话创建显示，按提交身份与原生历史合并。拒绝显示发送失败；未知确认继续核对；已接收的生成失败显示回复失败。新草稿不被旧确认清除。可见正文的完整性由适配器判断，其他字段被截断不产生完整正文按钮。

产品提示词修订与角色配置修订分开：已有默认角色会话在下一轮使用当前产品规则，并在该轮保存应用版本；不迁移会话、不改写旧正文。Windows 下隔离运行时的 TEMP/TMP 使用扩展长度路径形式，避免 Node 创建嵌套插件临时构建目录时触发传统路径长度限制。OpenClaw 会把插件源码捕获到独立目录，策略文件路径由可信插件配置显式提供，应用状态不通过磁盘文件中转。隔离聊天工作区启用原生 bootstrap 文件初始化，由 OpenClaw 补齐 SOUL.md、IDENTITY.md 等默认文件并加载已有定制内容；不覆盖既有文件、不导入个人 OpenClaw home 或工程仓库设定。保留注入的角色/记忆文本不启用记忆工具或文件写入；没有持久化能力时不声称已保存角色修改。补充规则仅覆盖当前入口不支持的工具执行、管理命令、外部消息、后台任务与特殊展示语法；身份和语气按原生设定。应用确认要求完整补充规则出现在有效系统提示词中，且本轮工具列表为空。失败或缺少观察证据保持降级；运行时重启使用新实例身份，旧观察记录不得被当作新轮次成功。详见[原生设定保留 ADR](adr/007-preserve-native-harness-prompts.md)；[可选提示词策略 ADR](adr/006-optional-conversation-prompt-policy.md)保留非阻断适配与观察设计的来源。

## 聊天入口的连接状态

公共响应的 connection 字段仅返回 connecting、connected、unavailable，不包含底层原因。connect 操作复用共享启动，connection 操作只读配置、启动和私有桥状态。桥状态依据 Gateway 已认证连接、已有重连操作及真实聊天终态；缺少模型凭据或实际模型请求失败统一返回 unavailable。正常回复后恢复 connected，配置更换采用新实例并清除旧实例的失败记录。只读历史不会清除实际模型失败。

展开聊天面板即启动本地 Agent，即使尚无会话；此操作不创建会话，也不请求模型。已连接确认本机 Agent 可达，模型认证仅随用户真实发送验证。连接轮询不得改变持久消息收据、发送队列、运行终态或重放策略。详见[连接状态计划](../development/features/chat-connection-status/plan.md)。

## 会话错误与展示本地化边界

公共会话协议 `internal/conversation/wire` 的 `Error` 保持原有机器错误码（`busy`、`rejected`、`not_found`、`unavailable`、`invalid_request` 等）决定排队、草稿回填与终态分流，同时可选携带 `message_key`、`message_args` 与非空兜底 `message`。[chatbridge](../../internal/executor/chatbridge/main.mjs) 向 Go 父进程返回的公开错误附带稳定消息标识，由 Go 适配层填入可选标识字段并按当前有效语言生成兜底文本；快捷输入宿主按当前语言本地化展示，未知标识或自由文本错误回退 `message` 原文。模型系统提示词与工具契约面向 LLM，不进入 UI 翻译表。
