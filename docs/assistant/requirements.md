# 助手需求

范围：OpenClaw + DeepSeek 及可扩展模型配置边界。关联 R03、R04、R17、R18、R23、C05。

| ID | 要求 |
|---|---|
| AST-01 | A、B 完整节点均有独立 OpenClaw，支持本机自然语言任务 |
| AST-02 | 自然语言明确指定 B 时，通过 Asterhand 提交持久远端任务 |
| AST-03 | 默认 DeepSeek，模型与 provider 可配置，不硬编码进任务核心协议 |
| AST-04 | 本地 Web 按需配置 API key，支持更换、删除、可选测试和重启后读取；启动及非模型入口不要求凭据或模型调用 |
| AST-05 | 普通文件任务无需 coding harness；首版不出现其登录前置 |
| AST-06 | 工具循环复用运行时，任务启动/重试归 Asterhand 唯一管理 |
| AST-07 | Skills/memory 优先复用且本地隔离，后续可导出，不复制活跃数据库 |
| AST-08 | 模型选择按 provider/model/credential_ref/endpoint 表达；仅开放已实现的 provider 与 endpoint 能力，未知值拒绝 |
| AST-09 | 旧节点配置与加密凭据可迁移；模型、凭据、有效运行时选项、源码或依赖变化使旧诊断过期，不阻止本地配置齐全的功能使用；显式选项重启后保留 |
| AST-10 | 节点运行、聊天/模型任务的本地配置状态和手动诊断分开；新请求按功能检查必要配置，直接执行真实请求，不插入预先 LLM 测试 |

验收必须使用真实模型完成本机和远程文件任务；固定回复或纯 FakeExecutor 不满足产品验收。

锁定 OpenClaw/provider 2026.10.7、Node 24.22.1 与默认 deepseek/deepseek-flash。Windows DPAPI、本机密码表单和真实无副作用工具 probe 已实现；每 attempt 独立 agent exec，无长期记忆同步。

## 本机持续聊天

自动化要求（已接入公共操作）：AST-AUTO-01 将本机默认角色的会话/消息/轮次/队列/收据提供给当前用户的 CLI/MCP，复用现有发送及持久化规则；AST-AUTO-02 要求多客户端显式目标、明确区分已保存会话和打开的输入草稿，保留原有界面与发送行为。见[自动化设计](../automation/design.md#会话任务与普通设置)。外部 agent 与内置助手使用不同身份；内置助手只获授工作区窄服务。

以下为[本机持续聊天](../development/features/local-node-chat/plan.md)的需求；当前源码已接入，工程验证和产品验收分别记录。详细契约由[持续会话设计](conversations.md)维护。

| ID | 要求 |
|---|---|
| AST-CHAT-01 | 快捷输入可显式发起当前节点默认助手的多轮文本聊天，使用节点配置的 runtime/provider/model，支持流式回复 |
| AST-CHAT-02 | 已接受消息由 harness 持久保存；支持新对话、会话列表、最近历史和向前分页，重启后恢复；agentd 只保存绑定/恢复元数据，不维护完整正文副本 |
| AST-CHAT-03 | 创建和发送使用稳定请求身份；可靠接收、送达未知与失败分开；确认丢失先核对，重试保持原目标与身份；未接受草稿仍为内存数据 |
| AST-CHAT-04 | UI 隐藏或崩溃不取消生成；停止请求与实际停止分开；runtime/节点重启后核对在途状态，部分未保存内容明确展示，不自动重跑未知轮次 |
| AST-CHAT-05 | 公共会话接口不依赖 OpenClaw RPC/原生 ID；按能力接入 harness；默认 runtime 变化不改绑旧会话，历史迁移单独设计 |
| AST-CHAT-06 | 会话显式绑定 node_id、默认 role_id 和角色/runtime 配置引用，名称不作身份；预留同机多节点、多角色而不实现其管理功能 |
| AST-CHAT-07 | 普通聊天独立于任务槽，未设置权限时默认开放本机工作区文件、检索和进度，已有明确关闭保持；代码、skill 执行及管理命令保持关闭；Conversation/Turn/Task 分离，为后续任务引用保留边界 |
| AST-CHAT-08 | 本地/未来远程共用会话语义，目标节点为权威；事件/历史有界，支持游标失效和状态核对；首版不开放远程聊天 |
| AST-CHAT-09 | 按需启动由节点运行时管理，并发历史与发送共享一次启动；单个请求超时不终止正在恢复的运行时。启动失败保留有界、脱敏的阶段与退出诊断，节点退出取消并回收自有启动 |
| AST-CHAT-10 | 启动期间新建和发送可进入节点持有的有界内存队列；稳定绑定目标与正文，入队和原生接收分别确认。发送后不提供撤回或队列管理；停止回复仅作用于已接收轮次，后续消息继续。明确失败记录结果后释放队列并保留近期失败展示，未知发送只核对；支持界面重建恢复，队满保留新草稿，退出明确处理待发内容 |

## 聊天提示词

- AST-PROMPT-01：默认聊天保留 harness 原生身份、人格、语气、行为和上下文设定；版本化产品规则仅纠正与当前有效能力/入口冲突的内容，优先使用原生策略和局部补充。提示词适配为可选增强，支持和实际应用状态分离。不支持或应用失败继续原生聊天，底层保留应用状态；聊天界面不显示注入或适配诊断。提示词不授予工具权限。

## 本机持续会话工具能力

本节定义工具开启时的行为，未设置权限时默认开启，用户可在设置中关闭。首批文件工具验收、第一阶段受限脚本与第二阶段受控提权边界分别见[本机工具计划](../development/features/local-runtime-tools/plan.md)、[工作区脚本与命令执行计划（第一阶段）](../development/features/workspace-script-execution/plan.md)与[受控提权脚本与外部目录执行计划（第二阶段）](../development/features/workspace-script-escalation/plan.md)。先完善本机能力，再评估远程聊天。

| ID | 要求 |
|---|---|
| AST-TOOLS-01 | 在本机持续会话的独立工作区完成读取、创建、覆盖、编辑、移动和删除，优先原生工具，不包装成旧任务 |
| AST-TOOLS-02 | 提供目录列举、文件名与内容搜索，输入、扫描与输出有界，禁止借搜索或列表参数绕过执行策略 |
| AST-TOOLS-03 | 复用原生本地记忆与人格；首批关键词检索、显式轮次内写入，禁后台自主任务与越界索引 |
| AST-TOOLS-04 | 工具活动、进度、结果和未知状态可展示、回读和停止；文本与工具调用按发生顺序共同显示，状态更新保留原位置，工具记录展示由命令定义白名单声明的简短目标摘要并排除未声明正文或秘密，纯工具记录不生成空消息；中间 assistant 消息不算轮次完成 |
| AST-TOOLS-05 | 稳定产物引用支持授权预览与下载；新增日常操作同步 UI/CLI/MCP，内置助手不继承全量自动化权限 |
| AST-TOOLS-06 | 变更前像与逐文件结果可恢复；恢复按修订与操作身份防覆盖、防重复；本批受限工具未设置时默认开启，已有明确选择保持；权限更改与提权信任配置仅限人工操作，详细交互与规则见下表第二阶段要求 |
| AST-TOOLS-07 | 第一阶段在既有“允许助手调用工具”开启下提供受限工作区零审批脚本与命令执行（`exec_command` / `process_control`）：允许出站网络，可写内核范围锁定在当前工作区与受管 `sandbox-temp`（`<journal>/sandbox-temp`），清理子进程环境（零节点/模型凭据，工作区桥令牌经环境注入不落盘），在启动前拦截用户常见敏感凭据目录覆盖与显式引用，并按平台诚实界定 Windows 非提权写隔离/防误触与后续 macOS/Linux 内核禁读边界 |
| AST-TOOLS-08 | 所有工具纳入四级统一聊天“停止”语义：排队项立即取消、单文件原子写保持当前边界、长搜索扫描协作即时中止（`search_files` 与可中断记忆桥 I/O）、脚本子进程树（含 Turn 内转后台并发会话）在用户停止、模型结束轮次或节点退出时并行强杀、有界排空、清理 `sandbox-temp` 并完成工作区对账后方释放工作区租约 |
| AST-TOOLS-09 | 第二阶段面向访问工作区外普通目录、使用系统 WinHTTP/Schannel HTTPS 或原生凭据链路的场景提供受控 Tier 2 普通用户态执行（Windows 复用 `OrdinaryToken()` Medium IL 与具名 `JobObject`，零管理员 UAC 提权）：在 Go 服务端按“系统硬底线 → 用户禁止 → 用户每次询问 → 会话/持久允许 → 模式兜底”五层评估（启动前同步校验未声明外部 `workdir`、按子进程生效环境绑定精确可执行路径并静态扫描工作区引用脚本），配合单次原子认领分片审批等待、`approval_pending` 同轮写屏障、待审批活动保底可见与启动前以 `FILE_SHARE_READ` 锁定并完成 `TOCTOU` 防篡改复核、经串行取消门禁启动后再发布信任规则（持久化异常独立告警且保留执行结果）；在聊天面板以非技术用语按需内联展开展示完整多目标胶囊的确认卡片（支持本对话允许、仅本次、条件始终允许及拒绝），拒绝与超时由共享活动投影明确标示且不阻塞对话 |
| AST-TOOLS-10 | 支持人工切换确认模式为“自动允许（极速，即 `turbo` 模式）”，并在独立修订上零重启毫秒热生效与一键查看/移除“始终允许”条目；`turbo` 将常规脚本与非保护外部目录操作作为单次临时授权直通 Tier 2、绝不污染持久白名单，同时保留系统硬底线（Asterhand `<HomeRoot>`、常见凭据目录、显式 UAC 动词与环境变量秘密保护）与用户显式禁止/询问规则 |

公共定义及上游映射见[能力设计](runtime-capabilities.md)；其他 harness 与 macOS/Linux 沙箱后端保留明确的能力接入边界，Windows 以外平台在实现与实测前不宣称可用。
