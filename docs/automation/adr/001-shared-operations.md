# ADR-AUTO-001：统一日常业务操作与 CLI/MCP

- 状态：accepted；公共操作与适配器已实现。
- 日期：2026-11-04。
- 所属需求：AUTO-01—24。
- 替代关系：本实现替代[本地命令启动边界](../../executors/adr/002-local-command-launch-boundary.md)及[统一命令运行](../../executors/adr/006-unified-command-runs.md)中“仅快捷输入手动启动、没有 agent 入口”的部分；其他执行/恢复约束继续适用。其他历史决策不改写，当前业务行为见领域 design。

## 背景

日常操作分布在 Web HTTP、快捷输入内部桥、聊天服务和桌面入口。命令保存已有公共注册服务，启动去重仍依赖宿主会话；持续聊天服务已经独立，但没有外部客户端通道。直接包装现有 HTTP 会遗漏启动、日志和聊天，也会把敏感设置一起开放。

## 决策

1. 建立节点内公共操作定义和窄适配，三个入口最终调用同一领域服务；CLI 和 MCP 共用客户端。节点继续拥有持久数据与执行生命周期。
2. 覆盖以日常业务结果和信息读取为单位；允许批处理与组合操作。纯展示操作有等价读取，认证、加密、秘密及授权管理保留人类。
3. 先交付本机自动化与现有远端任务，MCP 首选 stdio；远程持续聊天、远程脚本和内置助手使用工具分别扩展，不直接开放原生 harness RPC。
4. 写入接纳使用稳定操作身份、领域可恢复提交及对象修订；收据/结果与大日志分开保留，过期重放拒绝。CLI/MCP 断开不取消节点已接纳工作。
5. 日常能力覆盖成为长期开发规则，公共定义检查与行为测试共同阻止新增遗漏；逐项迁移旧入口，保留现有用户交互。

## 备选与后果

- 只包装 Web API：改动较小，但缺少窗口内部能力，且容易继承完整管理权限，不采用。
- MCP 调用 CLI 并解析文字：容易开始，但会增加进程成本、转义和错误解析差异，不采用。
- 新建独立自动化执行引擎/数据库：会复制运行、停止和恢复规则，不采用。
- 将所有 UI 操作机械变成工具：大量窗口/焦点动作增加调用成本且不改善业务覆盖，不采用。

采用共享领域服务需要补齐请求身份、保留与并发写入，并将部分 HTTP handler 中的业务编排移入所属服务。UI 本地草稿和交互反馈无需全部搬到后端；最终校验、执行事实和权限判断由服务端负责。

本机通道的精确身份核验、SDK 版本及资源预算须先完成计划中的验证门槛；这些技术验证不重新定义已接受的业务范围。
