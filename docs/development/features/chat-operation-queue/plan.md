# 聊天启动期间的操作缓冲

## 范围与契约

关联 AST-CHAT-01/02/03/04/09/10、WEB-CHAT-14。启动期间继续新建、切换和发送，按会话身份和提交顺序执行；原生生成仍保持每节点一轮。当前轮次可能仍运行时先核对，不重放未知提交。

节点服务持有有界内存队列，默认最多 8 条待发消息、正文总计 128 KiB；每条仍为 16,000 UTF-8 字节。上限是可调整的内部资源参数，不是运行时能力限制。创建与发送操作合计最多 16 项。队满拒绝新增并保留新草稿，已有消息不被淘汰。

新建先保存稳定会话身份并返回，原生创建在队列中完成。发送固定目标、操作身份、正文与草稿修订，先确认入队，执行前持久保存既有提交元数据。入队状态与原生接收状态分开；重复请求按操作 ID/摘要去重，不按正文去重。创建失败保留依赖消息。取消未派发消息立即生效；停止优先执行并暂停后续派发，恢复队列需显式操作。

正常发送的产品体验统一：初始化期间点击发送，与运行时已连接时使用相同消息气泡和“正在回复”提示。不展示待发数量、准备阶段或取回/取消发送按钮，内部阶段切换不改变气泡与等待提示。后端继续保留真实状态和防重发规则；仅实际失败后显示已有的异常提示与必要恢复入口，不扩展为新的送达状态管理界面。

历史、列表、窗口、编辑和复制不占生成队列；重复读取合并，过期响应不改变当前会话。模型、凭据或运行时配置在队列非空时拒绝变更；外观设置不受影响。正常退出遇到队列时要求明确确认丢弃尚未发送内容；界面隐藏与宿主重建保留主进程队列。崩溃或应用退出后不自动续发内存正文，持久排队元数据记明确未派发终态。

## 实现与验证

- 节点服务管理 FIFO、创建依赖、暂停、取消、退出和配置准入。
- 受限 wire/IPC 增加队列状态及单条正文恢复，保持帧大小限制；界面重建从主进程恢复。
- 界面立即显示普通消息气泡，可继续输入；初始化、排队与正常回复共用等待提示，新建/切换不等待原生历史，后台读取保留目标代次。
- 验证顺序、冷启动、跨会话绑定、队满、取消竞争、停止与未知结果、重建、退出、配置变更、消息正文不落入元数据和 IPC 大小。
- 固定原生运行时使用本地受控模型验证多条发送及历史，真实安装与桌面验收独立记录。
