# 提示词管理与聊天交互完善

状态：实现、分层自动化验证及独立审计修复已完成；提示词默认策略已由[原生设定保留](../native-harness-prompt-preservation/plan.md)继续调整；日常聊天交互已通过[用户验收](../local-node-chat/validation.md#用户验收状态)，其余实体桌面与专项验证仍单列。建立在[本机持续聊天](../local-node-chat/plan.md)基础上；工程验证、实体桌面验收和提交分别记录。

## 范围与需求

- AST-PROMPT-01、EXEC-PROMPT-01：版本化默认聊天提示词、有效能力事实、通用应用状态与 OpenClaw 适配。支持完整覆盖、补充或不支持；应用失败非阻断降级，权限继续由运行时执行。
- WEB-CHAT-06：发送意图立即产生本地气泡，接收后不显示成功标签，拒绝/未知送达/回复失败分别展示；按稳定身份去重。
- WEB-CHAT-07：Enter 发送、Shift+Enter 换行、Ctrl+Enter 兼容发送，IME 不误发，Esc 保持隐藏。
- WEB-CHAT-08：完整正文不显示完整读取按钮；非展示字段截断不冒充正文截断，长正文保持有界读取。

领域依据：[助手需求](../../../assistant/requirements.md)、[会话设计](../../../assistant/conversations.md)、[执行器需求](../../../executors/requirements.md)、[执行器设计](../../../executors/design.md)、[Web 需求](../../../web/requirements.md)、[Web 设计](../../../web/design.md)。

## 设计与实施

1. 当前入口差异规则和能力事实由独立提示词模块组装；保留原生身份和语气，适配器声明应用方式。公共协议只携带版本、方式、应用状态，不传原生提示词、路径或秘密。支持声明与实际应用确认分离；未确认不报告成功。观察通过已有认证 Gateway 的私有只读方法查询有界内存元数据，失败不缓存旧成功。
2. OpenClaw 通过受控插件的 before_prompt_build 以 appendSystemContext 补充当前入口约束，保留原生系统提示词和隔离工作区角色文件，通过模型输入观察确认补充内容；不修改第三方安装源码，不依赖用户消息覆盖系统指令。插件只从后端生成的固定策略文件读取，不读取仓库规范或聊天正文作为权限来源。提示词失败保持原生聊天可用并给出非阻断提示。
3. 本地气泡先于连接、创建和提交等待显示；有界内存持有快照，用操作 ID、轮次 ID 和原生消息 ID 合并，不以正文匹配。面板与气泡共用轮次新旧规则；迟到历史保留较新终态并在有界轮询中刷新正文。历史刷新、分页、会话切换和迟到响应不得复制或错挂消息；发送时立即清空可见输入，恢复快照按接收确认及提交修订释放。
4. 输入编辑器集中定义快捷键，覆盖输入法组合结束边界与重复按键。正文完整性由原生适配器解释，显示层只消费可见正文截断状态；不批量拉取所有全文。

## 验收与验证

- 提示词单测覆盖完整覆盖、补充、不支持和失败；原生 Gateway 本地模型夹具检查实际出站系统提示词、零工具、上下文延续与重启。真实模型与实体输入法验证单列，不能用夹具代替。
- 延迟提交、接收确认丢失、明确拒绝、生成失败、重复正文、冷启动、新建会话、会话切换和历史刷新均保持正确气泡与草稿。
- Enter/Shift+Enter/Ctrl+Enter、IME 组合与组合结束、长按和 Esc 行为测试；真实 Windows WebView2 验证允许时执行。
- 短正文加超长非展示字段、长正文、Unicode、多文本块、超限全文、读取失败和分页预算测试。
- 执行相关 Node/Go 测试、go vet、文档本地链接与规模检查；独立 reviewer 覆盖六项维度并对修复复审。

验证入口、运行前提和人工边界见[验证说明](validation.md)。已执行通用 Go/vet、前端回归、真实 OpenClaw 本地模型夹具、真实 DeepSeek 两轮与真实 WebView2；真实发送、历史查询、新对话、展开/收起的用户验收已完成；实体 IME 和其余专项保留独立状态。

## 非目标与规模

不接入新 harness，不增加角色管理、提示词编辑器、工具权限或持久离线队列，不改变既有任务执行。原生验证暴露的 Windows 深临时目录问题在聊天适配器内处理：仅将隔离 TEMP/TMP 转为扩展长度路径，节点目录、配置与其他环境变量保持原语义。新增代码按提示词、适配器、发送展示职责组织；不拆分已有超限文件。chatPanel 继续是共享状态的装配闭包（超过 100 行），负责连接、选择、草稿和渲染生命周期装配；拆开闭包会增加共享可变状态传递，本轮保持装配入口，新增发送状态规则放在独立 chat-outbox 模块。原生工作流测试的场景函数也超过 100 行，保留按用户操作顺序组织的 setup/action/assert 便于核对端到端因果关系。所有本轮源文件均低于 1000 行。

## 发送区即时转移

对应 WEB-CHAT-02、WEB-CHAT-06：发送时将可见输入立即转入待确认气泡，原文保留为编辑器/主进程的恢复快照。冷连接、创建与回执延迟不造成输入区重复显示；明确失败按原操作恢复，未知送达继续核对；新编辑（含再次输入相同文本）优先于迟到确认/失败。

验证编辑器快照与修订、冷启动首次发送、接收/拒绝/未知、随后编辑与 IME，以及真实 WebView2。实现保持原有 IPC 和主进程草稿权威，不新增持久化或模型调用。实现与自动化验证已完成：编辑器/面板回归、quickinput Go 测试及 vet、真实 Windows WebView2 均通过；真实消息发送已纳入日常聊天用户验收，明确失败、未知送达等专项仍按各自证据记录。输入编辑器装配闭包现超过 100 行，事件处理和发送快照共享修订、IME 与生命周期状态；保留该边界可避免分散主进程草稿协议，内部状态操作均为短函数，文件低于 1000 行。
