# 聊天发送与停止回复

状态：实现、自动化工程验证和本机用户验收通过；故障及跨环境覆盖以验证说明为准。

关联 WEB-CHAT-04/06/10/14、AST-CHAT-02/03/09/10。权威契约见[会话设计](../../../assistant/conversations.md)和[Web 设计](../../../web/design.md)。

## 范围与设计

点击发送后立即显示普通用户消息，初始化、排队和送达确认由后端负责。正常聊天不展示发送阶段，也不提供撤回、取回、取消发送、暂停或继续队列。保留“停止回复”：只作用于当前会话已经确认接收且尚未结束的模型轮次，不删除用户消息、不暂停后续派发；取消绑定原操作身份，迟到操作不停止新轮次。

明确未送达的异常在对应消息旁显示“消息未送达”；已送达后的生成异常显示“回复失败”；接收回执不明显示“送达待确认”，按原身份核对，不自动重发。明确失败完成记录后离开待发队列，后续消息继续。会话创建失败将依赖消息记为未送达，新一次主动发送可重新准备该会话，不重发旧失败消息。

失败展示使用独立有界内存快照，最多八项，单条正文保持既有 16000 UTF-8 字节限制；不占待发容量或配置/退出忙状态。宿主重建可恢复近期失败正文，原生历史仍是已送达正文的权威。应用退出/崩溃后的本地正文持久化沿用现有边界，本功能不增加历史删除、离线持久化或自动重发能力。

## 验收与验证

- 冷启动连续发送：气泡和等待提示一致，准备/排队阶段没有停止发送或撤回入口。
- 停止当前回复后，原用户消息保留；已有后续消息与新消息正常执行，无继续发送按钮。
- 切换会话、迟到停止与完成竞争只影响目标轮次；停止失败可再次操作，不伪造停止完成。
- 启动、创建或明确提交失败：对应消息提示未送达，释放队列，保留近期失败正文供宿主恢复；失败消息不自动重发。
- 送达未知时只核对；确认接收或确认轮次结束后释放后续调度，未知送达不误报未送达。
- 失败后可修改模型配置；重复操作身份、防重发、队满、草稿修订、隐藏/重建和单帧预算保持。
- 运行相关 Go/Node 回归、真实 WebView2 流程及固定 OpenClaw 本地模型模拟验证，记录实际覆盖与环境限制。

## 工程验证与规模

已验证节点队列与故障回归、前端交互、全量 Go 测试及 vet/build、静态资源和本地文档链接。真实 Windows WebView2 覆盖消息异常、停止后的新发送和发送时布局稳定；布局测试在原生尺寸确认后取展开态基准。固定 OpenClaw 配合本地受控模型验证连续排队、停止第一轮后自动执行第二轮、两条用户历史均保留且调用不重复。该验证不使用真实 DeepSeek，也不代替安装后的用户验收或跨机器验收。

本次修改文件均低于 1000 行。`chatPanel` 是既有面板工厂（421 行），闭包维护选择代次、草稿、停止请求与异步回调的共同生命周期；发送、历史、队列和渲染已分配至专门模块，内部处理函数均低于 100 行。保留该状态所有权可避免停止回执与切换会话之间增加同步接口，本次减少其职责并保持闭包边界；后续新增独立面板职责时重新评估。
