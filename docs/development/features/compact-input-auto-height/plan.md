# 收起态快捷输入框自动高度

## 基本信息

- 目标：全局快捷输入的收起态从单行开始，随当前文本的实际排版增减高度，最多显示十行，减少空白占位。
- 状态：已实现，工程验证、独立复审及本机输入体验用户验收通过，覆盖自动增减高度、十行滚动上限及滚动条/顶部残缺文字闪现修复；专项验证边界见[验证说明](validation.md)。默认恰好容纳，保留内部额外一行的调节能力。
- 关联：R03、C02、WEB-12、WEB-CHAT-01/02/03/06/07/12/13/14。下文 CAH 编号为本功能验收追踪编号；实施时将最终要求纳入 Web 领域需求。
- 领域依据：[Web 需求](../../../web/requirements.md)、[Web 设计](../../../web/design.md)、[安装需求](../../../installation/requirements.md)、[安装设计](../../../installation/design.md)、[测试设计](../../../testing/design.md)。
- 继承：[本机持续聊天](../local-node-chat/plan.md)、[聊天桌面体验](../chat-desktop-experience/plan.md)、[聊天操作队列](../chat-operation-queue/plan.md)、[窗口与位置决策](../../../installation/adr/008-chat-window-desktop-presence.md)。继续复用现有编辑器、受限桥和非提权宿主，无新增架构决策需要单列 ADR。

## 需求细化

### 状态与范围

“收起态”指消息区隐藏、顶部按钮显示“展开”的快捷输入窗口；“展开态”指消息区可见的大聊天界面。“一行高度”仅指文本编辑区，窗口仍包含原有标题、发送操作区及底栏，不把整个窗口压成一行。

| ID | 规则 |
|---|---|
| CAH-01 | 收起态空草稿显示一行编辑区；首次空白呼出不先展示旧的大输入区再跳到单行。 |
| CAH-02 | 默认按实际视觉行数定高：文本进入第二行时增加一行，之后逐行增加。视觉行包括自动折行、Shift+Enter、粘贴或恢复文本中的显式换行；尾部换行形成的空行也要容纳光标。扩高等待期间文本顶部稳定，不提前滚动而闪现被裁切的上一行；新空间就绪或确认限高后再跟随末尾。 |
| CAH-03 | 删除、剪切、选区替换、撤销/重做、程序清空后，按当前文本重新缩行；清空回到一行，不沿用曾经达到的最大高度。 |
| CAH-04 | 编辑区最多显示十行，总计十行而非初始一行再增加十行。正常换行扩高期间不闪现滚动条；超过十行或确认工作区限高后出现可拖动的纵向滚动条，支持滚轮和键盘查看更早文本；十行是显示上限，不截断文本。 |
| CAH-05 | 自动高度只作用于收起态；展开态保留现有编辑区、窗口高度及滚动行为。展开再收起时以当前草稿重新计算；发送、新对话和历史操作沿用现有展开规则。 |
| CAH-06 | 初始化恢复、失败回填、队列异常取回、主题/宽度/DPI 变化及隐藏后恢复，都得到与当前可见文本匹配的高度。布局变化不修改正文、草稿修订、选区或撤销历史，不触发发送和额外模型调用。 |
| CAH-07 | 把“恰好容纳 / 多留一行”作为独立的内部布局策略，默认恰好容纳；实测后可以低成本切换。两种策略均支持缩行、空框一行及十行封顶。 |
| CAH-08 | 窗口遵守工作区、DPI、位置保持和不抢焦点规则；显示条件不足以容纳十行时，优先保证控件可操作并提前使用输入区滚动。确认区等辅助控件出现时另计高度，不占用文本行数。 |

### 可调的留白策略

将额外预留行数集中为内部参数 `extraRows`，初始为 `0`，体验候选为 `1`。这里只预留调节能力，不增加 Web 设置项、持久配置或 IPC 字段。

```text
N = 当前文本实际排版的视觉行数，最少为 1
空字符串：目标行数 R = 1
非空文本：目标行数 R = min(10, N + extraRows)
```

- `extraRows = 0`：默认方案，实际换行才增高；编辑区恰好容纳当前行数，保留正常内边距。
- `extraRows = 1`：体验候选，非空文本多留一行；因此第一行开始输入后会显示两行高度。用于实测比较，不覆盖空框一行的要求。
- 删除后始终重新计算 R，不保存历史最大值；候选策略也只预留一行，不逐次累积空白。
- 第十行时两种策略都封顶；滚动条依据文本是否实际溢出显示，不因请求额外预留行而提前出现。
- 试用时比较短句占位、连续长文输入、删除回缩和靠屏幕底部时的窗口移动感受。默认交付值以用户实测体验定稿，调整只影响收起态布局。

### 保持的交互

- 热键继续显示/隐藏当前面板，不强制把已展开的窗口收起；空白收起态是一行，有草稿则恢复其所需高度。
- 发送继续自动展开，Enter/Ctrl+Enter 发送、Shift+Enter 换行和 IME 防误发送规则保持。
- 宿主重建仍恢复主进程最后接受的内存草稿；布局尺寸是派生状态，不新增持久化数据。
- 16,000 UTF-8 字节草稿上限、提交快照、迟到 ACK 保护、未知送达核对和队列语义保持。
- 保留现有宽度、字体、主题、标题/发送/状态/底栏布局；本次不顺带合并工具栏、重做窗口视觉或调整展开态阅读体验。

## 现有实现冲突与一致性检查

| 现状与源码依据 | 与需求的关系 | 处理方案 |
|---|---|---|
| [编辑器](../../../../internal/quickinput/assets/input.js)在 `commit()` 中按 `split("\n").length` 统计显式文本行数，收起态采用 `max(240, min(480, 164 + min(12, 显式行数) * 30))`。 | 只识别显式换行，长句自动折行不会扩高；240 DIP 下限留白过大，十二行计数也与十行上限不同。旧公式在删除后会重算，但仍受这些限制。 | 用实际排版测量与 1—10 行规则替换收起态旧公式；行高取实际样式，不沿用 30 px 或 164 px 常量。 |
| [基础样式](../../../../internal/quickinput/assets/input.css)设置视口相关高度和最小高度；[聊天样式](../../../../internal/quickinput/assets/chat.css)又设置 `flex: 1`、`min-height: 64px`。 | CSS 使收起态编辑区填满窗口，单改 `rows` 或窗口公式仍无法得到单行。 | 分离收起/展开样式作用域；收起态编辑区按目标行数定高，取消其填满和多行最小高度限制。 |

| 展开态由同一编辑器与 `setExpanded()` 驱动；当前窗口目标为 760 DIP，编辑区 CSS 高度为 104 px。 | 全局修改 textarea 最小/最大高度或保留收起态内联高度，会污染用户要求保留的展开态。 | 展开时撤销收起态专用尺寸/滚动覆盖，保留现有展开规则；收起时重新测量当前文本。 |
| 编辑器 `init`、`stageSubmission()` 和 `restoreSubmission()` 存在直接赋值路径，并非每条路径都重新布局；IME 期间跳过普通 `commit()`。 | 只监听普通 input 会遗漏恢复/回填；把布局继续耦合在草稿提交中会影响 IME 与快照保护。 | 所有可见文本赋值路径接入独立布局调度；IME 临时文本仅用于布局测量，不提前提交草稿。 |
| [聊天 UI](../../../../internal/quickinput/assets/chat-ui.mjs)可在收起态显示“切换会话确认”；状态区、停止/继续按钮也会改变辅助布局。 | 单行窗口若只按固定工具栏高度计算，会挤压输入或裁掉确认按钮。 | 把所有可见辅助区与间距计入窗口高度；确认区显示/隐藏触发布局，状态文案沿用固定占位。 |
| [Web 设计](../../../web/design.md)描述“紧凑状态展示多行输入”“展开/折叠只改变消息区显示”。 | 当前措辞没有规定单行起步、十行上限或输入视口随模式改变，需要细化。 | 实施时明确：复用同一草稿，收起态自动高度，展开态保持原布局；会话/生成状态不随折叠改变。 |
| 发送自动展开、隐藏恢复原模式、草稿内存恢复、工作区优先。 | 与新需求兼容，需要作为边界保留。“默认一行”不代表每次热键都清空或强制收起；小屏也未必能完整显示十行。 | 在验收中分别覆盖这些状态，避免把自动高度扩大为会话或窗口模式改造。 |

结论：需求与现有聊天、发送和恢复模型兼容；直接冲突集中在旧高度公式、样式约束和原生最小尺寸。新增工作属于前端排版与桌面窗口布局调整，不涉及模型或任务调度改造。

## 设计方案

### 1. 独立布局职责

新增小型 `composer-layout.mjs`，专门管理文本测量、额外行策略、收起态尺寸、resize 合并和清理。编辑器继续管理正文、修订、IME、提交快照与恢复；聊天 UI 继续管理展开/收起及确认区。

展开状态沿现有 `chatPanel → editor.setExpanded()` 路径同步，不另建一份独立模式状态。布局模块接收模式、当前可见文本和辅助区变化，不调用 `commit()`，不增加或修改草稿 revision。

### 2. 测量与计算

- 使用与真实 textarea 宽度、字体、字间距、制表符、换行规则和内边距一致的离屏测量 textarea，以浏览器实际排版为准；通过文本值赋值，不拼 HTML，不进入 Tab 或读屏顺序。
- 测量层不使用实际窗口的当前高度作为内容高度上限，避免单行窗口无法增长。中文、英文长词、URL、emoji、空格和显式换行都以同一排版路径计算。
- 从计算样式取得行高，扣除边框/内边距后推导视觉行数；覆盖小数行高和像素取整容差，防止 1 行误判为 2 行。尾部换行和空文本单独验证。
- 编辑区高度为目标行数乘行高，加正常内边距与边框。窗口请求高度为编辑区高度，加标题、操作区、底栏、可见确认区及其间距与外框。
- 预留稳定的滚动条宽度，使滚动条出现/消失不改变文本折行并反复触发第十行边界。收起态默认隐藏纵向滚动条，十行内等待窗口增高时不暴露临时溢出；仅超过十行或宿主确认限高且实际溢出时启用。已确认的限高在正文持续溢出的新请求期间保留，避免已有滚动条消失再出现；正文放得下或新的有效分配解除限高后清除。
- 编辑区达到上限后保持高度；末尾编辑按完整 scrollHeight 跟随，中部编辑保留原生 textarea 的滚动结果，不用缺少词尾上下文的前缀排版校正光标。用户拖动滚动条回看旧文本时，状态刷新、主题变化和被动尺寸重算不强行滚到底部。
- 尚未确认限高、目标编辑区仍大于实际可用空间时，十行内文本或末尾编辑暂时固定顶部，阻止浏览器迟到的自动滚动。保留末尾跟随意图，扩高完成或宿主确认限高后执行；隐藏、展开及销毁释放该临时约束。十行封顶/真实限高的稳定滚动与被动回看维持原规则。
- 当前请求未收到匹配确认前，即使旧大视口暂时放得下，也继续保留等待状态与末尾跟随意图；旧缩小请求之后落地时仍能锚定顶部。当前 ID 确认且 viewport 匹配后才结束，防止快速清空/重输触发交错请求残影。

### 3. 窗口与工作区

- WebView2 私有桥的 resize 携带单调请求 ID；宿主应用布局后回送 `layout_applied`，含窗口代次、请求 ID 与实际客户区逻辑高度。仅当前请求且浏览器 viewport 已与确认高度匹配，才把十行内的剩余溢出视为工作区限高；迟到确认忽略。移动、DPI/工作区与显示恢复后的原生布局也回送当前确认，无尺寸变化时仍确认请求。不增加父子进程 IPC 或通用窗口控制能力，不放宽来源、消息大小或非提权边界。
- 前端输出 CSS 逻辑像素，原生按现有 DIP/DPI 路径换算物理像素，避免重复乘缩放系数。桥与布局共享 128—800 DIP 请求范围，替换两处 240 下限；隐藏创建目标为 180 DIP，完整单行实际高度由 DOM 测量决定，不硬编码为创建高度。
- 原生保留宽约 680 DIP、展开目标 760 DIP、全局最高 800 DIP 及工作区限幅；新建窗口的隐藏初始尺寸与首次布局配合，首轮测量完成后才按正确高度显示。
- 区分“内容期望高度”和“工作区实际分配高度”。当前 viewport 高度不是增长上限；宿主裁定后，编辑区在实际可用空间内滚动，不把被裁定的高度反向累计到目标值，避免 resize 循环。
- 一般保留左上位置并向下增长；靠近工作区底部时复用现有位置约束，缩回后恢复用户首选锚点。程序 resize 不写回拖动位置，也不激活窗口。
- 可用高度不足十行时允许更少行并提前滚动。极端小工作区需验证标题、输入和操作区的访问顺序；不以突破屏幕边界满足十行显示。

### 4. 触发与生命周期

统一调用布局调度的入口：

1. 接收 init 草稿后同步完成首轮测量，先发送 resize 再发送 initialized；不等待隐藏 WebView 中的帧回调或字体 Promise 才通知就绪。字体就绪后有界补测，目标显示器宽度/DPI 生效后再次校正。
2. 输入、粘贴、剪切、删除、选区替换、撤销/重做；IME input 与 compositionend。
3. 提交暂时清空、拒绝恢复、队列取回、按 revision 清空等程序写入。
4. 展开/收起、确认区显示/隐藏、主题切换、有效宽度或 DPI/工作区变化。
5. 隐藏后恢复与宿主重建后的首轮布局。

IME 组合期间可以测量当前临时文本，布局不重写输入值、不重置光标、不强制聚焦；组合确认、快照和发送继续使用原有时序。按帧合并重复测量，目标整数高度变化时才发 resize；纯高度回调不反复提交同一尺寸。隐藏时停止持续观察/测量，恢复时补算；销毁释放监听、观察器、待执行帧和测量节点，不增加定时轮询。

## 验收与验证计划

| 场景 | 可见结果与验证重点 |
|---|---|
| 空白首次呼出、清空后呼出 | 编辑区一行；标题、发送、底栏完整；无 240 DIP 大空白闪现。 |
| 中文、英文、中英混排、emoji、长 URL 连续输入 | 使用真实排版逐行增长；默认策略不提前留空行；边界不抖动、不截掉光标或最后一行。 |
| 1→2、2→3、9→10、10→11 行 | 最多十行；超过十行才滚动；单次粘贴可以直接达到所需高度，无需逐帧播放每个中间行数。 |
| 11→10→9→1→空，含剪切、全选替换和撤销/重做 | 随当前文本缩行；回到十行且不溢出后移除滚动条；清空后回一行，不停留在历史最大高度。 |
| 显式换行、连续空行、尾部换行与混合软折行 | 空白行和光标位置计入实际行数；LF 规范化与文本内容保持。 |
| 两种 extraRows 值 | 空文本均一行；非空分别显示 N 或 N+1 行并封顶十行；删除同步回缩；实际溢出决定滚动条。 |
| 超过十行后拖动滚动条、滚轮、键盘回看 | 可到达最早文本；被动刷新不抢回底部；继续输入时光标可见。 |
| IME 临时组合跨行、确认/取消与 Enter | 高度跟随可见文本；候选确认不误发送，未确认文本不提前成为主进程草稿，选区/撤销保持。 |
| 展开编辑长文，再收起；收起发送、新对话和历史 | 展开态保持现有 104 px 编辑区及 760 DIP 窗口目标；收起按当前文本重算；发送等继续按原规则展开。 |
| 发送清空、拒绝回填、队列取回、迟到 ACK | 高度反映当前可见草稿；待确认快照不撑大空框，迟到结果不覆盖新编辑，也不按旧文本调整高度。 |
| 收起态携草稿新建/切换、取消确认、显示停止/继续状态 | 确认区和按钮可见，额外控件不挤掉输入；关闭确认后及时缩回。 |
| 双主题、100%/125%/150%/200% 缩放、窄工作区 | 折行与实际宽度一致，无双重缩放；工作区不足时提前滚动；标题、输入和操作区可访问。 |
| 拖动到底部、连续增长/删除、隐藏恢复、最小化恢复、宿主重建 | 保留原有位置和模式语义，不抢焦点、不累计位置漂移；草稿恢复后高度正确。 |

## 规模与风险控制

- 改动前主要入口均低于 1000 行：编辑器 118 行、聊天 UI 452 行、原生桥 147 行、原生窗口主文件 411 行、位置管理 121 行、窗口布局 43 行；实现未触发超限文件拆分。
- 新布局职责放入独立模块，避免继续把测量逻辑塞进编辑器提交函数或聊天装配闭包；单函数按 100 行软阈值评估。此处新增模块属于新增职责，不是对超限文件的拆分。
- `inputEditor` 为超过 100 行的现有装配闭包，继续共同持有草稿代次、IME 和待确认提交保护，新增布局通过独立类协作；保留内聚性，避免为缩短闭包暴露这些状态。新增布局方法均低于 100 行。
- 最高风险是 CSS 与原生窗口互相撑高、滚动条造成折行振荡，以及布局重算干扰 IME/提交快照。通过独立测量、目标/实际高度分离、稳定滚动宽度和不改草稿的布局路径控制。
- 交付完成条件：功能与领域文档一致、相关回归通过、实体体验及未覆盖边界清楚记录。用户验收、提交、推送和发布继续独立确认。
