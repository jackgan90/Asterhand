# 快速本地安装

## 目标与范围

日常功能验收与问题复现默认只更新当前源码产生的应用文件，复用安装目录内已经准备的固定运行时。关联 C04、INST-05、INST-11、INST-25、INST-26、INST-30、INST-31；权威行为见[安装需求](../../../installation/requirements.md)、[安装设计](../../../installation/design.md)，取舍见[本地目录候选与运行时复用 ADR](../../../installation/adr/009-fast-local-install.md)。

本功能包括 Fast/Full 模式、应用构建复用、运行时 generation、源码与启动结果核对、进度和相关回归。正式 ZIP 的摘要、安全解压与系统依赖门槛保留。具体模型、任务恢复、用户数据格式、发布和自动清理不在范围内。

## 构建与缓存契约

- `install-local.cmd` 仍调用 PowerShell 7 开发入口，默认 `-Mode Fast`；`-Mode Full` 选择完整包构建及正式安装。两类构建记录分离，Fast 收据不能作为 Release 包证据。
- 共享应用组装负责三个 EXE、同一 SourceDigest、图标、input-host.json、插件、辅助脚本、包描述及许可证。Full 再加入运行时并压缩；Fast 只生成应用目录和本地收据。固定 Windows amd64、CGO、Go flags、workspace 与工具链选择，不接受环境 overlay/workspace 改变编译输入。
- 源码指纹遍历仓库第一方文件的实际内容与相对路径，不按目录或扩展名白名单筛选；包含根文件、新增顶层包与其内嵌资源、未提交文件、删除及重命名。排除明确保留的生成与本地状态目录，这些位置不承载应用构建输入；拒绝源码中的重解析点和外部本地 Go replace。构建配置、工具链版本、脚本和文档也进入身份。
- 开始、构建结束、激活前及启动后核对源码；变化时失败，要求重新执行。应用缓存复用前校验完整文件清单与 SHA-256，宿主继续受现有版本/源码/摘要约束。
- 首版继续调用三个 Go build 入口，使用 Go 编译缓存；不自行维护 Go 包依赖图。源码和配置完全相同且产物有效时跳过整个应用构建。

## 安装目录与运行时

- 正式安装器提供窄 `InitializeLocalCache` 入口，先解析已有安装的数据目录，校验空目录或合法安装标记，解析现有祖先实际路径并检查程序与数据分离，再初始化程序目录。该阶段不创建节点数据、不停止节点、不安装系统组件。
- 开发入口在规范化程序目录持有 `.local-runtime.lock`，串行查找、导入与发布缓存；根目录初始化与最终激活使用安装锁，Fast/Full 共用最终激活锁。仓库级锁只串行同仓库入口，不能替代目标安装锁。构建和运行时准备期间不持有 service.lock。
- 运行时位于 `local-runtimes/<dependency-key>-<generation>`；key 包括依赖清单、锁、Windows amd64 和准备逻辑，generation 是独立准备实例。以新的临时目录完成准备，检查后同目录重命名发布，最后原子替换 key 索引。发布不覆盖已有 generation；索引损坏或准备中断视为未完成。
- 首次导入验证来源目录无重解析点、Node/Go 版本、锁、所有已安装锁定包 metadata，完整复制 Node/runtime 并保留许可证。收据记录 Node、根 package/lock、直接组件 package.json 及其声明的入口、声明原生模块的摘要；普通缓存命中只检查这些明确文件及收据身份。安装时再执行 bundle-check、真实原生模块加载和系统依赖检测。
- 热命中不遍历全部传递依赖文件。缓存关键检查失败或显式 `-RepairDependencies` 都重新按锁准备，不再使用旧 prepared.json；可复用经过原始摘要验证的下载或 npm 内容缓存。`RepairDependencies` 与 `PreparedPath` 同时指定时拒绝，避免把损坏目录再次导入当作修复。显式 PreparedPath 首次导入仍需完整 metadata/锁检查，不将其视为 npm 字节重新验证。
- 应用版本内只有 `runtime` junction 指向本安装内的完整 generation；三个 EXE 和插件为普通文件。拒绝外部目标、未完成收据及意外重解析点。运行中的版本与 generation 不被原地修改，仓库 out 清理不影响安装。
- 区分应用收据身份与安装版本身份：后者绑定应用收据摘要、runtime generation 和 runtime 收据摘要。同源码修复复用应用产物，创建指向新 generation 的新版本；已有版本复用时重新核对应用清单及实际链接目标。
- 本功能不自动递归清理旧版本和运行时。临时候选失败清理先移除自身 junction，再清理普通文件，禁止沿链接删除目标。

## 激活、正确性与进度

本地目录候选参数与 ZIP/Release 选择互斥。独立 install.ps1 保持 PS5.1 和内存执行能力，不依赖仓库 helper。先检查候选清单、路径、内容和运行时，并将应用收据的版本和源码摘要与受摘要保护的宿主清单绑定，再进入与 Full 共用的节点归属核对、正常停止、锁、稳定启动入口、快捷方式和 installation.json 更新。

仅本地同进程入口可传 `BeforeLocalActivation` 校验回调；固定无返回值、失败抛错，在安装锁内、取得服务锁及任何停止动作前执行。回调只核对当前源码，构建输入知识仍属于开发 helper；ZIP/在线模式拒绝该参数。不是通用生命周期扩展点。

启动后先验证目标进程路径/身份与 loopback health，再读取登录 token，禁代理/重定向访问 `/api/info`，核对 source_sha256。检查失败明确报错，不自动回退数据或强杀进程。源文件在激活后继续变化时最终检查报 source changed。

各阶段输出开始、完成、耗时和缓存原因；超过 5 秒的构建、复制、压缩、准备输出心跳。子进程 stdout/stderr 并行排空，退出码保留，输出和阶段耗时存入当次生成目录。解压按实际处理条目输出进度，不为百分比增加整树预扫描。重定向输出仍可观察，不仅依赖 Write-Progress。

## 验收与验证

- 真实指纹函数：Go、Web、txt、插件、未跟踪输入、删除/重命名均失效；构建中或激活前变化拒绝；环境覆盖不造成陈旧缓存。
- 应用损坏、未知 schema、重复/越界路径、遗漏/额外文件、重解析点与错误宿主被拒；失败发生在旧节点退出之前。
- 首次空目录成功；陌生非空目录和 program/data 实路径重叠拒绝；跨入口并发不交叉发布；中断不发布完整标记。
- dependency key 变化、缓存关键文件损坏、repair 和同源码新 generation 的实际链接切换；RepairDependencies 不复用 prepared。
- 真实 Windows 隔离新装、热重复、代码变更重建、在线正常停止/重启、启动摘要一致；保留自定义 data、身份、token、历史与快捷方式选择。模型、真实桌面和系统组件安装独立验收。
- 更新后的真实 Full 构建及其包清单、三个程序/图标、宿主、插件、许可、manifest/latest-build 登记检查；PS5.1 安装、在线引导和 Fast↔Full 互操作必须有直接验证，旧 ZIP 不能替代新 builder 证据。
- 性能硬验收为热缓存普通改动复制零运行时文件、创建/解压零 ZIP；重复输入跳过应用构建。记录阶段、总耗时和停机时间；一分钟内为暖缓存目标，首次准备、修复和 Full 单独计量。

实现与验证入口、环境限制和当前结果维护在[验证说明](validation.md)。

## 规模评估与状态

职责分为应用组装、开发缓存/收据、进度与正式安装。install.ps1 为 873 行，保留 PS5.1 独立脚本契约；安装校验与生命周期函数各自内聚，没有超限文件拆分。新增开发 helper 分别承担应用构建、缓存与进度，函数均按 100 行检查；生成物与第三方依赖不计入手写代码规模。

实现、工程验证和独立复审已完成，本地安装提速效果已通过用户实际使用验收。专项验证边界见[验证说明](validation.md)，提交和发布由 Git 与 Release 记录追溯。
