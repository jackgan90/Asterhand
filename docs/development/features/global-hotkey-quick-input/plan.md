# 本机全局快捷键与快捷输入面板

## 状态与目标

状态：Windows 首版开发、独立实现审计和用户验收已完成。隐藏 CPU 冻结门槛保留 failed，作为首版性能限制；工程覆盖及专项验证范围见[验证说明](validation.md)。本功能尚未发布。

目标是在 Windows 当前用户的交互桌面，以全局快捷键呼出可编辑的文本面板，并通过现有 Web 设置本机快捷键。面板采用“星核 · 紧凑浮层”布局。当前不执行文本、不调用模型；未来逐步增加角色、skill 和脚本入口。

关联全局目标 C02、C04、R03；R20、R23、R11 仅说明未来方向，不计入本次实现。涉及 [Web 需求](../../../web/requirements.md)、[Web 设计](../../../web/design.md)、[安装需求](../../../installation/requirements.md)、[安装设计](../../../installation/design.md)、[节点设计](../../../node/design.md) 和 [测试设计](../../../testing/design.md)。

## 输入与窗口行为

| 操作或事件 | 行为 |
|---|---|
| 有效全局快捷键，面板隐藏 | 在前台窗口所在显示器的工作区内呼出，尝试激活并聚焦编辑器 |
| 同一快捷键，面板已显示 | 收起，保留草稿；预热中的重复呼出合并，不创建第二个面板 |
| Enter / Shift+Enter | 换行；中文组合输入期间先由输入法处理 |
| Esc | 候选组合期间交给输入法；无组合时收起 |
| 点击外部窗口 / Alt+Tab | 收起并保留草稿，不主动夺回焦点 |
| 窗口关闭 | 隐藏面板，不退出节点、不取消任务 |
| 禁用快捷输入 | 隐藏并释放注册/渲染资源；本次运行内的有效草稿仍由输入控制器持有 |
| 锁屏、桌面切换、远程会话断开 | 隐藏，不在恢复时自动弹出；解锁后下一次有效呼出再显示 |
| 程序正常退出 | 清空应用管理的草稿和待处理 UI 请求，释放本进程拥有的注册与 WebView 对象 |

文本为有效 Unicode，编辑器内部统一 LF 换行；空格与制表符保留，不 trim。首版有效草稿最多 16,000 UTF-8 字节，前端和宿主使用同一规则，不能把 textarea 的 UTF-16 maxlength 当作字节校验。超限拒绝本次编辑并明确提示，不静默截断；IME 组合中不裁切候选，在提交组合时检查，超限恢复该次编辑前的有效文本。粘贴不修改剪贴板。

输入控制器持有一个有长度上限、单调版本的内存草稿；编辑器通过限定消息同步已确认的编辑，忽略过期版本。主题切换不重建编辑器或覆盖选区/撤销栈。主动禁用或重建前，先取得当前有效草稿的确认快照；无法确认时保留现有编辑器并报告失败，不伪装保存成功。渲染进程意外失败只能恢复最近已确认的草稿，必须显示恢复提示；尚未提交的输入法候选不计入恢复承诺。

草稿不写入应用配置、数据库、业务日志、浏览历史或 Web 存储，也不送入模型或节点协议。这个规则约束应用持久化，不承诺清除操作系统分页、崩溃转储等系统级痕迹。

窗口为单实例、无任务栏按钮的工具浮层，默认宽约 680 DIP，高度随文本增长并受工作区约束；以所在显示器工作区的水平中心、上方约三分之一处定位。小屏裁定宽度和最大高度，不允许窗口脱离可见区域。失效前台窗口回退到鼠标所在显示器，再回退到主显示器。拔屏、负坐标、DPI 改变时重新计算。

快捷键回调中的前台激活是一次有用户输入依据的尝试，不循环抢焦点。激活被系统拒绝时报告 focus_denied，并提供托盘“打开快捷输入”供显式重试；不通过模拟按键、提升权限或修改系统前台锁设置绕过。主动收起只在本浮层仍持有前台且原窗口有效时尝试恢复原窗口；外部失焦不恢复。

## 默认快捷键与键盘表示

默认组合确定为三键 `Ctrl+Alt+J`，优先满足高频呼出的按键舒适度；普通键盘和紧凑键盘共用该默认。首次配置与恢复默认使用同一组合，保留 Web 自定义及托盘打开入口。真实系统注册、按键派发和 MOD_NOREPEAT 由显式桌面测试覆盖；不同物理键盘和前台软件的使用体验另行验收。

`Ctrl+Alt+J` 与 [Visual Studio 对象浏览器](https://learn.microsoft.com/en-us/visualstudio/ide/default-keyboard-shortcuts-in-visual-studio)及 [IntelliJ IDEA 的 Live Template 包围操作](https://www.jetbrains.com/help/idea/using-live-templates.html)重叠是已接受的局部快捷键取舍，不对这两项弹出警告、要求二次确认或阻止启用。系统已被其他进程注册的全局组合仍须实际检测并按冲突处理。自定义组合的其他已知冲突提示与系统注册状态分别展示。

采用具名 HotkeyBinding 值对象，包含修饰键集合与平台中立的命名键。Windows 显式映射到虚拟键；字母数字保存逻辑字母身份，例如 KeyJ 对应 VK_J，不把非拉丁布局中的浏览器物理 code 猜成字母；修饰键顺序、大小写和等价表示由唯一规范化函数处理。显示标签不参与业务判断。首版允许 Ctrl/Alt 至少一种，可附加 Shift，加一个普通键；不区分左右修饰键。排除单独按键、纯修饰键、仅 Shift 加可打印键、Fn、连续双击、F12、Win 和系统保留组合。

首版收敛到字母、数字与命名功能键，暂拒绝 OEM 标点，避免跨布局歧义。录制使用 event.key 的逻辑字母和受限命名键；非拉丁字母提示使用选择器或切换布局。布局变化保持保存的虚拟键身份，不重写组合；未来 OEM 支持需增加布局识别与重新注册契约。

## 配置权威与运行状态

独立配置文件为节点数据目录下的 `desktop-settings.json`，只保存 schema_version、revision、enabled、binding、theme_id。文件大小上限 16 KiB；主题 ID 来自随包清单。配置由 DesktopPreferencesStore 唯一持有，与一般节点配置并列，不复制凭据、模型、工作区或 peer 字段。

初次缺文件采用 `Ctrl+Alt+J` 与内置主题；正常启动按 enabled 尝试准备面板并注册。已存在但 JSON 损坏、版本过新或字段无效时，保留原文件、关闭快捷输入并报告 config_invalid，节点继续；不能当作缺文件直接覆盖。显式恢复默认需先保全旧文件，走独立恢复流程；写入失败保持原文件。升级保留独立数据目录；旧版本不理解新 schema 时仅禁用该桌面功能。

运行状态与持久化配置分开返回：

- `desired`：期望 enabled、binding、theme 和 revision。
- `registration`：disabled、initializing、registered、conflict、unavailable、unsupported 或 config_invalid。
- `effective_binding`：仅在系统已注册且允许触发时填写。
- `surface`：not_created、initializing、ready、failed 或 closing；error_code 表示稳定错误分类，runtime_version 报告实际加载版本。
- `cleanup_pending`：仍待释放的本进程旧注册；其触发事件全部被屏蔽。
- `last_operation`：最近变更的 ID、提交 revision 和结果，供响应丢失后对账。

“已注册”只说明当前交互桌面的系统注册结果；“面板就绪”独立呈现。冲突与资源不足、线程错误、运行时缺失、无交互桌面分开，不把所有 Win32 失败映射成占用；不猜测占用软件名称。

同数据目录复用现有 service.lock/启动器单实例边界，不创建第二个权威写入者。同一用户同一桌面运行不同数据目录的节点时，各自配置独立；同组合由系统仲裁，后启动者报告冲突。不同 Windows 登录会话不提供自动迁移或统一设置。

## 快捷键提交与失败恢复

DesktopController 串行处理变更、检查、录制和停止。HTTP 使用自己的窄接口调度，不持有 App 全局锁等待 UI/Win32 完成；所有注册/注销操作都投递给持有注册窗口的 OS 线程。新的注册使用独立 ID，不能复用相同 HWND/id 掩盖旧资源；退休 ID 在消息排空前不复用，分派同时核对 ID 和组合。

变更请求包含 operation_id 和 expected_revision。相同 operation_id 和相同参数重试返回原结果；同 ID 改参数或版本过期返回 409。每节点最多保留 64 条、5 分钟内的操作结果，过期后通过 revision 与当前状态对账，不能因 HTTP 超时重放旧意图。

| 阶段 | 动作与可观察语义 |
|---|---|
| 校验/预备 | 检查 schema、权限、版本、退出状态、UI 能力；旧组合继续有效。新组合以候选 ID 注册，但事件不触发面板 |
| 系统注册失败 | 不落盘、不释放旧组合；返回 conflict 或具体 unavailable |
| 提交前写入失败或取消 | 释放候选，保留旧期望配置与旧有效组合；释放候选失败则登记 cleanup_pending，屏蔽其事件并报告残留 |
| 持久提交 | 用 Windows 上验证过的同卷替换机制写入完整配置；禁止先删旧文件再重命名。成功返回新 revision 是提交点 |
| 提交后发布 | 在控制器内发布新 desired/effective 并允许新 ID 触发；随后释放旧 ID |
| 提交后释放失败 | 保留新持久配置与有效组合，旧 ID 禁止触发；显示已提交且 cleanup_pending，不宣称回滚成功 |
| 响应丢失 | 客户端查询 operation_id / revision；已提交结果不因连接关闭撤销 |
| 进程中断 | 注册不持久化；下次启动只按磁盘中的完整旧版或新版配置重新申请，仍可能遇到其他进程新占用 |

配置替换、提交后状态发布之间不受普通请求取消打断；停止请求与该临界区串行。不能保证磁盘和 OS 注册跨系统原子性；通过明确提交点和启动重新注册收敛。对掉电损坏保留错误状态与原始文件，不虚构掉电绝对持久保证。

禁用先持久提交 enabled=false，再关闭触发并释放注册；释放失败仍返回“已禁用，旧注册待清理”。已禁用时编辑组合只做瞬时注册检查，成功后释放并保存，页面明确是检查时可用；重新启用必须实际持有注册。主题单独变化不注销再注册快捷键。

相同配置且运行健康时为无操作；相同配置但当前 conflict/unavailable 时，显式“重试生效”重新准备和申请，不能跳过。cleanup_pending 最多自动重试三次，随后停止自动重试并提示从托盘退出/重新启动本节点；不持续抢占或终止其他进程。

存在 cleanup_pending 时拒绝新的注册、检查和录制请求，只允许查询、禁用、清理与不涉及注册的主题修改，避免残留注册无限累积。任意时刻最多持有两个注册：正常为有效与候选/退休各一个，禁用后可以是两个待清理注册。原生消息队列上限 32；HTTP 另设 8 个并发桌面操作额度，满载返回 429。输入草稿合并到一个有界版本，不为每次按键累积后台工作。

## Web 设置与录制租约

Web 增加“本机快捷输入”设置区域，显示作用节点、期望/实际组合、面板状态、启用、组合录制与选择、保存并应用、重试、恢复默认和内置主题。未配置模型、模型检查中或存在在途任务时仍可修改；不清除 ModelVerified，不广播 peer 元数据，不创建任务。

设置接口在本机 API 下独立分派：GET/POST `/api/desktop/settings`、POST `/api/desktop/check`、POST `/api/desktop/retry` 和 `/api/desktop/recording/start|poll|cancel`。请求体最多 16 KiB，拒绝未知字段与多余 JSON。全部复用已认证 Web 会话、Host、Origin 和 CSRF 防护；peer TLS 路由不注册这些接口。停止接收后沿用节点屏障拒绝新 HTTP 请求，托盘可观察收尾状态。

录制仅在用户明确进入后开始，采用一个当前会话所有的短期租约。服务器生成不透明 recording_id，绑定认证会话、页面实例和开始 revision；同时最多一个录制者，第二录制者返回 409。截止时间取开始后 30 秒与认证会话到期时间的较早者，不自动续期，超时后需显式重录。页面失焦、取消、保存成功、配置 revision 改变或节点退出都结束录制；pagehide 只是加速释放，正确性依赖服务器计时与会话检查。断线无法保证被立即检测，但最多抑制 30 秒，不能依赖浏览器正常关闭通知。

录制期间保留原系统注册，自己的快捷键事件只进入录制结果，不呼出面板；租约结束后恢复正常分派。普通组合由已聚焦页面捕获并交给原生适配器校验；浏览器截获的组合通过选择器填写。无全局键盘钩子，不持续记录其他程序输入。租约 ID 不授予保存权限，保存仍校验认证、CSRF 和 revision；取消/超时不改配置。

检查成功也必须成功释放临时注册；清理失败时检查不能返回单纯“可用”，并屏蔽该临时 ID。保存时重新检查并持有新组合，检查结果不构成预留。

## 桌面线程与生命周期

HotkeyService 复用节点托盘所属 OS 线程和专用消息分派，注册资源与托盘图标分开。QuickInputSurface 使用独立、锁定的 STA UI 线程和自己的窗口/消息循环，避免现有托盘 MessageBox/TrackPopupMenu 的嵌套消息循环影响 WebView2。窗口过程不做磁盘 I/O、HTTP 或阻塞等待；配置写入由控制器执行，UI 回调只投递消息。COM 初始化/释放、WebView 创建和调用都在其所属线程。

快捷输入窗口的 WM_CLOSE 只隐藏，WM_DESTROY 只结束其自身 UI 线程；不能套用现有托盘窗口的停止节点回调。初始化、激活、渲染进程失败等预期错误只进入 surface.failed/unavailable，不调用 RequestStop。面板不可用时释放/屏蔽本功能注册，避免一个无法显示的面板持续吞掉用户快捷键；期望配置保留，用户可显式重试。

节点开始退出时先关闭桌面变更与呼出入口，终止录制，等待已经进入提交点的变更结束，再释放注册与面板。UI 收尾不需要用户点击、不依赖 HTTP 回调；必须有界，超时记录实际残留并继续节点现有的持久化/执行清理。WebView 的异步创建结果携带控制器代次，禁用/退出后的迟到回调只负责释放自己的资源，不能重新创建窗口或注册。

面板收尾在其 STA 上按“关闭业务消息入口、解除业务事件订阅、关闭 controller、释放对应 WebView/controller 引用、异步观察本 profile 的浏览器进程退出、撤销剩余观察者并释放 environment/handler COM 引用、COM 反初始化、退出该 UI 消息循环”执行。不得在回调内同步等待本线程事件；Go 回调对象在最后一次可能调用结束前保持有效，不能只销毁 HWND 或提前释放 callback。重建的旧实例未收尾时不再创建第二个实例。节点退出只等待有界收尾期限，超时保留 closing/残留诊断，不能阻塞核心收尾或删除仍在使用的 UDF。

本方案不增加常驻启动器、监督进程或 Windows Service。使用 WebView2 自身的子进程，关闭时只处理本实例拥有的对象/进程，不按进程名终止系统或其他应用的 WebView2。可恢复的 renderer 失败与整个宿主进程崩溃分开：同进程方案不承诺宿主崩溃后任务继续，沿用节点重启对账语义。

## WebView 内容、安全与存储

快捷输入页面从随包资源加载到独立的应用虚拟 HTTPS 来源，唯一主入口为 `/quick-input/index.html`；不使用 file://，不携带本机 Web 登录 token，不复用通用浏览器 profile。它不访问通用任务/设置 HTTP API；认证设置页仍在现有 loopback Web 中运行，两条权限链明确分开。

原生桥只接受预定义的 ready、hide、resize、snapshot 和 draft_updated 消息，带协议版本、窗口代次和草稿版本。双向发送前均验证当前 WebView 实例、固定的主文档 origin/path、消息结构、大小和范围；页面不创建子框架，任何来自子框架的消息均拒绝。单条 JSON 消息最多 128 KiB，解码后的有效草稿仍受 16,000 UTF-8 字节限制，窗口大小由宿主按工作区限幅。桥不暴露通用 host object、脚本执行、文件读取、进程调用或任意 URL 打开。消息通过 JSON 序列化，输入按文本呈现，不拼接可执行脚本或 HTML。

宿主在顶层/子框架导航、新窗口、下载、权限请求和资源请求处实施允许列表，仅允许随包资源；禁止外部网络、任意本地路径、拖入文件导航和未经授权的 frame。页面 CSP 与宿主限制共同生效；发布版关闭调试入口、默认脚本弹窗和不需要的浏览器功能。主题来自固定资源 ID，不接受任意 CSS/HTML/远程背景 URL。

UDF 显式位于节点数据目录的独立受保护子目录，不能落在版本安装目录或用户默认浏览器目录；已有授权目录保护覆盖整个节点数据目录。使用独立的 InPrivate profile，禁用自动填充与密码保存，不使用 localStorage/sessionStorage/IndexedDB 保存草稿。正常退出后等待本实例相关浏览器进程释放，再按 API 支持清理会话数据；不在进程仍使用 UDF 时删除目录。清理失败保留可诊断状态，不阻断任务服务。

首版桌面面板仅在标准权限的当前用户交互进程启用。节点以管理员、SYSTEM 或非交互模式启动时保留 Web/任务能力，面板报告 unavailable；不静默提升权限、不禁用浏览器沙箱。普通权限节点面对管理员前台窗口的唤起能力必须实测，失败按 focus_denied 处理。锁屏、UAC 安全桌面、其他登录会话不属于可输入桌面。

## 外观、依赖与资源门禁

默认内置“星核”主题，深蓝底和克制的青紫光晕；另含“霜蓝”亮色主题。编辑区和底部快捷键提示保持清晰，遵循高对比与减少动画设置，不使用持续粒子动画。选择器切换 theme_id，无重载地更新颜色变量。背景层预留受控资源 ID，未来生成图片经审查后随包分发，文本与控件保持真实 UI。

使用 WebView2 Evergreen：复用合格的系统安装，缺失时由安装器使用固定版本、官方来源、摘要校验的离线安装材料补齐；不得使用滚动 URL 的当前响应冒充已验证版本。现有版本已满足需求时不降级、不修改共享更新策略，卸载 Asterhand 不卸载共享 Runtime。SDK、加载器、Go 绑定和安装材料分别登记版本/许可证，实际 Runtime 版本独立记录到诊断与验证证据。

Evergreen 后续更新是外部平台变化，启动检查所用 API 能力与最低兼容版本，不将所有未来版本标为已验证。Runtime 初始化失败仅禁用面板；设置、托盘打开 Web、任务和节点通信继续。安装依赖失败保留已运行节点，依赖准备通过后才允许现有安装流程停止并激活节点。

运行中发现新 Runtime 不重启任务节点；当前实例继续使用其已加载版本，用户主动重建面板或下次正常启动时再采用新版本。依赖安装出现拒绝、失败或需要重启时明确报告，不自动重启 Windows、不通过停止在途任务重试；根据正式安装流程保留旧节点及待激活状态。开发机已有 Runtime 不能替代完整包的 loader 与无开发工具干净安装验证。

工程门禁与平台专项验收如下；未执行条件不宣称通过。隐藏 CPU 冻结门槛作为明确的首版性能限制保留 failed，详见[验证说明](validation.md)，不阻断首版交付，其余指标独立判断：

1. 选定具体 SDK/加载器/Go 绑定版本，验证 CGO_ENABLED=0、Windows x64 构建、许可证和导出接口；不能维持既有构建契约时先修订设计，不暗中引入工具链要求。
2. 在隔离 Windows 当前用户桌面验证双线程消息调度、IME、前台激活、隐藏/恢复、renderer 失败、InPrivate/UDF、异常收尾和标准/提升权限边界。
3. 在缺 Runtime、已有合格 Runtime、离线与安装失败环境验证安装/升级/卸载策略，并完成依赖清单与脚本契约扩展；不将未知安装技术直接加入清单。
4. 验证 `Ctrl+Alt+J` 的真实注册、长按及普通/紧凑键盘唤起路径，覆盖 IDE 作为前台窗口时的助手响应；上述两项已接受的 IDE 局部绑定不作为阻塞项，真实全局占用必须按冲突处理。
5. 冷初始化、隐藏页面桥往返、WebView 子进程树内存、后台 CPU 和重复启停遵循[冻结成本协议](validation.md#资源成本协议)。前台可编辑延迟、禁用长时间成本与服务 ready 基线单独验证，不用桥往返指标替代。

未启用时不创建 WebView；启用后异步准备唯一隐藏面板，不能阻塞任务服务 ready 或每次按键启动一个新浏览器。首次准备时显示 initializing，后续呼出复用；禁用后释放渲染资源。测量包含整个新增 WebView 进程组，不能只报告 Go 主进程或只测缓存命中。重复启停、主题切换和错误重试后的资源数量必须有界。

## 实现职责与文档同步

| 职责 | 实现边界 |
|---|---|
| 本地配置、组合与事务 | internal/quickinput 持有偏好、草稿和控制器；保存/注册/释放使用明确提交点和故障状态 |
| Windows 注册 | internal/desktop 在原托盘 OS 线程注册和注销，候选/退休 ID 的事件不触发面板 |
| 文本宿主 | internal/quickinput 的独立 STA 线程管理 WebView2、窗口、受限桥和私有 profile；正文与主题资源随包嵌入 |
| Web 设置 | internal/app/desktop_api.go 与 web/desktop-settings.mjs 提供独立认证设置入口、录制租约、占用检查和重试 |
| 安装与回归 | 固定依赖清单、构建许可收集、Runtime 安装边界和桌面测试接入已有构建/验证流程 |

底层桌面包不导入 app/task，应用通过窄接口调度。macOS/Linux 适配器返回显式能力状态，不通过空成功模拟支持。当前不建立通用命令注册表、解析器或插件运行时。

Web、安装领域 requirements/design 及节点生命周期、测试说明、路线图和支持矩阵已同步。线程、权限、安全来源与依赖取舍由[快捷输入宿主决策](../../../installation/adr/006-global-hotkey-input-surface.md)维护，与[桌面入口决策](../../../installation/adr/004-desktop-launcher-and-tray.md)共同约束节点生命周期。

实现按 [代码风格](../../code-style.md) 评估实际修改后的文件/函数规模，避免把新职责全部加入既有 api.go、app.js 或托盘窗口过程；触发超限且可安全拆分时，先提交拆分方案取得同意。新增职责分布在独立文件，修改后文件均未超过 1000 行。原有 settings 函数为 125 行，其职责和实现保持，新桌面路由另设文件；desktopSettings 的外层表单闭包超过 100 行，内部事件函数共用状态，保留以避免将一次性表单状态散布到全局。

## 验收与验证入口

下列 V 用例定义验收全集；自动化覆盖与仍需人工验收的边界见[验证说明](validation.md)。自动化用例已接入 [测试入口](../../../../tests/README.md) 和 [脚本指南](../../../../scripts/README.md)，提供独立、隔离数据目录与桌面的测试脚本，不能只靠手动按键或任意 sleep 判定完成。

| 用例 | 触发与预期结果 | 验证方式 |
|---|---|---|
| V01 基本唤起 | 首次配置与恢复默认均为 Ctrl+Alt+J；浏览器关闭或 IDE 位于前台时可呼出；重复/长按不创建第二面板；仅隐藏不退出节点 | Windows 交互桌面，普通/紧凑键盘真实注册与按键 |
| V02 设置事务 | 另一测试进程占用新组合则保存失败，旧组合有效；覆盖写入失败、候选释放失败、提交后旧注册释放失败、并发版本和响应丢失 | 隔离 OS 占用进程 + 控制器故障注入 |
| V03 启动降级 | 测试进程先占用保存组合；Runtime 缺失/失败；桌面配置损坏/过新；节点仍 ready，状态具体可见，修复后显式重试可生效 | 隔离节点与受控依赖故障 |
| V04 持久与迁移 | 修改、禁用、重启、升级保留组合与主题；不同数据目录竞争不互相覆盖；仅修改桌面配置 | 文件快照与多进程测试 |
| V05 中断与资源 | 在预留、写入、提交、旧注册清理四个边界结束测试进程；重启读取完整配置，无借用旧 HTTP 意图；录制超时/掉线/会话过期恢复分派 | 子进程检查点与控制时钟 |
| V06 桌面行为 | 副屏、负坐标、100/150/200% DPI、拔屏、锁屏/解锁、RDP 断开；外部失焦不抢焦点，UAC 桌面不输入 | 实际 Windows 桌面专项 |

| V08 草稿与主题 | 收起、切换主题不丢已确认草稿、选区和撤销；禁用/重建快照失败可见；renderer 失败恢复最近已确认版本；退出重启不恢复草稿 | 组件测试 + WebView 真实进程事件 |
| V09 安全边界 | 伪来源/子框架/错误代次/超大桥消息被拒绝；外链、新窗、文件导航、权限与下载被阻断；草稿不出现在业务日志与应用持久存储 | 自动化攻击 fixture + 文件/网络检查 |
| V10 对象外回归 | 在途任务/模型检查时修改组合不影响其状态或 ModelVerified；面板初始化失败、关闭、取消录制不调用节点退出；节点正式退出仍释放任务/端口/本实例进程 | 既有生命周期/设置回归 + 桌面测试 |
| V11 平台与权限 | Windows 标准用户；管理员/SYSTEM/非交互模式降级；peer 无设置入口；macOS/Linux 能编译适配器且返回 unsupported | 原生 Windows 与平台构建，跨编译不记原生通过 |
| V12 安装依赖 | 全新安装、已有 Runtime、离线、中断、缺安装材料与升级；失败不停止原节点，不影响其他应用 Runtime；新包保留配置 | 隔离 Windows/VM，正式安装链 |
| V13 性能 | 按原型阶段冻结的预算测冷/热延迟、内存/CPU、服务 ready 回归和 100 次启停后的资源归还 | 代表性 Windows 设备与基线对比 |

已有基础回归命令为 `go test ./...`、`go vet ./...`、`node --test tests/plugin-contract.test.mjs tests/web-state.test.mjs`。桌面包目前的显式入口为 `ASTERHAND_DESKTOP_TEST=1` 后执行 `go test ./internal/desktop -count=1`，它的现有合成消息覆盖不代替新增真实快捷键、IME 和 WebView2 验收。完整验证由已有 `scripts/verify-dependencies.ps1` 接入新增入口；实际命令、版本和结果保存到独立生成物目录，长期文档只维护复现方法。

本功能的 Windows 桌面验收在单机进行；共享节点生命周期与安装发生改动后，仍需按 [产品验收](../../../testing/acceptance.md) 验证两台 Windows + OpenClaw + DeepSeek 的相关路径。FakeExecutor、合成消息、VM 和交叉编译的证据分别报告，不互相替代。固定依赖、默认键注册及工程预算均有专用入口；完整包干净安装、物理 IME、显示器与会话行为仍按实际执行状态记录。
