# 本地命令完成通知

状态：实现、相关工程验证、独立审计修复复审及本机用户验收已完成，包括命令表单开关对齐、通知按内容收紧高度和圆角背景修正。圆角背景已通过双主题、不同内容高度和原生宿主回归及用户视觉验收。首个交付平台为 Windows；macOS/Linux 只预留平台接口，不声明支持。默认可读停留时间为 3 秒，验证入口与专项环境边界见[验证说明](validation.md)。

普通应用窗口遮挡通知的修复已通过 Windows 交互桌面回归和安装后的本机用户验收。

## 目标与范围

本地命令结束后，在桌面工作区右下角显示简短通知，让用户离开助手窗口后仍能知道执行结果。通知跟随当前节点主题，具有自然的进入、退出和堆叠位移动画；同时完成的多次运行使用有限卡片和等待队列。每条命令可独立关闭通知，新命令默认开启，现有命令缺少该配置时也视为开启。

关联现有 EXEC-CMD-02/03/09/12/14/15/16、EXEC-AUTO-01/02、AUTO-01/03/05/07/08/18/24/25；领域新增 EXEC-CMD-18/19、WEB-CMD-NTF-01/02/03、INSTALL-NTF-01、AUTO-NTF-01 和 TEST-NTF-01，下表保留 CN 编号便于对应功能范围。

涉及[执行器需求](../../../executors/requirements.md)、[命令注册](../../../executors/local-commands.md)、[执行与恢复](../../../executors/managed-local-commands.md)、[Web 需求](../../../web/requirements.md)、[Web 设计](../../../web/design.md)、[安装设计](../../../installation/design.md)和[自动化设计](../../../automation/design.md)。运行历史与日志保留以自动化设计的当前规则为准，不恢复早期“下一轮删除全部旧记录”的行为。

| ID | 必须满足的行为 | 交付位置 |
|---|---|---|
| CN-01 | 整次本地命令运行结束后产生一次提醒，多个并发实例独立识别 | 运行管理器、通知服务 |
| CN-02 | 桌面右下角卡片、主题背景、自然进退与堆叠动画 | Windows 通知宿主、展示资源 |
| CN-03 | 限制同时显示数量，多余通知按序等待，内存与恢复都有边界 | 公共通知队列 |
| CN-04 | 编辑页增加“执行结束后通知”，新命令和缺失字段的老命令默认开启，显式关闭有效 | 注册模型、Web 表单、CLI/MCP 与草稿 |
| CN-05 | 通知不抢焦点、不影响脚本执行；点击可查看对应实例日志 | 桌面宿主、现有日志窗口 |
| CN-06 | 公共规则与平台显示分离，后续平台实现适配器即可接入 | 通知接口、平台能力声明 |

本次不增加远端任务或聊天通知、声音、系统通知中心、未读中心、邮件推送、全局通知设置页或独立通知历史。队列是当前节点进程内的临时提醒缓存，执行结果和日志继续由现有存储保存。

## 呈现与交互

Windows 通知需覆盖普通应用窗口，首次显示、隐藏后复用和宿主重建均遵循相同的层级检查。验证时同时核对原生置顶样式、卡片中心命中的顶层窗口和前台焦点。还需覆盖 Windows 接受定位请求但保留原层级时的恢复行为，见[完成通知设计](../../../web/completion-notifications.md)。

### 参考和选择

参考 [VS Code 的右下角通知布局](https://code.visualstudio.com/docs/configure/custom-layout#_notification-position)，采用紧凑卡片、明确状态和关闭入口；按[微软通知设计建议](https://learn.microsoft.com/en-us/windows/apps/develop/notifications/app-notifications/app-notifications-ux-guidance)控制信息量与频率，并让通知直接打开相关内容。这些参考不决定本项目的数量、时长或动效数值，以下数值由本计划提出。

采用应用自绘的桌面通知窗口，复用已有 Win32/WebView2 能力，便于统一主题和动效。Windows 系统通知使用[系统定义的内容结构](https://learn.microsoft.com/en-us/windows/apps/develop/notifications/app-notifications/app-notifications-content)；本功能需要控制卡片背景、堆叠和动画，因此不把系统通知作为本次渲染实现。相应地，本次卡片不进入 Windows 通知中心，也不承诺自动遵循系统勿扰策略；这项区别应进入用户说明。

### 卡片

- 宽度初值 360 DIP，窄工作区按可用宽度缩小；距右边和底边各 16 DIP，卡片间距 10 DIP。圆角约 12 DIP，细边框和轻阴影，不用大面积高饱和状态背景。
- 卡片主题底色随圆角边框一起裁剪，页面外层与 WebView2 背景透明，Windows 窗口按 DPI 裁剪圆角显示和命中区域；短标题、长标题、错误行和主题切换均不露出方角底色。
- 高度随实际内容调整，普通单行标题不预留长标题或错误行空间。首次显示前在目标宽度及 DPI 下测量，堆叠按各卡片实际高度计算；页面测量以通知身份和更新序号校验，限定在 80～160 DIP。显示容量按允许的最大高度保守计算，避免内容增长后越出工作区。
- 内容为应用标识、命令主名、结果、耗时和“查看日志”，右上角关闭。并发同名命令附开始时间；可访问名称包含可区分的运行标识。命令名最多两行，超长省略，不靠扩大卡片挤出工作区。
- 成功显示“执行完成”，失败显示“执行失败”，超时显示“执行超时”；图执行结果来自整次运行。失败仅显示稳定原因的本地化短文，不展示脚本参数、路径、stdout/stderr 或原始异常。
- 首版对自然成功、失败、超时及接纳后的启动失败提醒；主动停止、节点正常退出造成的中断、重启核对出的中断不弹出。接纳前拒绝仍在原操作入口反馈。此区分避免用户刚点击停止或退出就收到重复提示。
- 显示不激活窗口、不改变前台应用或键盘输入目标，不增加任务栏/Alt+Tab 项。普通桌面下浮于其他应用之上；不在锁屏或安全桌面显示，不保证覆盖独占全屏应用。
- 点击“查看日志”才显式打开、激活对应日志窗口，并选中通知绑定的 run ID。沿用现有 Windows 前台限制；不强制关联其他线程输入队列。
- 命令已删除、日志已过期时给出明确说明，不跳到最新一次运行，不重建命令或重新执行。若日志打开失败，卡片保留错误和重试入口；关闭按钮只关闭该提示。

### 主题、语言与动效

- 从当前节点已保存的桌面偏好取得主题和有效语言。复用星核（star）与霜蓝（frost）的背景、文字、边框、强调色和状态色；不新增一份独立主题设置，不以浏览器本地缓存为权威。
- 正在显示及等待中的通知跟随主题/语言更新。更新不重建队列、不重新计时；初次显示前完成主题初始化，避免深色主题先闪白。
- 进入初值为从右侧约 24 DIP 位移并淡入，约 240 ms，减速结束；退出为向右约 16 DIP 位移并淡出，约 180 ms；其余卡片补位约 200 ms。无弹跳和过冲，快速进出从当前位置平滑衔接，不先跳回起点。
- 优先使用合成层位移/透明度和原生窗口定位，避免持续读写布局造成抖动；窗口裁剪、阴影和卡片内容必须同步，不能出现内容被窗框截断或动画结束前突然销毁。
- 默认可读停留 3 秒，从卡片实际进入完成后计时；系统通知时长高于默认 5 秒时遵循较长的辅助功能设置。悬停任一卡片或用户主动给予键盘焦点时暂停整组倒计时和自动补位，移出后继续剩余时间，至少留 1 秒操作余量。
- 尊重系统减少动态效果设置：取消位移、缩短或关闭淡变，直接稳定排列。提示提供可访问名称、状态文本、可聚焦操作与关闭按钮；焦点不被新提示主动转移。读屏和无动画模式列入 Windows 验收。

### 多条通知与屏幕选择

- 最多同时显示 3 张，工作区放不下时自动降为 2 张或 1 张；进入中和退出中的卡片也占名额。新卡片从底部加入，已有卡片平滑上移，不覆盖其他卡片。
- 一批提示从空栈开始时，选择当前前台窗口所在屏幕；没有可用前台窗口时依次使用鼠标所在屏幕、主屏。该批显示期间固定在同一屏幕，避免焦点切换导致通知来回跳。
- 使用显示器工作区而非全屏尺寸，避开任意位置的任务栏；支持负坐标、混合 DPI、工作区变化和显示器拔插。屏幕失效时迁到可用工作区，调整不丢失倒计时或 run ID。
- 卡片外和卡片间隙不拦截桌面点击。鼠标停留时冻结自动排列，避免操作按钮在指针下移动。

## 排队、去重与故障处理

- 所有入口共用节点内的一条队列，按整次运行确认结束的顺序排队；同一命令不同 run ID 不互相覆盖，同一 run ID 的重复完成信号不重复入队。脚本图中各步骤完成不单独通知。
- 有空位时依次显示，相邻进入动作至少间隔 300 ms；退出动画结束才释放名额。队列非空也不立即挤掉仍在可读期的卡片。
- 等待区最多保存 100 条详细通知；每条使用有界结构化数据，上限 2 KiB，不携带日志正文或完整命令配置。超过容量的部分合并为“另外 N 次执行已结束”的汇总，并保留成功/失败计数；汇总也占显示名额。
- 汇总是固定大小的计数对象，不保存无限 ID 列表。首次溢出时保留它在完成顺序中的位置，后到通知不能使它无限后移；持续溢出也只更新有界计数。汇总提供“打开本地命令”，不新增通知历史页。
- 等待超过 5 分钟的详细提示合并为汇总，避免恢复后长时间刷出旧卡片。执行记录不随通知合并而删除。锁屏、睡眠或宿主暂不可用时暂停展示，可读时间不在不可见期间消耗；恢复先执行过期合并，再按限流规则显示。
- 队列由主进程持有，快捷窗口隐藏、热键关闭或浏览器退出均不停止通知。通知宿主重建时恢复同一批展示身份和剩余时长，重复快照只更新已有卡片，不重播进入动画。
- 发送与显示确认分开。已发送但显示确认不明的提示不作为一条新通知再次入队；宿主代次、通知序号和应用侧状态过滤迟到确认。已关闭或已超时的提示不因断连恢复再次出现。失效身份记录也必须有界，可使用单调确认水位与有界在途集合。
- 通知创建失败、队列溢出或宿主断连不阻塞完成保存、不占用脚本执行名额，不把已完成运行改成失败。宿主采用有界重建与退避，连续失败通过现有诊断入口反映，禁止无限启动宿主进程。
- 节点退出先停止通知展示和接收，再按已有流程收尾命令。队列不跨主进程重启保存，不扫描旧历史补发；正常退出和崩溃恢复都不会形成通知风暴。

## 配置与兼容

新增命令级字段 `notify_on_completion`，编辑页放在并发开关、整图超时附近，显示“执行结束后通知”，默认勾选。该项随保存命令生效，遵循原修订冲突和运行中禁止编辑规则。

读取当前 schema 4 的命令时，字段缺失按 true 解释，显式 false 必须保留。只兼容当前受支持格式中缺少这个新增字段，不扩大到早期已不支持的 schema。加载时不批量重写配置、不生成新修订；正常保存时写出明确布尔值，序列化不得用省略 false 的方式丢失关闭状态。较旧程序对新字段的识别不作降级兼容承诺。

新建/校验省略字段时采用 true；局部更新省略字段时保留当前值；已有命令的完整保存入口若缺字段也保留原值，避免旧页面无意重新开启。显式 null、字符串及数值拒绝，不能与缺失混淆。实现使用能区分“未传”和 false 的解码方式，并保留原有未知字段检查。

运行接纳时把有效开关保存进该次命令快照，终态根据快照决定是否通知，不在完成时重新读取可能变更的注册内容。复制命令保留原开关；表单脏状态、放弃修改、保存后重读和未保存草稿接手均携带此字段。

UI、CLI、MCP 使用相同领域规则：补齐 `commands.create/get/list/validate/patch/clone` 的相关输入、输出与 schema 描述，以及 `drafts.get/update/commit` 的命令草稿。无需增加专门的“发送通知”业务操作。结果读取仍用 `runs.list/get/wait`、`logs.read`；卡片动画、排队、关闭属于展示，按[覆盖清单](../../../automation/coverage.md)登记等价读取。

## 代码结构与平台接口

```mermaid
flowchart LR
    R[本地命令运行管理器] -->|终态成功保存| N[公共通知服务：过滤、去重、排队]
    P[节点主题和语言偏好] --> N
    N --> A[通知展示接口]
    A --> W[Windows 非提权通知宿主]
    A -.后续实现.-> M[macOS / Linux 展示器]
    W -->|用户点击与原始运行身份| L[现有日志窗口]
```

- **完成事件**：在[运行管理器](../../../../internal/localcommands/run_manager.go)的最终保存成功路径接入。现有 `persistFinalLocked` 同时完成运行记录及历史索引保存，成功后才释放 busy；首次成功完成这一步才产生事件，写盘重试、状态查询和恢复读取不产生重复。事件快照只包含身份、名称、结果、原因、耗时、结束时间和通知设置。
- **公共通知服务**：`internal/notifications` 拥有过滤、队列、容量、去重、显示名额、时钟和展示确认状态。运行管理器只依赖小型完成观察接口，不引用 quickinput/WebView2。锁内只做有上限的内存交接，进程创建、IPC 等待、显示及日志打开都在锁外进行；满载进入同一汇总策略，不开无限 goroutine。
- **展示接口**：定义平台能力、应用有序通知快照、更新外观、暂停/恢复及关闭；展示器回传实际显示、进入结束、悬停/焦点、关闭和查看日志等有界事件。队列规则只实现一次，原生 HWND、屏幕句柄、令牌、WebView2 对象不进入公共接口。
- **Windows 适配**：沿用 `AsterhandInputHost.exe` 的进程隔离基础，增加专用通知宿主模式；与快捷输入/日志分开持有窗口生命周期。单个非提权通知进程，最多 3 个可复用卡片窗口，各 STA 持有自己的 WebView2 环境接口引用，通过同一 profile 共享浏览器进程，避免跨 STA 直接传递 COM 对象；窗口数及清理中的实例也受上限约束。空闲隐藏并停止渲染与轮询，不预留遮挡整块桌面的透明窗口。
- **原型门槛**：先验证非激活窗口下 WebView2 点击、鼠标移入移出、窗口位移与淡变、阴影裁剪、透明边缘命中和双主题首帧。如果现有 WebView2 包装不能满足效果，在这一阶段调整 Windows 内部渲染方式；不更改公共队列接口、不预先引入新 UI 框架或依赖。
- **IPC**：沿用同版本宿主校验、受限管道、消息方向/大小校验和代次隔离。宿主只接收展示数据，点击只回传 notification ID；主进程核对其对应 command ID/run ID。页面不传任意 URL、路径、PID 或执行字符串。
- **日志定位**：当前[日志宿主接口](../../../../internal/quickinput/log_host.go)按 command ID 打开，需要增加可选 run ID，并贯穿窗口初始化、复用和[日志页面](../../../../internal/quickinput/assets/command-log.mjs)选择。必须支持仍在保留期内的历史实例；不让自动刷新改回最近运行，不破坏其他已有分屏的阅读位置。
- **应用装配**：由 `internal/app` 注入完成观察器、通知展示器和日志打开动作，并把 Web/CLI/MCP 的主题与语言保存统一广播给通知。通知可用性独立于快捷键是否启用；无交互桌面或不支持的平台只停用展示，不影响命令运行。
- **后续平台**：macOS/Linux 实现相同展示与生命周期接口，能力明确报告 unsupported/unavailable/available；本轮仅做公共核心的编译与测试，不提供空实现假报已显示。各平台的屏幕、DPI、桌面会话、减少动态效果和可访问性分别验证后再启用。

## 实施顺序与文档同步

1. 补齐所属领域需求、设计和一份桌面通知 ADR，固定提醒终态、默认开关、队列/重启语义及自绘窗口取舍；更新自动化覆盖与机器 schema 变更清单。
2. 完成 Windows 通知窗口原型，以双主题、3 张堆叠、鼠标操作、不抢焦点和混合 DPI 验证上述渲染方案。动画参数在此阶段做视觉调整。
3. 增加配置字段和兼容规则，贯穿注册、命令快照、Web 编辑/脏状态、公共操作、CLI/MCP schema、命令复制和草稿接手。
4. 接入运行终态事件，实现公共队列、过滤、去重、限流、汇总、时钟及恢复状态；使用可控时钟和展示替身验证竞争。
5. 接入正式 Windows 通知宿主、主题语言广播、可访问性与桌面会话状态；扩展日志窗口定位到原 run ID，处理历史/删除/过期。
6. 完成回归与真实 Windows 视觉验收，处理发现的问题；用户验收后再分别处理本地提交及后续发布。

## 验收与验证

| 场景 | 预期结果 |
|---|---|
| 新命令、老 schema 4 缺字段、显式 false 后重启 | 前两者默认开启；false 始终保持关闭，无自动重写和数据丢失 |
| Web/CLI/MCP 创建、局部编辑、复制、草稿接手 | 有效值、修订冲突和运行锁一致；缺省/null/false 按约定区分 |
| 成功、非零退出、超时、接纳后启动失败 | 收尾及最终保存成功后恰好一条，对应正确终态与实例 |
| 图内多个节点结束、用户停止、退出、启动拒绝、历史读取 | 不误触发通知；图成功前不提前报告成功 |
| 停止/完成竞争、终态写盘失败后重试 | 与现有状态机结果一致，不提前弹出、不重复、不阻塞收尾 |
| 10 个实例接近同时完成，含同命令多实例 | 同屏不超过 3 条，其余有序显示；每条内容和日志目标正确 |
| 队列边界、100 条以上、持续高流量及长期悬停 | 内存有界，溢出/过期汇总不饿死，已有卡片不被强制挤掉 |
| 双主题切换、中英文切换、长命令名 | 初始无白闪、对比清晰、局部更新、不重置时长和队列 |
| 进入/退出/补位中再次关闭或进新通知 | 动画连续、无重叠/裁剪/瞬移；退出卡片占名额直到真正隐藏 |
| 快捷窗口隐藏、热键关闭、浏览器关闭、其他程序输入 | 仍能提示；不抢焦点、不吞键盘、卡片间隙能操作桌面 |
| 双屏、负坐标、100%/150%/200% DPI、任务栏变动和拔屏 | 卡片始终在有效工作区，宽高与堆叠不越界 |
| 锁屏/睡眠、通知宿主崩溃、迟到回执、节点重启 | 不在不可见期间耗尽展示时间；宿主恢复有界且不重复；节点重启不补播历史 |
| 排队时启动新一轮、命令重命名/删除、日志淘汰 | 打开原实例；不可读取时明确反馈，绝不改开最新实例 |
| 减少动态效果、系统延长通知时长、读屏 | 按系统偏好展示、文本可读、操作有名称且不主动夺取焦点 |
| Windows 无交互桌面、macOS/Linux 未实现 | 展示能力明确不可用，命令服务与状态读取继续正常 |

核对通知宿主闲置时无持续轮询、窗口/进程数和队列内存有界；记录冷启动到可见的延迟及动画帧稳定性。使用项目固定工具链和已安装 WebView2；Mac/Linux 仅编译或公共测试不能记作该平台产品验收。文档修改后检查根文档、领域、功能、模板和指南的全部本地链接，目标应为已跟踪文件或同一交付新增的文档。

## 规模与维护

规划时相关文件均未超过 1000 物理行：`run_manager.go` 424 行、`surface_windows.go` 483 行、`host_runtime_windows.go` 188 行、`log_surface_windows.go` 192 行、`hostipc/protocol.go` 246 行、`web/local-commands.mjs` 308 行、`web/index.html` 300 行、`web/style.css` 791 行。

新增队列、Windows 通知窗口和通知 CSS/JS 按职责独立组织；不继续把卡片规则堆进快捷输入主窗口或通用 Web 样式。实施后重新统计物理行数和函数规模；新增函数以 100 行内为目标。若修改造成文件超限且适合拆分，按[代码风格](../../code-style.md)先说明拆分范围并取得同意；本计划不预先批准拆分。

交付代码的手写改动文件均低于 1000 行。`web/i18n-catalog.mjs` 和 `internal/quickinput/assets/i18n-catalog.mjs` 为 `scripts/sync-i18n.mjs` 从权威词表生成的产物，按生成代码分类，不拆分输出。`hostipc.Message.Validate` 超过 100 行，保留集中校验消息种类、方向与允许字段的职责，通知负载校验已经放在独立文件；`TestNativeNotificationRendering` 超过 100 行，连续验证同一真实窗口生命周期的进入、外观更新、不抢焦点和退出，集中保留便于核对测试顺序。其他新增 Go 函数低于 100 行。
