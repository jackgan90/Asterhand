# 本机持续聊天与可扩展快捷入口

## 基本信息

- 状态：核心实现与日常聊天用户验收完成。2026-10-28 用户确认真实消息发送、历史记录查询、新对话、展开/收起符合预期；P5 中其余故障、实体桌面、升级与成本专项保持独立状态，见[验证说明](validation.md)。实现、工程验证、用户验收和提交分别记录。
- 目标：从 Windows 全局快捷输入发起与当前节点助手的连续文本对话，展开阅读回复，重启后查看并继续已有会话。
- 产品定位：快捷输入保持多功能入口；聊天是首个操作，未来 skill、snippet、节点/角色选择通过独立能力加入。
- 关联全局要求：R03、R04、R05、R17、R20、R23、R27、R28、C02、C05、C12、C13。
- 设计决策：[ADR-AST-005](../../../assistant/adr/005-conversation-runtime-and-transport-boundaries.md)。

## 首版范围

这里的“首版”专指本功能第一次交付，不改写现有 Windows 跨节点任务产品范围。

| 纳入 | 可观察行为 |
|---|---|
| 当前节点、默认助手 | 使用该节点已配置的 OpenClaw/provider/model；内部使用稳定 node/role ID |
| 持续文本聊天 | 同一会话中追问有上下文；真实模型流式回复，可停止 |
| 展开/收起 | 发送后自动展开，同一窗口上方消息、下方复用输入；折叠不取消 |
| 阅读体验 | Markdown、代码块、复制、滚动位置保持；固定面板支持边读边操作其他应用 |
| 历史 | 默认恢复最近会话，简单会话列表、新对话、向上分页；重启后恢复已接受消息 |
| 可靠性 | 明确送达/运行/保存状态，重复请求去重，UI 重建和断连核对，不自动重跑未知轮次 |
| 数据归属 | harness 为唯一正文权威；agentd 仅保存会话绑定和必要请求元数据 |
| 安全 | 工具/代码/skill/管理命令执行关闭，UI 不持有模型或 Gateway 凭据 |

最低输入为纯文本；Markdown 是回复展示能力，不增加富文本输入编辑器。Unicode emoji 作为文本自然显示，不提供表情面板。输入框默认 Shift+Enter 换行、Enter/Ctrl+Enter 或按钮发送；IME 组合期间不发送。历史入口始终可访问，未发送新消息也能恢复旧聊天。

首版每节点一个聊天生成槽，与既有任务槽分离；生成中允许编辑，下一次发送等待当前轮次结束。无持久离线队列；未接受草稿仍遵守内存生命周期。主 Web 任务页面不在本功能中改造成持续聊天页面。

## 非目标与预留边界

| 后续能力 | 现在必须保留的边界 | 本次不实现 |
|---|---|---|
| Hermes / DeepSeek harness / Pi 等 | 独立会话适配器、能力声明、原生引用隐藏 | 新 adapter、登录安装、跨 runtime 无损迁移 |
| 工具和代码 session | Conversation / Turn / Task 分离、类型化内容、执行授权边界 | 工具调用、代码执行、审批、任务卡片 |
| 单机多节点 | 显式 node_id、实例化配置/路径/连接、输入 UI 与节点引擎解耦 | 多节点安装管理、发现、共享热键协调器 |
| 多角色 | 默认角色 ID/配置修订、角色与 runtime 映射独立 | 角色 CRUD、切换 UI、共享记忆和角色交接 |
| 跨机器聊天 | 统一会话客户端、可替换通信、目标权威、幂等/游标/核对语义 | 远程聊天端点、`@` 选择、远程审批、全网会话同步 |
| 多媒体 | 文本作为内容块，媒体以未来授权引用扩展 | 附件、录音、语音/视频、转码、模型多模态 |

全文搜索、编辑已发送消息、重新生成/分支、导出/导入、会话删除、移动端和自动恢复全部中断生成均后置。未来对旧会话的迁移或角色切换必须显式处理，不因默认配置变化自动迁移。

## 设计基线

详细语义只在[持续会话设计](../../../assistant/conversations.md)与 [Web 设计](../../../web/design.md)维护。关键约束：

- agentd 会话服务校验目标、身份、能力和请求，OpenClaw 负责模型循环及正文存储。
- OpenClaw Gateway 是首个适配器内部实现，不能成为公共 UI/通信接口。
- 运行时持久接收与网络确认分开；未知请求先核对，重试不换 ID/目标。
- 聊天目录保存稳定绑定，不保存整份正文；已接受消息可恢复，接收前草稿崩溃丢失边界明确。
- 首版独立 Gateway state 与任务 attempt state，按需启动并复用；只管理自己创建且身份可验证的进程。
- 关闭 UI 只解除展示，停止轮次和退出节点是显式独立操作；UI 故障不终止任务或模型生成。
- 角色、节点、会话和 runtime 身份分开，网络连接状态不改写远端运行事实。

## 实施前门槛

以下 G 项先做隔离验证，再进入正式实现。任何关键门槛失败，先更新设计并说明范围/代价，不通过扩大权限或假确认绕过。

| 门槛 | 要确认的问题 | 产出 / 进入下一步条件 |
|---|---|---|
| G1 会话和收据 | 锁定 OpenClaw 的创建幂等、发送持久接收、请求 ID 去重与重启查询是否满足契约 | 真实原生交互与故障窗口证据；稳定映射到公共 ID 和状态 |
| G2 历史 | 分页、单条完整读取、无 key/断网只读、压缩/reset/维护后的历史保留、升级格式行为 | 不复制完整正文也能满足历史与保留要求 |
| G3 安全 | 无工具可调用、无管理命令/skill 旁路、无任意插件发现/外部发送，认证与来源限制 | 检查有效配置和工具面并做拒绝测试；拒绝不能只依赖模型口头承诺 |
| G4 生命周期 | Windows 受管 Gateway 就绪、取消、退出、异常中断与原任务并存 | 真实进程树及数据独占证据；不占用个人 runtime home |
| G5 控件与预算 | 轻量自建展示或成熟 Web Component（如 Deep Chat）能否兼容现有编辑器、CSP、主题、分页/流式和键盘 | 定稿控件方案与依赖版本/许可/摘要；冻结启动/停止/查询/重连预算，实测成本 |

首选复用现有 WebView2 和原生 ES module；成熟组件只是候选，不因其默认能力自动开放直连模型、浏览器存储或文件上传。若组件需要放宽安全策略或整体换前端框架，重新评估轻量展示实现。上游资料和复现前提见[验证说明](validation.md)。

隔离验证后的实现决策：

| 门槛 | 决策及已确认的边界 |
|---|---|
| G1 | 固定会话 key、持久提交身份与原生消息 ID；同 ID 重复/冲突及重启后去重已验证。没有 `messageSeq` 的 started 响应继续核对收据。 |
| G2 | 采用原生分页和完整消息读取；正常上下文压缩保留正文。维护固定 warn，自动 reset 关闭；管理员截断不支持。reset 改变生命周期版本，旧绑定遇到此变化拒绝继续写入。只支持依赖清单锁定版本，版本不符拒绝接入；实际升级验收保留在 P5。 |
| G3 | 固定 deny-all、toolSearch 关闭、codeMode 关闭和命令拒绝策略；实际模型夹具请求无工具，`/reset` 被拒绝。加载模型 provider 和[可信提示词插件](../chat-prompt-interaction/plan.md)，关闭默认 memory 槽；产品连接无 admin scope。 |
| G4 | 使用独立 Gateway state 和用户环境；取消与崩溃恢复可核对，重启不自动重跑；复用已验证的 Windows Job 子进程回收机制。完整应用退出和任务并存回归在 P5。 |
| G5 | 采用现有 WebView2、原生 ES modules 和安全 DOM 展示，无新增前端依赖。真实 WebView2 原型验证原输入框/CSP/主题及 200 条长文本展示。有限等待预算已冻结于会话设计，成品性能和实体 IME 验收在 P4/P5。 |

这些结论确认接入可行性，不代替 [LC01—LC20](validation.md) 的完整产品验证。

## 实施步骤与完成条件

产品接入从 P1 开始。依赖顺序为 G1—G5 → P1 → P2 → P3 → P4 → P5；可独立验证的门槛不改变后续准入。

| 阶段 | 工作 | 完成条件 |
|---|---|---|
| P1 契约与目录 | 定稿会话/请求/轮次/事件模型、能力与错误；最小会话目录和恢复元数据；本机目标与默认角色 | 创建与绑定恢复、身份隔离、未知结果及 schema 兼容契约通过；无正文副本 |
| P2 运行时接入 | 会话 adapter、受管 Gateway、配置与只读历史、状态核对/取消、独立聊天准入 | 锁定 OpenClaw 真实多轮和重启历史通过；原任务接口保持 |
| P3 宿主与通信 | 有界桥/IPC、会话操作、订阅生命周期、快照与增量合并、隐藏背压 | 错宿主/旧代次/超限拒绝；UI 崩溃不取消轮次，未知写不重放 |
| P4 用户界面 | 自动展开、固定/折叠、单一输入框、状态、Markdown、历史、新对话、停止 | 实体 IME、键盘、复制、滚动、主题与窗口边界验收通过 |
| P5 交付验证 | 故障、性能、权限、升级/数据保留及既有任务回归；更新用户说明与支持状态 | [验收矩阵](validation.md)必测项有证据；实现/验证/用户验收分别记录 |

进入 P1 前把 G 项结论同步到本计划及所属领域设计，不将试验性 API 直接写入稳定公共协议。正式实现应为新增模块安排独立职责，避免把聊天控制器并入现有任务控制器。验收完成后才更新路线图“已实现”状态；提交和发布另行授权。

## 验收标准摘要

详细操作、故障注入和需求映射以[验证说明](validation.md)为准。

1. Ctrl+Alt+J 呼出，发送后自动展开；真实模型回答并支持上下文追问，任务服务保持可用。
2. 收起、失焦隐藏、固定显示、停止和节点退出分别符合契约；物理 IME 不误发。
3. 新对话有独立上下文；列表、最近页和更早历史可读取，重启恢复已接受消息。
4. 确认丢失、重复发送、取消竞争、UI/运行时/节点故障有明确状态，不重复运行或伪造保存。
5. 工具与管理旁路被拒绝；凭据不进 UI/历史/日志；恶意 Markdown 不产生脚本、网络请求或原生操作。
6. 大历史、长回复、慢消费者和隐藏窗口资源有界；沿用原 UI 门槛，新 Gateway 成本单独报告。
7. 既有文件任务、问答、配对、取消、设置、快捷键恢复、安装升级继续满足原契约。
8. fixture 证明目标/角色/runtime/传输隔离；不据此宣称新 harness、多节点产品或远程聊天已交付。

## 规模与拆分评估

实现以会话领域、运行时适配器、通信和展示职责组织新模块。现有 app、quickinput 和 executor 的接入点均未超过 1000 行；不拆分现有文件。新增内容继续按[代码风格](../../code-style.md)评估规模和职责，超限文件的安全拆分另行取得同意。

`chatPanel` 是一个面板的装配闭包，包含选择、发送、分页、轮询和可见性的短局部处理器；整体超过 100 行，各处理器独立且共享状态不外泄。客户端、消息窗口和 DOM 渲染已按依赖边界拆为模块，保留装配闭包比进一步暴露内部状态更易追踪。原生集成测试中的长测试函数按同一故障场景顺序组织，便于对照发送、回执、重启和恢复；辅助启动、等待及正文比较已独立。既有 settings 事务继续保持一次校验和一次提交边界，不在本功能中拆散事务。
