# 本机持续会话工具能力开发计划

## 基本信息

- 状态：首批实现、工程回归和独立审查已完成，用户验收通过。工程验证覆盖与后续专项验证范围见[验证方案](validation.md)；未设置过工具权限时默认开启，已有明确选择保持。
- 目标：让本机默认助手在持续聊天中完成文件发现、读写、整理、记忆和结果交付，逐步接近所选 harness 的原生工具能力。
- 关联：R03、R04、R23、R27、R28；AST-CHAT-01—08、EXEC-CHAT-01—03；AST-TOOLS-01—06、EXEC-TOOLS-01—06。
- 权威设计：[本机工具能力与运行时适配](../../../assistant/runtime-capabilities.md)。
- 相关领域：[助手需求](../../../assistant/requirements.md)、[助手设计](../../../assistant/design.md)、[执行器需求](../../../executors/requirements.md)、[执行器设计](../../../executors/design.md)、[自动化覆盖](../../../automation/coverage.md)。
- 决策：[跨 harness 工具能力与本机优先](../../../assistant/adr/010-local-runtime-capability-boundaries.md)；原生文件修改的适配验证见[实施门槛](preflight.md)。
- 调研依据：[调研记录](research.md)。验证要求：[验证方案](validation.md)。
- 后续能力批次各自确定范围。默认助手使用本批受限工作区工具，人工关闭后使用纯文本模式。

## 产品方向和批次

| 顺序 | 目标 | 边界 |
|---|---|---|
| 第一批：本计划 | 本机工作区文件、搜索、本地记忆、工具活动与产物、文件恢复 | 不执行脚本，不开放网络检索或远程聊天 |
| 后续本机能力批次 | 逐项接入网络、媒体、结构化问答、隔离执行、子 agent、后台任务及业务工具 | 优先复用官方能力；每类完成授权、依赖、事件、取消与资源验证 |
| 远程聊天 | 本机常用能力已基本完善后，评估节点间持续会话 | 不作为第一批或紧随第一批的默认里程碑；需另行设计目标端授权、补读和产物传输 |

“接近原生能力”指尽量保留有用的原生工作流；运行时管理、凭据及扩大权限仍由人工管理。Hermes、DeepSeek Harness 和自定义 harness 是适配目标，不在本计划安装或实现。

旧 route/execute job 路径暂保留兼容，不扩展、不删除、不迁移其历史。未来远程聊天就绪后另定退役方案。第一批不把聊天重新包装成旧 job。

## 第一批交付范围

| 能力 | 首个 OpenClaw 适配 | 验收 |
|---|---|---|
| 读取、创建、覆盖、精确修改 | 原生 read/write/edit | 工作区内成功，目录外读取和写入均失败 |
| 多文件补丁、移动、删除 | 原生 apply_patch | 逐项记录真实变化；部分失败不伪报全部成功；修改前可恢复 |
| 目录和文件发现 | 优先检查原生正式入口；缺失时注册一个 Asterhand 受限搜索工具 | 同时支持目录列举、文件名和内容搜索，不调用 shell |
| 持久记忆 | memory_search/memory_get + 原生文件写入，关键词模式 | 新会话能检索已保存记忆；无需新增 embedding 凭据 |
| 工作进度 | 原生 progress_card，经公共事件模型呈现 | 计划进度与工具事实分开，重开页面可回读 |
| 结果交付 | 工作区文件引用、元数据、预览与下载 | 按稳定引用读取，不接受任意宿主路径 |
| 文件恢复 | 节点侧版本记录与显式恢复 | 覆盖、移动、删除可恢复；冲突和中断可核对 |

第一批明确排除：exec/process/terminal、Code Mode、代码执行、注册命令启动、浏览器/桌面、网络检索、外发消息、跨会话发送/委派、cron/heartbeat、主动后台学习、插件安装更新、凭据工具、运行时管理、远程持续聊天及其他 harness 实装。允许生成脚本文本，禁止执行它。

## 实施前可行性门槛

先在独立测试目录验证 G1—G5。G3 的宿主文件竞争探针表明调用前快照/加锁不足；现用正式 `SandboxBackendHandle.createFsBridge` 接管受限 I/O、保留原生工具算法。正常修改、外部竞争、目录链接、取消、重启及关键词记忆已具备测试入口，可复现方法和支持边界见[实施门槛](preflight.md)与[验证方案](validation.md)。原生夹具不替代真实模型和用户验收。

1. G1 固定版本：以依赖清单的 OpenClaw/provider 2026.10.7 为调研基线，评估后续 workspace 修复；选定经过来源、摘要和许可校验的固定版本。升级必要时先完成兼容试验，不使用滚动 latest，也不自动改已安装节点。
2. G2 有效权限：捕获真实 Gateway 发给本地模型夹具的工具集合，实测文件边界、禁用工具、命令与会话权限覆盖；确认 workspaceOnly 在本入口可强制执行。
3. G3 文件修改监督：验证正式 hook/插件扩展能在每次原生修改开始前取得可校验操作范围、拒绝调用、完成前像快照，并在完成/失败/取消后核对结果。前像、修订检查与真实写入必须具有经实测的原子条件修改或排他访问保证，覆盖外部进程在步骤间原地写入、替换及抢先创建目标。范围含 write/edit/apply_patch、记忆写入、公共 mutate 和 restore；必须同时证明原生工具能正常完成，不能以阻塞所有写入算通过。仅有异步通知或 before hook 等待不足以通过；无法保证则对应写能力保持关闭。
4. G4 原生事件与历史：验证工具调用身份、开始/结果、progress_card、分页及重启后的可读取性；若原生持久事件不足，采用设计中限定的元数据日志，不复制完整会话正文。
5. G5 Memory 与 skills：确认关键词模式、索引范围、后台任务禁用及工作区内可写文件不会加载可执行插件；确定必要原生模板/skill 的受控读取方式。

门槛失败先保持工具关闭。可以使用同一原生工具实现加薄守卫/正式插件补齐；若必须 fork harness、重写文件工具、改变会话存储或引入系统 sandbox，记录证据并修订计划，重新确认范围，不用提示词代替执行约束。

## 实施步骤与完成标准

| 阶段 | 工作 | 退出条件 |
|---|---|---|
| P0 依赖与能力验证 | 执行 G1—G5，记录最终版本、接口和不可用原因 | 每项有通过证据或明确阻塞；无“文档存在即已支持” |
| P1 公共契约与工作区 | 工作区身份、绑定、权限修订、能力描述、修改租约；收窄 ConversationRuntime 选择中的厂商判断 | 异名 runtime fixture 可通过同一公共契约；不增加未来工具空接口 |
| P2 原生文件与记忆 | 生成明确工具白名单，接入路径与修改守卫、搜索、快照、关键词记忆 | 正常功能、越界、部分失败、容量与恢复用例通过 |
| P3 会话执行观察 | 调整零工具 prompt hook、事件投影、历史、终态、取消和配置切换 | 中间 assistant 消息不结束轮次，迟到取消不影响下一轮 |
| P4 产品与自动化 | 聊天工具活动、设置中的工具开关；文件/版本、读取/下载/恢复保留公共 CLI/MCP schema | 各入口同范围、同冲突与错误语义；权限变更人工限定；常用界面不展示低频维护表单 |
| P5 回归与验收 | 固定包原生夹具、Windows 路径实测、真实 DeepSeek、桌面交互、隔离安装升级 | 代码/文档/测试齐全；用户验收、提交与发布分别确认 |

P1 不重构所有 executor：在持续会话现有边界增加小的能力契约，旧任务接口保留。工具循环、模型选择及原生上下文仍归 harness。

## 文档与自动化同步

日常界面面向普通用户：移除独立“助手文件”入口及其目录、搜索、产物、版本/恢复表单；在“设置 → 助手”保留“允许助手调用工具”开关，点击即保存。开关不影响模型表单的未保存内容，关闭/重开时拒绝迟到响应，保存失败或响应丢失后核对真实权限。文件、日志、产物和恢复服务及 CLI/MCP 能力保持，聊天内必要的工具活动与进度保留。验证覆盖双语、设置保存隔离、忙时拒绝、未知保存结果和重开竞争。

未设置过工具权限时默认开启，包括缺失字段或没有权限修订的旧默认关闭配置；已有明确关闭保持。默认值由配置层统一补齐，界面仅显示有效值，原生白名单、提示词和文件服务读取同一策略。验证新增安装、旧配置、明确关闭、重启和其他设置保存，决策见[默认工具权限](../../../assistant/adr/011-default-assistant-tools.md)。

第一批同步助手、执行器、节点权限、Web/桌面、安装升级和测试领域的 requirements/design，以及本计划验证表。旧纯文本基线保留兼容回归；ADR 保存决策过程。

日常业务操作、公共名称和人机等价详见[覆盖清单](../../../automation/coverage.md#本机持续会话工具能力)。contracts/automation-coverage.json、注册定义、输入输出 schema、错误和行为测试已同步；权限表单仍为人工操作。

认证主体分两类：当前用户授权的外部 CLI/MCP 客户端，和内置助手的会话/轮次受限主体。不得将完整现有自动化凭据、commands.run 或通用 MCP 工具集传给内置助手。

## 规模与拆分评估

新增服务按 Windows I/O、路径、读与搜索、变更、日志与恢复、私有传输组织；原生插件、公共注册、工具权限设置和聊天活动均为独立模块。手写产品逻辑文件均未超过 1000 行。两个 i18n JSON 源词表属于集中维护的声明式翻译数据，继续保持现有双语键检查和生成流程；由它们生成的两个 catalog 模块属于生成代码。

原生集成测试中的长场景函数保留顺序明确的模型脚本、检查点和清理过程，避免拆散后隐藏重启/取消时序。生产函数按[代码风格](../../code-style.md)检查职责与大小；无需拆分已有超限产品文件。

## 验收与支持边界

验收矩阵详见[验证方案](validation.md)。第一批用户工作流程：

1. 在聊天中创建多个文本文件，列举、搜索、读取、修改、移动、删除，并查看真实结果。
2. 在第二个对话中检索第一段对话保存的记忆；重启后文件、记忆和已保存历史保留。
3. 通过公共 CLI/MCP 恢复一个误覆盖/误删文件，恢复前出现外部修改时拒绝静默覆盖。
4. 明确观察调用中的工具、失败和部分完成；停止后保留已产生的文件变化。
5. 越界读取/写入及脚本执行在实际执行处失败；模型回复不作为操作成功证据。
6. 原有纯文本、已授权外部 CLI/MCP、本地命令、旧文件任务与升级路径无新增回归。

文件服务、原生桥、关键词记忆、活动、产物、恢复、公共 CLI/MCP 和简化后的工具设置已交付并通过用户验收。P5 的工程回归及独立审查完成；用户验收不替代尚未执行的专项故障、完整升级和性能测量，后续按[验证方案](validation.md)继续补充证据，不将全部 LT 场景记为通过。正式插件和窄文件服务属于文件约束，不提供通用进程隔离。
