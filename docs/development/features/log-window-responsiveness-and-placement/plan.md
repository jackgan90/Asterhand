# 日志窗口快速显示、复用和同屏定位

## 目标与范围

- 状态：已完成。实现、工程验证、独立审计修复复审及本机日志窗口响应与双屏同屏定位的用户验收通过；其他显示布局和平台的验证边界见[验证说明](validation.md)。
- 关联：EXEC-CMD-08、EXEC-CMD-12、EXEC-CMD-15、EXEC-CMD-16、WEB-CMD-11、WEB-CMD-14、WEB-CMD-15。
- 权威契约：[托管命令设计](../../../executors/managed-local-commands.md)、[执行器需求](../../../executors/requirements.md)、[Web 设计](../../../web/design.md)、[安装设计](../../../installation/design.md)。
- 决策：[日志窗口复用与异步初始化](../../../executors/adr/004-log-window-reuse-and-initialization.md)。

查看日志应先显示独立窗口；WebView2 创建、模块加载和页面握手在可见窗口内完成。窗口关闭改为隐藏并暂停页面刷新，再次打开复用已有窗口。首次加载失败保留本地化错误提示；下次显式打开重建相应窗口，不改变命令执行。

快捷输入在点击时从自己的原生窗口采集所在屏幕的物理坐标，通过受限 IPC 传递定位提示。日志窗口每次显式打开优先进入该屏幕工作区，适应负坐标、任务栏和不同 DPI。公共协议不接受网页指定的 HWND 或显示器句柄。

不改变脚本启动、停止、日志存储、执行身份和跨节点能力；不增加自动脚本重试，不要求模型配置。Windows 为本次真实验证平台。

## 设计与交付

1. 将原生窗口显示回执与页面就绪分离；创建与清理不阻塞日志宿主的消息循环。
2. 按命令 ID 缓存窗口；保留最多四个隐藏窗口，实际创建及清理中的窗口总数最多十六个。达到上限时回收隐藏窗口或明确返回繁忙。
3. 初始化超时和渲染失败直接进入可见错误状态；旧窗口在后台有界清理。重建使用独立 UI profile，迟到事件只作用于原窗口。
4. 打开请求超时后淘汰不可用连接，后台停止宿主；节点退出等待所有已退休宿主清理，不牵连命令执行。
5. 对定位提示和诊断事件进行方向、动作和数值边界校验。诊断只记录阶段、耗时及错误键，不记录脚本参数、日志正文或凭据。
6. 管理列表和快捷列表的打开错误保留到下一次主动操作，不被自动刷新立即清除。
7. 创建前已接纳的 UI 更新在 HWND 发布后可靠唤醒；同屏最小化恢复保留正常矩形。退休窗口确认释放后回收独占 profile，释放未确认时保留目录、淘汰日志宿主，错误最终传播至应用关闭结果。

同步更新执行器/Web 需求、托管命令设计、安装设计、领域 ADR、导航、路线图和[验证说明](validation.md)。历史生命周期 ADR 的窗口释放约定由新 ADR 替代，执行与日志权威保持原契约。

## 验收与验证

- 首次冷开在页面握手前显示窗口和加载提示；失败显示可重试说明，慢清理不阻塞其他窗口或日志/停止消息。
- 关闭重开复用同一窗口，不重复创建 WebView2；隐藏期间不持续轮询；渲染失败后可重建。
- 打开回执确认实际原生显示；请求超时和旧代次回执不会污染新窗口或连接。
- 双屏下从屏幕 A 的输入框打开日志位于 A；输入框移至 B 后再次打开同一日志移至 B。覆盖负坐标、缩放、最小化和工作区约束。
- 运行中的托管脚本不受窗口隐藏、重建或宿主终止影响。
- 运行相关 Go、前端、国际化守卫和文档链接检查，并进行独立测试宿主的真实 Windows 验证；用户安装后验收单列。

## 规模与职责

原生日志窗口、生命周期管理、定位和加载占位分别放入职责明确的文件。现有共享 WebView2 底层只增加构造与日志专用分支，不扩展聊天生命周期。目标为单文件低于 1000 行、函数低于 100 行；验证时核对新增代码规模。
