# 保留原生 Harness 设定的提示词适配

状态：实现与工程验证完成。全量 Go 测试、vet、前端回归和锁定 OpenClaw 原生请求验证通过；日常聊天已通过[用户验收](../local-node-chat/validation.md#用户验收状态)；原生角色内容保留由实际请求测试确认，模型人格表达及其余专项继续独立记录。

## 范围

对应 AST-PROMPT-01、EXEC-PROMPT-01。提示词管理遵循原生优先：保留 harness 的身份、人格、语气、工作习惯和原生上下文组装，仅纠正与当前入口已实现能力冲突的工具、管理入口、持久化和展示约定。适用于当前 OpenClaw 与后续适配器。

权威契约见[会话设计](../../../assistant/conversations.md)、[助手需求](../../../assistant/requirements.md)、[执行器设计](../../../executors/design.md)和[原生优先 ADR](../../../assistant/adr/007-preserve-native-harness-prompts.md)。

## 设计

- OpenClaw 默认从 replace 改为 appendSystemContext；不复制、解析或整段重写上游系统提示词。产品文本移除强制身份与语气，只保留有范围的能力和入口差异。
- 恢复隔离聊天工作区的原生 bootstrap 文件初始化。OpenClaw 生成缺失的 SOUL.md、IDENTITY.md 等文件，原有定制内容保留；不读取个人 OpenClaw home 或工程仓库的角色文件，不共享其他节点的角色或记忆。
- 工具清单与定义由最终运行时策略提供；继续零工具、关闭命令/默认 memory 执行和外部渠道。原生行为中需要未开放能力的部分，以实际配置为准；保留已加载文本不宣称可写回文件或拥有自动记忆。
- 配置事实与模板形成 v2 修订；append 是正常支持方式，已确认时不告警；不支持、缺少观察或失败仍非阻断降级。replace 保留为协议兼容能力，不作为默认策略。
- 已有会话下一轮使用新规则，不改历史或绑定。上游文件初始化遵循原生缺失补齐与已有文件保留语义。

## 验证

1. 提示词组装测试验证无强制身份/语气，有冲突范围和当前能力事实；配置测试验证 append、原生初始化与零工具约束。
2. 插件测试验证 append 不返回 systemPrompt，成功/失败/观察丢失状态准确，原有兼容模式继续可识别。
3. 锁定 OpenClaw + 本地模型夹具捕获实际出站系统提示词：原生核心、默认 SOUL、自定义 IDENTITY/SOUL 和补充规则同时存在，工具列表为空；两轮上下文、重启与既有角色文件保持。
4. 验证策略失效与 unsupported 仍有原生设定且继续聊天。运行相关 Go/Node 回归、vet、文档链接和规模检查。

## 非目标与边界

不开放聊天工具、不引入角色编辑 UI、记忆写入、个人配置迁移、跨节点同步或新 harness。自动化测试不修改已安装节点；日常聊天用户验收与安装升级专项分别记录。真实模型行为与原生出站请求验证分开报告。

复现步骤与测试入口见[验证说明](validation.md)。原生两轮与模式测试的场景函数超过 100 行，保留准备、模型请求断言、修改角色文件和重启检查的因果顺序；产品代码仍由小函数承担配置/文本/观察职责，所有修改文件低于 1000 行。
