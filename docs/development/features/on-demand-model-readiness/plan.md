# 按需模型配置与可选诊断

## 目标与范围

让节点启动、Web、托盘和快捷输入不依赖模型验证。模型凭据按需配置，聊天与自然语言任务使用真实请求检查在线可用性，不额外插入探测请求。源码更新只使诊断证据过期，不阻止正常使用。

关联 R03、R04、R11、C04、AST-04/09、WEB-01/09/10 及新增 AST-CHAT/任务准入要求。权威文档：[助手需求](../../../assistant/requirements.md)、[助手设计](../../../assistant/design.md)、[会话设计](../../../assistant/conversations.md)、[执行器设计](../../../executors/design.md)、[节点设计](../../../node/design.md)、[任务设计](../../../tasks/design.md)、[Web 设计](../../../web/design.md)、[安装指南](../../../installation/quickstart.md)。

状态：实现、工程验证和独立审计修复完成；取消恢复、持久拒绝、损坏响应分类和真实依赖包准入问题均已复审关闭。本机聊天使用验收通过，实体双机、全新节点和其他专项边界见[验证说明](validation.md)。

本次包含：

- 分开节点运行状态、按功能配置可用性与手动诊断结果。
- 取消本机及远端自然语言任务对 `ModelVerified` 的强制依赖。
- 无 key 可启动、配置基础节点、查看任务；使用模型功能时提示所缺配置。
- 保留显式模型工具诊断、诊断失效规则及发布验证入口。
- 更新前后端准入、设置说明、托盘、兼容处理及对应测试。

非目标：实现快捷脚本、增加执行器或 provider、改变工具权限、预热模型、自动后台 probe、跨节点聊天、自动重放副作用、修改依赖版本、优化实际模型响应延迟。未来脚本按自己的执行能力准入，本次不增加虚构的脚本能力。

## 当前问题与设计依据

`ModelVerified` 同时被用作诊断记录和任务/节点就绪标志。成功记录绑定源码、依赖和有效执行配置摘要，普通源码更新后会失效；Web 初始化根据 `info.ready` 自动打开设置，任务入口又强制要求该标志。持续聊天已经独立于文件工具 probe。

保留现有 probe 的端到端诊断价值：独立 OpenClaw 调用模型、请求无副作用工具并验证回调。运行时适配器与工具执行处继续承担实际权限、凭据、路径和结果校验。

## 功能与接口设计

### 1. 节点运行与按功能配置

- 启动仅做既有本地配置、身份、数据存储和监听检查；不新增模型请求或 OpenClaw 子进程。
- `/api/info` 和 `/v1/info` 增加 `capabilities.chat`、`capabilities.model_tasks`，分别携带 `available`、稳定 `code` 和安全的 `detail`。这里的 available 只表示本地必要配置齐全，不承诺外部 API 在线。
- 模型任务的公共检查由 executor 层拥有，统一检查所选 provider/runtime、可读取的非空凭据、宿主/运行时入口/provider/工具插件的本地安装条件。状态查询和准入检查不调用模型、不启动运行时，不递归校验整个依赖树。按功能区分聊天对任务工具插件和授权目录的非依赖。
- 节点身份与在线状态独立于能力。授权项目单独返回，执行请求必须检查具体项目；A 路由到 B 不要求 A 自己配置文件授权目录。
- 初次启动和重启均直接进入 Web 主页面，缺少模型配置在相关功能处提示；用户仍可随时打开设置。托盘显示“节点运行中”或“正在退出”。

### 2. 使用时准入与执行

- 聊天保留按需启动受管 Gateway 的生命周期；配置齐全后直接发送真实消息，无预先 LLM 测试。无凭据的历史只读路径继续有效。
- 本机 `route` 和目标节点 `execute` 统一走任务引擎的新请求准入。接收事务内依次处理已有任务或拒绝结果/摘要、取消墓碑、新请求准入：已接收的重复请求返回原任务；取消先到、尚无接收或拒绝结果的迟到请求保存 `cancelled` 记录，不要求模型配置，不创建 attempt。
- 仅全新且未取消的请求检查本地模型任务配置和本次操作的项目。缺少配置时保存独立拒绝 receipt，绑定 origin/request ID/完整摘要，提交成功后才明确拒绝；不伪造 job、attempt 或 probe 成功。存储失败仍是未知结果。执行前发生环境变化时由实际执行器报错并保存到已接收任务；不自动重启任务。
- Store 决定是否需要调用新请求检查，任务引擎拥有准入策略；检查回调只做有界本地读取，不调用网络、子进程、Store 或重新取得 App/Engine 锁。所有产品接收入口（包括本机 outbox）与设置保存共享 App 配置互斥，保持 App → Engine → Store → Config 的锁顺序。
- 保持配置修改与新请求接收的同步边界，防止准入与凭据修改交错。停止后的新接收屏障继续有效。
- 模型鉴权/额度/网络错误通过原聊天或任务错误路径返回。成功真实请求不伪造独立工具诊断通过。

### 3. 远端投递与兼容

- TLS、peer 身份和项目授权仍在任务准入前校验。节点配对和任务记录读取不要求模型配置。
- 对本次新增的“明确未接收，缺少功能配置”使用稳定错误码及结构化响应，绑定请求 ID 和完整请求摘要。发送方只在提交阶段收到与本次请求匹配的明确响应后，把未交付 outbox 标为 rejected 并显示原因，停止自动投递；修复配置后由用户重新提交。取消或查询端点的同类错误不证明提交未接收。
- 拒绝结果为持久终局：恢复配置、重启或迟到请求均返回原拒绝，同 ID 不同摘要冲突。schema 1 数据在打开时升到 schema 2，已有任务/事件形状保持；旧二进制拒绝打开 schema 2，防止忽略拒绝记录后再次执行。Web 校验归一化后的 route 摘要，只对匹配的明确拒绝释放原 pending ID、保留草稿，下一次用户提交生成新 ID。
- 网络超时、响应损坏、未知服务端错误继续视为 delivery_unknown，只用原请求 ID 向原目标对账；不能按普通 HTTP 状态或错误文本猜测未接收。已接收任务的查询失败不变成 rejected。
- 保留 `ready` 兼容字段的原有“手动诊断通过”含义，新增客户端优先读取能力字段；旧节点缺少能力字段时按原 ready 门槛提示在旧节点验证或升级。旧客户端仍遵循旧门槛，不把新配置状态冒充旧验证通过。
- 不改变已有任务/会话数据格式和请求摘要；新错误字段应被旧客户端安全忽略，旧发送方仍按原目标/ID 重试并得到相同拒绝。数据库版本保护属于拒绝恢复契约，升级后的任务库不支持用旧二进制原地回退。

### 4. 可选诊断与设置

- “验证模型与工具”改为“测试模型与工具（可选）”，说明会产生真实模型请求；保存设置不触发测试，也不要求测试后才能使用。
- `ModelVerified`、`VerifiedBundle`、`VerifiedExecution` 保留为兼容诊断证据，继续绑定当前源码/依赖/执行配置。失效时只影响诊断展示和旧兼容字段。
- 区分未测试、执行中、通过、失败、过期；凭据或执行配置变化不能把旧成功展示为当前成功。沿用正在执行诊断时的配置保护与退出取消。
- 基础配置不要求 key 或授权目录。删除 key 只禁用需要模型的新操作；设置页和非模型入口继续工作。
- 保留安装与发布工具的显式真实 probe，不把工程验收变成可跳过的虚假通过。

## 验收条件

| 用例 | 预期结果与验证方式 |
|---|---|
| 全新节点无 key、无授权目录 | 正常启动并读取健康/节点/设置/任务；Web 不自动弹模型配置，不执行 probe 或模型请求 |
| 有效本地配置、从未 probe | 允许直接聊天及本机/远端自然语言任务；用受控执行器断言不存在 probe 调用 |
| 仅源码或依赖证据变化 | 诊断过期，功能配置不受旧成功标记控制；实际不兼容依赖仍由本地检查/运行时校验报告 |
| 无 key、密钥不可读取、运行时路径缺失 | 功能状态给出具体原因，新请求明确拒绝且无新 job/attempt/模型调用 |
| A 无授权目录，B 有授权目录 | A 能路由到 B；B 的具体目录授权在目标执行处校验 |
| B 缺配置且收到新任务 | 结构化明确拒绝，A 展示原因并停止该 outbox 的自动投递 |
| B 已接收、响应丢失后配置变化 | 原请求返回原任务；相同 ID 不同摘要冲突；无第二次执行 |
| 取消先到，随后配置缺失且提交迟到 | 返回持久 cancelled 记录，重复请求返回同一记录，无模型调用或 attempt |
| 真正的投递未知 | 保留原目标/ID 对账，不自动生成新请求或换节点 |
| 旧调用超时、重试拒绝、恢复配置、旧调用迟到 | 同 ID 保持原拒绝，无 job/attempt/文件副作用；重启与存储故障边界同样覆盖 |
| Web 明确拒绝后重新提交 | 草稿保留，仅匹配 ID/摘要/错误码的拒绝释放 pending；未知错误保持原 ID |
| schema 1 升级和旧程序回退 | 任务与事件保持，库版本升为 2，旧程序拒绝打开；较新未知 schema 不被写入 |
| 模型返回鉴权/网络失败 | 用户实际请求有明确失败结果，不污染基础节点状态，不自动重放 |
| 名称/网络/模型/key/目录修改 | 名称与网络保持诊断；有效执行变化撤销当前成功，功能按新配置判断 |
| 旧节点兼容 | 新 UI 对缺少能力字段的旧节点使用旧 ready 规则；不误宣称无验证可执行 |
| 手动诊断、停止、配置竞争 | 诊断结果准确、退出可取消，检查中修改配置按原规则拒绝 |
| 历史与权限回归 | 无 key 仍可读历史；认证、目录保护、撤销、取消、重启对账保持 |

## 验证与规模

工程检查入口：`go test ./...`、`go vet ./...`、`go build ./cmd/asterhand`；Node 使用 [测试指南](../../../../tests/README.md)中的所有 `*.test.mjs`。新增测试应覆盖真实入口行为、失败与幂等边界，不镜像实现。

使用 Windows、清单固定 Go 1.27.3 与本地 Node；测试在隔离目录内进行，使用合成凭据及受控模型/执行器。生产安装和真实密钥保持不变。可用时用锁定 OpenClaw 加受控本地模型验证无额外探测请求，真实在线模型和实体双机验收单列未验证范围。

主要改动文件在 app/executor/tasks/store/peer、Web 和 desktop 中按既有职责局部修改；新增能力判断和准入测试使用独立职责文件。修改前后检查物理行数，新增内容使文件超过 1000 行时先评估，安全拆分须获得用户同意。原有长函数仅在本功能所需范围调整并记录理由。

本次修改文件均未超过 1000 行。现有 `cmd/asterhand/main.go` 的 `run` 为 107 行，承担顺序化 CLI 分派，本次更新启动提示和诊断失效调用；拆分会扩大无关命令范围，保持原结构。`internal/app/api.go` 的 `settings` 为 142 行，配置校验、忙碌判断、凭据修改和保存共同构成一个互斥事务；本次仅接入诊断失效和能力响应，分散事务步骤会增加锁/快照推理成本，保持集中。新增功能与测试放在各自职责文件，不引入超限文件拆分。

`internal/executor/conversation_integration_test.go` 中既有 `TestNativeConversationBridge` 为 139 行，本次保持原函数不变：该测试按同一 Gateway 生命周期依次验证创建、发送、恢复、历史和停止；拆成独立测试会重复启动并丢失跨阶段状态检查。本次仅在同文件的只读适配器用例加入独立的真实配置检查 helper，以合成 key 覆盖固定包元数据准入。

工程验证包含全量 Go 测试、vet、三个 Windows 可执行目标构建、全部 Node 测试、文档链接和规模检查；锁定 OpenClaw 的受控模型发送与无凭据历史测试通过。原生测试使用本地受控模型，实体双机、真实在线模型、实际安装升级及物理桌面验收仍按验证说明执行。

长期文档保存行为、可复现方法与支持边界；运行日志、审计报告和机器路径只放构建产物下的独立审计目录。功能交付后同步 [路线图](../../roadmap.md) 和 [文档导航](../../../README.md)。
