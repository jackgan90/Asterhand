# 项目结构与文档治理

## 目标与范围

关联 C01、C07、C08、DEV-01—DEV-11。项目按产品领域组织需求、当前设计和 ADR，维护者无需原始开发对话即可理解功能及决策。

领域入口见 [文档导航](../../../README.md)，原始需求和场景见 [需求迁移对照](../../../overview/migration.md)。

## 维护契约

- requirements 描述有效需求，design 描述当前职责与行为，ADR 记录重要决策及替代关系。
- 每个功能在语义明确的目录中维护 plan.md，连接需求、领域设计、验收方法与规模评估。
- 仓库文档只引用受版本控制的目标；临时执行记录与个人运行数据留在忽略目录。
- 新增功能同时更新代码、测试、领域文档和使用说明，避免只在计划中勾选完成。

## 验证方法

检查 Markdown 本地链接及目标是否进入版本控制；核对需求编号在 [全局需求](../../../overview/requirements.md) 和各领域文档中的定义。维护规则见 [开发流程](../../workflow.md) 与 [代码风格](../../code-style.md)。

本功能只涉及目录和文档职责，不要求产品代码拆分。
