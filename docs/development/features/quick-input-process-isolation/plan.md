# 快捷输入进程隔离重构计划

## 基本信息

- 状态：源码、打包契约、领域文档和独立审计已完成，2026-10-26 本机用户验收通过。隐藏 CPU 预算仍为 failed，其余权限与桌面环境的验证边界见[验证说明](validation.md)。
- 目标：让普通用户和管理员运行的 Windows 节点均能使用快捷输入，同时让 WebView2 宿主保持非提权权限；宿主故障不丢失主进程已接收的草稿。
- 关联需求：全局 C02、C04、C07、C08、C09、R02、R28；安装 INST-27；Web WEB-11、WEB-12；现有快捷输入 QIN-01—12。
- 领域入口：[全局设计](../../../overview/design.md)、[安装需求](../../../installation/requirements.md)、[安装设计](../../../installation/design.md)、[Web 需求](../../../web/requirements.md)、[Web 设计](../../../web/design.md)。
- 现有基线：[快捷输入计划](../global-hotkey-quick-input/plan.md)、[快捷输入验证](../global-hotkey-quick-input/validation.md)、[ADR 006](../../../installation/adr/006-global-hotkey-input-surface.md)。
- 架构决策：[ADR 007](../../../installation/adr/007-quick-input-process-isolation.md)替代 ADR 006 中的进程内宿主与权限处理决策，保留其他仍有效的交互和隐私约束。

## 背景与重构原因

### 当前结构为什么出现权限问题

重构前，`quickinput.Controller`、原生 `Draft`、快捷键管理和 WebView2 宿主都在节点主进程内。独立 STA 线程隔离了消息循环，却共享主进程的权限和故障范围。主进程以管理员权限运行时，快捷输入的交互桌面检查会拒绝创建面板；控制器先准备面板再注册快捷键，因此默认 Ctrl+Alt+J 也不会生效。

对于关闭 UAC、默认使用管理员令牌的环境，要求重新以普通权限启动节点并非可用的产品方案。Runtime 或 VC++ 安装时的提权与节点运行时的权限是两件事；修复应针对实际进程令牌，不根据安装器是否弹出窗口推断权限来源。

重构前托盘菜单直接展示配置中的期望快捷键，即使面板创建失败、实际未注册，也会显示“快捷输入 · Ctrl+Alt+J”。重构需要同时修正这个状态表达，避免把配置值显示成当前可用能力。

### 为什么分离 WebView2

微软建议 WebView2 宿主运行在非提权用户权限，需要高权限的工作放到独立进程。这遵循最小权限原则：网页内容、脚本桥或浏览器组件发生缺陷时，应减少其可使用的原生权限。[微软 WebView2 安全文档](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/security#recommended-privilege-level-for-webview2-host-applications)

本项目据此保留节点既有运行权限，将浏览器宿主移入独立非提权进程。这样既适配管理员环境，也获得清晰的故障恢复边界。仅删除管理员检查、降低线程权限或在同一进程内更换 STA 均不能建立所需的进程边界。

“受限宿主”在 Windows 上指经过检查的非提权 **Medium Integrity** 进程，不要求 WebView2 宿主本身采用 Low Integrity。WebView2 自身的沙箱继续启用。受限令牌也不是文件系统全面隔离：同一用户本来可访问的资源仍需按其 ACL 判断，不能把此方案描述成能够抵御同用户任意恶意程序的完整沙箱。

### 为什么草稿继续留在主进程

现有产品的原生 `Draft` 由主进程控制器持有。可行性原型为复用现有代码，把控制器一起放进了 UI 进程；强制结束 UI 后，旧草稿随该进程消失。这说明正式重构必须只迁移显示职责，保留主进程的草稿所有权。

主进程保存已接受的最新完整文本和版本；WebView2 页面及 UI 宿主保留编辑所需的临时副本。宿主重建后从主进程初始化。草稿仍只存内存，主进程退出即结束其生命周期，不新增文件、数据库、Web Storage 或日志中的草稿备份。

## 前置验证结论与边界

以下结论来自独立原型和故障注入，用于选择架构；正式产品仍须按本文验收矩阵重新验证。

| 验证组 | 已获得的结论 | 对正式实现的要求 |
|---|---|---|
| 第一组：受限宿主初始化 | 在关闭 UAC 的管理员环境，采用受限令牌、Medium IL、明确的令牌默认 DACL 和 GUI 子系统程序，可完成 WebView2 初始化、加载和退出；最小宿主与产品代码路径均有成功样本 | 将令牌创建、默认 DACL、启动身份复核写入 Windows 启动器；不复制原型中的临时覆盖文件作为产品实现 |
| 第二组：输入与窗口行为 | 受限窗口可获得焦点、进行中文 IME 和英文输入；最小宿主完成实体键盘确认，产品编辑器路径完成桌面自动化输入、候选确认、收起和恢复 | 正式包仍须使用原始工具窗口样式完成实体键盘、IME、失焦和 Escape 验收 |
| 第三组：快捷键与进程协作 | 管理员进程注册真实全局快捷键，向确切 UI PID 授予前台权限，通过匿名管道通知受限宿主；独立高权限和 Medium 前台程序均可切入输入并恢复焦点；强制结束 UI 后可重建 | 主进程承接快捷键与生命周期；扩展原型的最小 IPC；增加主进程草稿同步与恢复，不能照搬原型的 UI 内草稿 |

必须保留的验证边界：

- 早期出现过 WebView2 `0x80000003` 异常提示，后续测试未复现，根因尚未定位。不能宣称某项令牌或 DACL 调整已经修复该异常。
- 初始化存在秒级延迟，最小宿主也出现过。创建和恢复必须异步，不能阻塞托盘消息循环、任务服务或设置请求。
- 第二、三组部分窗口为了自动化改为可见任务栏窗口，原始工具窗口样式的完整链路仍待验证。
- 第三组重建由主动结束 UI 触发，证明故障隔离和恢复路径；它没有验证正式产品的草稿恢复，也不构成长期稳定性或完整安全审计。
- 独立普通用户机器、其他 UAC 配置、macOS、Linux 尚未完成对应原生验证。现有隐藏 CPU 预算失败项继续保留。

## 范围与非目标

本次计划覆盖 Windows 独立 UI 宿主、权限启动策略、受控 IPC、主进程草稿、焦点与生命周期、真实状态展示、构建安装和回归验证。普通用户与管理员环境使用同一套进程架构，权限启动策略由 Windows 适配层选择。

本次不实现 macOS/Linux 原生快捷输入，不调整系统 UAC、桌面 ACL 或全局前台策略，不主动提升普通用户节点权限，不增加任务执行入口、远端草稿同步或草稿持久化，也不重构已有任务服务的权限体系。

### 职责与源码落点

| 组件 | 职责 | 计划落点 |
|---|---|---|
| 主进程控制器 | 期望与实际配置、注册事务、录制租约、原生草稿、状态与重试决策 | 保留 `internal/quickinput/controller.go`、`draft.go` 和现有设置接口 |
| 远程 Surface 与宿主管理 | 将现有 Surface 操作转为 IPC，负责异步准备、代次、超时、退出检测与有界恢复 | `internal/quickinput` 新增按职责划分的文件；不将进程启动逻辑堆进 Controller |
| IPC 契约 | 定型消息、版本、长度边界、序号与错误码，不依赖 Win32 或 WebView2 | 独立内部协议包，主进程与 UI 共用 |
| Windows 平台适配 | 检查令牌、创建进程、句柄白名单、前台授权、所属进程树清理 | Windows build tags 下的宿主启动与激活实现 |
| UI 宿主 | 原生窗口、STA、WebView2、受限页面桥、临时编辑状态和快照应答 | 新入口 `cmd/asterhand-input-host`，打包为 `AsterhandInputHost.exe`；现有 surface 文件按职责迁移 |
| 页面 | 本地编辑、IME、选择区与撤销、发送文本更新 | 复用 `internal/quickinput/assets`，调整桥协议 |
| 托盘与 Web 设置 | 展示已注册、初始化、恢复、不可用等真实状态 | `internal/desktop/tray_menu_windows.go` 和现有桌面设置页面 |

采用独立 GUI 可执行文件，避免子进程误进入节点、HTTP 服务、数据库或执行器初始化流程。宿主不接收节点凭据、模型配置或执行器能力；无合法父进程通信通道时直接启动应失败。UI 宿主只能加载内置编辑页面，保留导航、下载、权限请求和原生对象暴露的限制。

### Windows 启动与权限策略

1. 普通非提权交互用户：以当前用户的非提权身份启动独立宿主，复核身份与完整性级别，不要求管理员权限。
2. 提权管理员，包括 UAC 关闭：使用已验证的受限令牌方案；禁用管理员组授权能力与多余特权，设置 Medium IL，并为新对象指定当前用户和 SYSTEM 所需的默认 DACL。创建后复核有效令牌，检查失败则终止该宿主。
3. SYSTEM、非交互会话或不能建立符合要求的宿主：快捷输入明确降级，节点其他功能继续；不回退到提权 WebView2。
4. 只从当前节点版本目录解析配套宿主，不通过 PATH、当前工作目录或页面消息选择程序。校验包完整性、应用版本、协议版本和启动会话；升级切换时不得混用新旧宿主。
5. 显式限制环境变量和可继承句柄，避免将节点秘密或调试覆盖参数传给 UI。核查 WebView2 有效配置，不使用关闭沙箱的参数。
6. UI profile 沿用本机独立用途和不存草稿的约束；对用户目录、缓存目录和版本目录的访问权限做实际验证。不放宽整个安装目录、用户目录或桌面的 ACL 来绕过失败。

平台启动器须控制子进程完整生命周期。Windows 优先采用创建时纳入自有 Job 的方式，实现主进程异常退出后的清理；与 WebView2 自身 Job、浏览器子进程和受限令牌的兼容性列为实现门槛。清理仅针对本次启动拥有的进程树，不按 `msedgewebview2.exe` 名称结束系统其他实例。

### IPC 与权限边界

- 沿用两条匿名管道，显式继承必要端点，UI 启动后先清除端点继承标记，再创建 WebView2。管道归属绑定主进程实际创建的进程句柄与会话；不信任消息自报 PID。
- 主进程发送初始化、显示/隐藏、主题、快照请求、草稿确认与关闭；子进程发送就绪、窗口状态、草稿更新、快照结果和定型错误。协议不提供执行命令、任意文件、任意 URL 或通用原生 API 代理。
- 页面消息、UI 宿主消息在各自边界独立验证。协议包含版本、宿主代次、请求 ID；窗口句柄如需跨边界使用，须由 Windows 适配层验证属于当前宿主。
- 帧在分配内存和反序列化之前检查长度。草稿仍限定 16,000 UTF-8 字节；IPC 帧上限为 128 KiB，以容纳 JSON 转义后的文本与固定字段。原型的 8 KiB 状态上限不能直接用于正式草稿消息。
- 队列有界，草稿更新允许合并为最新完整文本；控制应答和退出消息不得被输入洪峰饿死。未知消息、错误版本、过期代次、重复冲突请求与超长帧均有明确拒绝行为。
- 日志记录错误码、耗时、代次和大小，不记录草稿、剪贴板内容、原始 IPC 帧或凭据。

### 主进程草稿与一致性

1. 主进程是唯一权威来源，保存文本、草稿 epoch 和 revision；UI 保存编辑副本及当前宿主代次内的编辑序号。revision 由主进程推进，epoch 用于隔离清空等失效操作。
2. 页面提交已完成的编辑，经宿主转发给主进程。主进程校验 Unicode、LF、字节上限和会话/序号，更新内存后返回确认。输入法尚未确认的组合文本不作为已提交草稿。
3. 同时最多保留一个待确认更新和一个合并后的最新文本。重发同序号同内容应幂等；同序号不同内容拒绝。主题和普通状态更新不得用较旧文本覆盖编辑副本。
4. 重建宿主时，用主进程当前草稿初始化新代次，初始化确认前不开启编辑。旧宿主、旧页面或清空前 epoch 的迟到消息不能覆盖新状态。
5. 主动禁用或需要销毁 UI 的配置操作，继续使用快照屏障：等待页面完成可提交文本的快照，再等待主进程接收确认。无法确认且原宿主仍在时，保留编辑器并报告操作失败；不能为完成配置更新而静默丢弃文本。
6. 宿主意外退出时恢复主进程最后已接受的草稿。崩溃前尚未到达主进程的输入、未确认的 IME 组合可能丢失，恢复提示应准确表达这个边界。ACK 丢失但主进程已接受的文本仍可恢复。
7. 收起、主题切换、暂时禁用和 UI 重建不清空主进程草稿。显式清空推进 epoch；主进程退出释放草稿，不承诺跨节点重启或断电恢复。

### 激活、恢复与状态

全局快捷键仍由主进程桌面消息线程注册。收到真实快捷键或显式托盘操作后，Windows 适配层向当前 UI PID 授予前台激活权限，再发出显示命令；窗口切换与焦点确认异步完成。保持 Escape、同键收起、失焦收起、IME 候选和焦点恢复语义，不使用模拟按键或修改系统前台限制来强抢焦点。

冷启动和故障重建期间，记录一次有时效的激活意图。UI 就绪时复核原前台窗口和后续用户活动；意图已过期或用户已转去其他工作时，只完成隐藏预热，不突然弹出抢焦点。无后续用户活动的冷恢复路径须验证能够正常激活。Windows 的 HWND、PID 和活动计数保留在适配层，不进入跨平台业务协议。

| 状态 | 快捷键与行为 | 托盘/设置显示 |
|---|---|---|
| disabled / unsupported | 不注册，不创建 UI；禁用时保留主进程草稿 | 已禁用或当前平台不支持 |
| starting | 异步准备宿主，首次就绪前不宣称可用 | 正在初始化 |
| ready | UI 可用且实际注册成功，才给出有效快捷键 | 快捷输入及实际生效组合 |
| recovering | 已工作过的 UI 故障，短期保留注册以接收恢复意图；只允许一个恢复实例 | 正在恢复，不能伪装成 ready |
| unavailable / conflict | 恢复失败或冲突时释放无效注册，保留配置与草稿 | 具体原因及重试/设置入口 |

恢复策略为一次故障突发只自动重建一次，新宿主连续稳定就绪 60 秒后才重新获得自动恢复额度；失败或短期再次崩溃转为 unavailable，等待显式重试。初始化/恢复超时采用 15 秒，不能放宽已有冷初始化性能预算。新宿主默认隐藏，故障本身不构成显示请求；已排队且仍有效的显式请求可在就绪后显示。

状态中的“已注册”和“面板就绪”分别保留，托盘和 Web 由二者共同判断可用性。不可用时不再把期望组合直接拼在可用入口上；设置页可继续以“已设置、尚未生效”展示期望值。管理员环境创建失败应显示真实启动错误，不再一概要求用户修改账户或系统策略。

继续保留现有设置事务、operation ID 幂等、注册冲突回滚、录制租约、旧注册清理及节点退出语义。停止后到达的异步就绪或 IPC 应答不能重新创建窗口或注册快捷键。

### 跨平台扩展边界

抽象仅覆盖已有职责：`HostLauncher` 负责受控启动与退出，`ActivationBroker` 负责用户触发的激活授权与恢复，`SurfaceSession` 负责版本化消息和会话生命周期。具体类型名可在接口评审时调整，避免为未来平台建立通用进程框架。

草稿所有权、协议验证、代次和恢复状态机跨平台复用；Windows 令牌、匿名管道句柄、Job、HWND 和 WebView2 均留在平台实现。macOS/Linux 将来分别选择其原生 Web 宿主、IPC 与权限机制，不复用 Windows 的降权实现，也不假定 root 与 Windows 管理员具有相同限制。

本次保留 macOS/Linux 的明确 unsupported 路径，验证公共包不依赖 Windows 类型和系统调用。未来接入时必须在对应系统验证桌面会话、前台激活、输入法、渲染沙箱、父子进程退出和权限策略，再开放平台能力；交叉编译和 WSL 不替代原生验收。

## 验收矩阵

| 类别 | 必测场景 | 预期结果 |
|---|---|---|
| 普通用户 | 独立标准用户会话；管理员账户未提权启动；已有 Runtime 与干净安装 | 同一独立宿主架构可用，无管理员要求和额外提权 |
| 管理员 | UAC 开启并提权；UAC 关闭的管理员节点 | 主进程保持原权限，宿主实际非提权 Medium IL，沙箱启用，快捷键与输入可用 |
| 不支持环境 | SYSTEM、非交互会话、权限/目录访问不足 | 准确错误和有限重试，不启动提权 UI，不影响任务服务 |
| 激活 | 独立 High/Medium 前台程序；热显示、冷恢复、恢复中继续操作其他窗口 | 获得焦点即可输入；Escape/同键恢复合理；过期请求不抢焦点 |
| 真实窗口与输入 | 正式工具窗口样式；实体键盘中文 IME、英文、换行、候选、粘贴、清空、主题、撤销 | 字符一致，候选不触发错误收起，无需点击第二次才可输入 |
| 草稿恢复 | 杀死 UI/renderer/browser；ACK 丢失；快照超时；旧代次消息；清空后迟到更新 | 恢复主进程最后接受文本，旧文本不复活；主动销毁遵守快照屏障 |
| 协议边界 | 超长帧、非法 UTF-8、未知命令、错版本、序号冲突、队列洪峰、异常断管 | 有界拒绝或终止会话，无任意执行、文件访问代理或内存无限增长 |
| 生命周期 | 主进程正常/异常退出，子进程卡死，启动中禁用/退出，连续崩溃 | 无自有残留进程、注册或窗口；无无限重启；不会清理其他应用 WebView2 |
| 配置与界面 | 注册冲突、配置提交失败、录制租约、快捷键切换、不可用时托盘操作 | 保留现有事务保证，显示实际状态与真实生效组合 |
| 包与升级 | 独立安装、源码安装、缺宿主、错误版本、路径含空格/非 ASCII、升级退出旧宿主 | 校验完整，错误只降级面板，不混用旧宿主，不修改模型/任务数据 |
| 桌面环境 | 多屏、负坐标、100/150/200% DPI、锁屏/RDP、资源压力 | 保持现有定位与隐藏规则，故障有诊断，解锁不自动弹窗 |
| 平台隔离 | Windows 测试及非 Windows 公共代码构建/unsupported 测试 | Windows 类型不泄漏到公共层；macOS/Linux 仍准确标为未支持 |

新增具体用例前须先固定超时、恢复额度、会话关闭和帧大小的边界值，测试边界和竞争条件，不以重复实现逻辑的测试代替真实进程验证。对 `0x80000003` 保留异常日志与可关联的崩溃证据；复现时先定位再判断是否阻断交付，不将“未再出现”写成“已修复”。

## 验证入口与性能预算

沿用现有入口，在实现阶段扩展其跨进程用例和报告字段：

```powershell
go test ./...
go vet ./...
node --test tests/plugin-contract.test.mjs tests/web-state.test.mjs tests/quick-input.test.mjs tests/desktop-settings.test.mjs
pwsh -NoProfile -File scripts/test-quick-input.ps1 -Go go -OutputDirectory .\out\quick-input-validation -Desktop -Cycles 100
```

`-Desktop` 必须在交互式 Windows 环境运行，分别在权限矩阵各环境执行；缺失环境记为 skipped 或 blocked。脚本覆盖协议、草稿、受限宿主与退出生命周期；物理输入和权限矩阵仍须按验证说明单独验收。使用仓库支持的 Go/Node 版本与已校验 Runtime，实际版本、原始日志和样本写入忽略的输出目录，发布证据随版本提供。

保留冻结预算：冷初始化 P95 ≤10 秒、桥往返 P95 ≤200 毫秒、自有进程树增量 private commit ≤350 MiB、隐藏采样 CPU ≤单核 1%、100 次完整启停后自有子进程残留为 0。新增宿主必须计入进程树成本；同时报告完整 IPC 往返、可见激活耗时及主服务 ready 延迟，避免用桥 ACK 冒充窗口可输入时间。既有隐藏 CPU 失败项单独记录，不因完成隔离而自动通过。

## 规模与拆分评估

实现按职责新增 `hostipc`（协议）、`hostbundle`（配套程序校验）、`host_session.go`（主进程代理）、`host_editor.go`（编辑确认）、`host_peer.go`（宿主通道）、`host_runtime_windows.go`（UI 入口）、`host_process_windows.go` / `host_token_windows.go`（启动和权限）及 `controller_recovery.go`（有限恢复）。既有原生 surface 保留在 quickinput 包，只有独立 GUI 入口实例化 WebView2；不为文件迁移新增抽象层。现有协议 Unicode 检查由双方共用。

当前核心控制器约 473 行，直接相关的 quickinput、desktop 和节点入口 Go 文件均未超过 1,000 行。新进程协议、启动器和宿主按职责组织，保持单文件建议不超过 1,000 行、单函数建议不超过 100 行；原生窗口实现保留现有模块边界。

本计划不包含无关文件拆分。实施期间若新增内容触发已有文件超限，先评估职责与依赖，再按[代码风格](../../code-style.md)说明拆分影响并取得确认；不以重构授权自动扩大范围。
