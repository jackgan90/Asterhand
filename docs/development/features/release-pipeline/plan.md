# 可复现发布与独立安装

## 范围与需求

实现 Windows x64 完整节点的单脚本安装及统一 GitHub Release 发布。关联 INST-01、INST-05、INST-06、INST-15～INST-18；领域权威见 [安装需求](../../../installation/requirements.md) 与 [安装设计](../../../installation/design.md)。

安装包含 Asterhand、内嵌 Web、Node、锁定的运行时与 provider、Microsoft VC++ x64 运行库和缺失的 Tailscale 系统组件。原生模块加载通过后完成安装并退出；登录、凭据、授权目录、启动、配对与模型验证属于后续配置。

## 设计

- `scripts/release.ps1` 从固定清单准备构建器和依赖，调用平台 builder，执行发布检查，生成完整附件集合，上传草稿并校验远端附件，再按显式模式发布。
- 平台注册表声明 OS、架构、builder、installer 和启用状态；当前只启用 Windows。Linux/macOS 接入必须实现各自构建、引导和原生验收，不能只更改启用标记。
- 安装脚本绑定仓库和应用版本。公开 Release 的下载无需开发工具或 GitHub 登录；本地包模式继续用于离线包检验。
- 草稿可按相同内容重试；同名不同内容的远端附件拒绝覆盖。公开版本不可被脚本覆盖。源码摘要、依赖摘要、文件大小及 SHA-256 随附件发布。
- 开发发布使用单独测试仓库和 prerelease；默认操作创建草稿，生产发布必须显式选择模式。

## 验收与验证

1. 全新 Windows 仅下载并执行 install.ps1，依赖完整、版本检查成功、生成启动入口，未打开配置流程。
2. 发布命令自动准备附件并上传；GitHub 中附件完整，公开测试 Release 可匿名下载，下载内容与本地摘要一致。
3. 重复安装保留数据；拒绝错误摘要、错误版本、非预期平台；发布失败保持草稿，重试不误覆盖。
4. 原生干净系统测试与已有系统中的隔离目录测试分别记录。方法见 [验证说明](validation.md)。

## 规模与职责

发布编排、GitHub 传输、平台构建、安装各自独立。平台扩展复用附件契约，不把操作系统分支集中到一个安装脚本。依赖锁为生成数据；其余文件遵守工程规模规则。
