# 任务可靠性与配置保留

## 目标与范围

关联 TASK-05/06/07/08/09、AST-09、EXEC-09、INST-12/13。确保事件容量耗尽时仍可收尾和恢复，取消不会被问答覆盖，运行时自动发现不会改写显式配置。

## 设计

- 普通事件预算 4096，额外预留 16 条控制事件，总硬上限 4112。预留仅用于已有操作证据、问答交付、取消、结束、恢复与人工处置；重复控制请求不追加事件。
- 新文件写入和委派先取得普通事件预算，拒绝后不产生副作用。文件完成操作、产物与事件同事务提交；旧 completed 操作按已有证据幂等补齐。
- 收尾持久化失败停止调度，保留待核对现场；旧满容量任务仍可启动并进入待核对。
- 问答事务检查 attempt、interaction、状态和 context，取消状态优先；活动表登记与取消同步，收尾再次保留已提交取消。
- runtime_options_explicit 标记显式选项，启动/repair/升级保留。旧配置仅在全部路径匹配同一历史包布局时视为自动，其余非空值视为显式。
- 就绪结果绑定程序包和有效执行配置摘要；程序、模型或有效运行时选项变化后重新 probe。

## 验证与规模

见 [可靠性验证方法](validation.md)。函数软阈值例外：
- cmd/asterhand.run 为 133 行，顺序组织 CLI、配置、锁、启动和清理；集中保留退出路径与资源生命周期。
- tasks.fileTool 为 104 行，连续表达 prepare/create/fsync/readback/commit 的故障边界；拆成薄包装会隐藏证据提交与副作用顺序。

手写文件低于 1000 行；生成依赖锁和第三方代码单独分类。相关职责复杂化时重新评估，不通过压缩代码规避计数。
