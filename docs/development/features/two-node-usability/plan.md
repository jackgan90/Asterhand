# 双节点交互与连接同步

## 目标与范围

关联 WEB-04/05/06/10、NODE-01/04/07/08、AST-09、INST-05。使远端任务可见、已配对节点名称和地址可同步、网络设置可正确生效，并保持准确的模型就绪与发送反馈。

## 设计

- 合并 job 与 outbox 后按原始提交时间倒序；路由转执行保留同一逻辑卡片和原始目标。
- 节点名称/网络设置不撤销 probe；模型、凭据、运行时及授权目录改变后重新验证。
- 元数据通知只带节点身份与地址。接收方使用原固定证书、凭据和 node_id 回查，仅更新 name/endpoint，保持权限与撤销状态；后台每 20 秒重试。
- 设置页配置 peer_listen；Tailscale 按钮同时填入监听与公布地址，保存后明确是否需重启。远端配对拒绝 loopback 地址。
- 信息与元数据回查时限 10 秒，外层通知 15 秒，覆盖冷连接及往返延迟；超时不放宽身份校验。
- JS/MJS 显式返回 JavaScript MIME 并保留 nosniff，避免 Windows 文件关联干扰模块加载。
- 发送禁用显示具体原因，只有实际提交时显示忙碌状态。

## 验证与规模

见 [双节点验证方法](validation.md)。app.settings 为 121 行，解析、任务/probe 互斥、凭据保存与就绪失效属于同一受锁保护的配置事务；保留连续顺序以便审查写前拒绝和副作用边界。

元数据通知与信任校验分别位于 app/peer_metadata.go 和 peer/metadata.go，避免扩展通用调度职责。手写文件低于 1000 行。
