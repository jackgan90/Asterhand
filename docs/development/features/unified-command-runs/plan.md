# 统一脚本图命令与多实例执行

状态：实现、自动化验证、独立审计复审与用户验收已完成。关联 EXEC-CMD-01—16、EXEC-GRAPH-01—09、WEB-CMD-01—14。

## 范围与目标

所有本地命令使用脚本图，由助手持有执行、计时、日志和停止能力。取消托管/非托管、单脚本/图两组命令类型及独立终端选项；单脚本场景为默认连好的开始、脚本、结束三节点图。新增 `allow_concurrent`，默认 false；允许时可启动同命令多个独立实例。仍由快捷输入显式启动，不增加 HTTP、模型、远端启动和执行重试。

最近执行按接纳顺序，其他实例日志保留到下一轮成功接纳时清理；旧测试配置不迁移，不做缺失占位兼容。交互输入仅预留可选执行器接口，不开放输入请求、界面或终端后端。

## 设计依据与职责

- [本地命令](../../../executors/local-commands.md)：schema 4、名称和图配置、入口及失效行为。
- [执行和保留](../../../executors/managed-local-commands.md)：多实例接纳、持久化、停止、恢复、容量及交互扩展。
- [脚本图](../../../executors/script-graphs.md)：节点调度、全局名额、超时、失败与日志来源。
- [统一命令 ADR](../../../executors/adr/006-unified-command-runs.md)：替代旧类型、单实例和日志替换决定。

注册模型只保存图和命令属性。脚本路径参数验证及平台启动改用独立 `ScriptSpec`，不再构造一个伪单脚本 Command。运行管理器按 command ID 分组、run ID 定位；每实例持有原有图状态机和各节点执行对象。存储负责原子发布当前轮次索引和每实例记录。UI 只使用稳定身份，不拥有进程或猜测完成。

## 实施顺序

1. 同步权威需求、设计、ADR 与验证说明，独立 reviewer 审核，复核修复缺口。
2. 统一图注册和 ScriptSpec，移除非托管启动入口、旧 schema 迁移及配置合并分支；保留通用 Windows 参数构造和普通用户执行能力。
3. 按实例组织运行/恢复/存储，增加有界接纳、原子换轮、逐实例及批量停止；为交互能力建立可选接口，当前仅支持无输入/双流文本。
4. 同步 HTTP/IPC、快捷列表、Web 表单和多实例日志选择；复用独立日志窗口和每屏分页，保持焦点、翻页、主题和语言。
5. 更新受影响测试并增加竞争、恢复、容量、分页与多实例界面回归；运行 Go、Node、国际化及文档链接检查、Windows 受管进程与原生 UI 验证。
6. 同一 reviewer 审计实现及计划一致性，复核修复再复审；对本机旧测试命令的数据清理在确认旧节点和命令已停止后执行，只删除命令注册和对应运行区，不删除脚本、聊天、任务或凭据。

## 验收条件

- 新建图只填一个脚本即可保存运行；无类型/独立终端选项，不按脚本相同自动合并命令。
- 禁止并发覆盖接纳到进程清理和日志收尾；允许并发时日志、结果、超时、停止独立，别名共用命令限制。
- A 先接纳、B 后接纳，B 先结束时仍以 B 为最近执行，A 不覆盖；全部结束仍可查看二者，下一轮接纳才清理上一轮。
- 预检查、容量、日志准备和索引发布失败均不清理上一轮；接纳后的平台启动失败成为新实例结果。
- 删除、编辑与任一活跃实例互斥；批量停止携带点击时实例 ID 集合，迟到请求不停止新实例。
- 恢复核对每个未完成节点，不自动续跑；停止未确认或存储收尾未完成不释放占用，不删除恢复证据。
- 多实例/节点日志可分别选择，分页和阅读位置互不干扰，新实例加入不重置旧屏；旧轮被清理后旧读请求明确失效。
- 同时运行、每轮保留数量、日志容量、读取消息及屏数均有上限；限制失败有本地化原因，无静默丢日志。
- 旧 schema 和未知字段被拒绝、不被自动重写；旧兼容代码不继续进入产品执行路径。
- 可选交互接口不向 UI/IPC 暴露输入能力，Windows 后端继续关闭 stdin，生命周期接口不要求无意义空实现。

## 验证与规模

具体入口见[验证说明](validation.md)。原始日志保存在构建产物的独立审计目录，长期文档仅保留可复现步骤和边界。新增模块按注册、实例集合、存储索引、摘要、视图选择职责组织；修改后评估文件/函数规模，超 1000 行且可安全拆分时先取得同意，不以压缩排版规避。

本次修改的手写文件均未超过 1000 行；两个超过阈值的 `i18n-catalog.mjs` 属于词表生成代码。日志屏 `logPane` 为 134 行，集中管理同一屏的 DOM、分页、事件和本地化，内部已分为局部渲染与追加函数；拆成跨文件对象会增加状态传递。`TestNativeLocalCommandsWorkflow` 为 114 行，按一次窗口生命周期验证完整操作顺序，共享窗口和启动计数，保持连续场景更便于复现。日志选择器工厂和新增 Windows 双实例场景均在 100 行内。若后续增加交互输入或终端视图，应另建视图和执行适配，避免继续堆入文本日志工厂。
