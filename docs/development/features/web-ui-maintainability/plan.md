# Web 与快捷输入的维护性重构计划

保留现有原生 HTML/CSS/ES module、Go 内嵌分发和 Windows WebView2 快捷输入。本次只整理通信、页面生命周期、业务状态、DOM 视图与宿主桥的职责，使现有功能更容易维护和回归验证。

状态：实现、工程自动回归与独立审计复审已完成，用户验收通过。交付目标是现有 Windows Web 与快捷输入的等价重构，不新增平台、产品功能或第三方依赖。验证方法与各层边界见[维护性验证](validation.md)；真实模型、双 Windows 与既有物理设备待验证项单独验收。

## 需求与设计依据

- 关联需求：WEB-01—07、WEB-09—12，沿用现有实现范围；WEB-04 中尚未开放的审批仍不开放。
- 权威文档：[Web 需求](../../../web/requirements.md)、[Web 设计](../../../web/design.md)、[安装设计](../../../installation/design.md)、[测试设计](../../../testing/design.md)。
- 沿用决策：[统一节点 UI](../../../web/adr/001-unified-node-ui.md)、[桌面启动与托盘](../../../installation/adr/004-desktop-launcher-and-tray.md)、[快捷输入宿主](../../../installation/adr/006-global-hotkey-input-surface.md)。本次不替换宿主、认证或构建方案，无需为模块拆分新增 ADR。
- 支持范围继续以[平台矩阵](../../../testing/platforms.md)为准。

## 取舍

| 问题 | 本次决定 | 原因 |
|---|---|---|
| Web 技术路线与前端框架 | 保留原生 ES module，按现有职责拆分 | 当前页面规模足以直接整理；引入 Vue/React、TypeScript 和 Vite 会增加迁移及构建验证范围 |
| 通信与认证 | 抽出同源客户端，保持现有 Cookie、CSRF 和来源校验 | 同源限制是当前部署契约；提取模块无需同时开放远程访问 |
| 宿主能力 | 分别提取浏览器操作和快捷输入 WebView2 桥 | 两个入口的能力、认证及安全边界不同，避免形成通用高权限桥 |
| 页面状态与刷新 | 明确状态所有者和资源释放，保留全量读取与现有刷新规则 | 先消除职责混杂和异步回调失去归属的问题，不扩大为渲染框架或事件协议改造 |
| 快捷输入资源 | 保留独立入口、主题和资源目录 | 主页面与浮层目前没有需要合并的业务组件，合并工程和主题不能直接减少本次维护风险 |

Web UI 可复用是保留技术路线的依据；具体复用比例、其他平台支持与宿主性能不作为本次重构的承诺或验收条件。

## 保持不变的契约

| 边界 | 保持内容 |
|---|---|
| 部署与登录 | Web 仅监听 loopback；保留登录链接、会话 Cookie、Host/Origin/CSRF 校验、CSP 和同源请求；不增加服务地址设置 |
| 接口与数据 | API 路径、请求/响应字段、SSE 事件、配置格式、数据库和持久化位置不变；未确认提交继续使用现有 `asterhand-pending` 存储及请求 ID |
| 任务操作 | 排序、路由转执行去重、目标选择、提交互斥、问答去重、取消和人工核对语义不变；网络错误不自动重发写请求 |
| 页面交互 | 布局、文案、主题、按钮行为、确认/取消语义及现有窄屏样式不变；主输入草稿及正在编辑的回答不因刷新被覆盖 |
| 刷新 | 保留服务端每 2 秒的 `refresh` 通知、前端全量读取 jobs/outbox、节点每 20 秒刷新及回答框聚焦时暂停任务列表刷新 |
| 桌面设置 | 继续调用现有 `/api/desktop/*`；沿用 `supported`、注册状态、录制租约、修订号与操作 ID；修改快捷输入设置不改变模型就绪状态 |
| Windows 宿主 | 托盘线程仍持有全局热键，独立 STA 线程仍承载 WebView2；快捷键默认值、冲突处理、隐藏/恢复、关闭与退出关系不变 |
| 浮层安全与草稿 | 保留独立虚拟 HTTPS 来源、`connect-src 'none'`、资源白名单、桥版本与代次校验；无 Web 登录凭据，无任务 API；16,000 UTF-8 字节、LF、IME 和内存草稿语义不变 |

明确排除：远程登录、HTTPS/CORS/Bearer 接入、通用能力注册表、桌面壳、PWA、移动端及其他 OS 适配；页面内新确认框、统一主题、增量 SSE、精细 DOM diff、列表虚拟化和性能专项优化。保留既有能力边界，不为假定宿主添加空实现或未验证的适配器。

## 重构前的维护问题

1. [主入口](../../../../web/app.js)同时持有请求、CSRF、全局数据、定时器、DOM 渲染与设置事件，初始化和后续更新缺少统一的资源所有者。
2. `start()` 创建的 EventSource 和节点刷新定时器没有成对的停止入口；模型检查轮询、通知计时器各自管理，难以检查重复初始化和迟到回调。
3. 任务刷新直接查询回答框的 DOM 焦点决定是否暂停；任务提交与回答的去重状态嵌在事件处理器中，测试难以覆盖完整交互顺序。
4. [快捷输入页面](../../../../internal/quickinput/assets/input.js)将草稿编辑与 `window.chrome.webview` 收发写在一起。新增桥模块还会涉及[原生资源白名单](../../../../internal/quickinput/surface_content_windows.go)，仅移动 JS 文件会导致模块被拒绝加载。
5. 现有 [Web 状态测试](../../../../tests/web-state.test.mjs)、[桌面设置测试](../../../../tests/desktop-settings.test.mjs)和[草稿模型测试](../../../../tests/quick-input.test.mjs)覆盖局部逻辑；主页面生命周期、输入保护和真实静态模块加载需要补齐验证。

## 实施清单

按以下顺序完成，每步保持现有入口可运行。新增模块名称可随内聚性小幅调整，职责边界和验收条件保持一致。

### 1. 固定行为回归与状态归属

- [x] 复用现有测试，补充未确认提交后重试、回答 ID 复用、输入期间刷新暂停、取消确认以及设置保存的特征用例；断言用户操作和实际请求，不断言私有函数结构。
- [x] 为连接会话、任务快照、提交状态、回答状态和设置事务指定唯一所有者。继续使用[任务视图模型](../../../../web/view-model.mjs)进行合并、排序与发送状态计算。
- [x] 记录现有页面与浮层的操作基线，作为后续各步的等价验收依据；测试数据与截图使用隔离数据目录，不写入长期文档。

完成条件：可以通过操作序列确认请求 ID、目标、任务排序和用户输入在重构前后的行为一致。

### 2. 提取同源请求客户端

- [x] 在 `web/api-client.mjs` 集中管理 JSON 请求、CSRF 注入、登录/会话读取和带 HTTP 状态的错误；以实例持有会话，不使用跨页面共享的模块可变单例。
- [x] 接收可注入的请求依赖以支持测试；生产实现只使用当前同源路径，不增加任意 endpoint、认证策略注册或凭据存储。
- [x] 由客户端提供现有事件流的创建入口，生命周期控制器负责持有和关闭；业务视图不直接创建 fetch/EventSource。
- [x] 请求 ID、答案 ID、桌面设置操作 ID 和未知提交结果仍由各业务控制器处理；客户端不生成新 ID、不自动重试 POST/DELETE，也不把中止 HTTP 等同于取消服务端操作。

完成条件：现有接口负载和来源保护保持一致；成功、401/403、业务失败、网络失败通过同一错误边界返回，沿用现有页面反馈。

### 3. 明确页面与异步资源生命周期

- [x] 提取 `web/app-lifecycle.mjs`，统一拥有连接会话的启动、停止、EventSource 和节点刷新定时器；重复启动保持最多一个有效会话。
- [x] 用会话代次或等效机制拒绝已结束会话的迟到读取结果。释放订阅、监听器和计时器时使回调失效，避免旧响应回写当前页面。
- [x] 模型检查轮询归节点设置控制器，通知隐藏计时器归通知视图，录制轮询与租约归现有桌面设置控制器；由各所有者提供必要的清理入口。
- [x] 页面离开时完成清理；浏览器前进/后退缓存恢复时只恢复一次现有订阅。保留 EventSource 原生重连，不叠加另一套重连循环，不增加后台同步或推送。
- [x] 单独验证只读刷新与写操作的中断边界：停订阅不会取消任务，未确认写入保留原有重试状态；录制取消继续依赖明确的租约请求与服务端到期机制。

完成条件：重复初始化、离开/恢复、断线重连和迟到响应均不会叠加资源、覆盖新会话或重复产生业务操作。

### 4. 按现有业务拆分控制器与视图

- [x] 将任务提交、回答、取消、详情与其状态移入任务控制器；任务卡片渲染及输入焦点事件由任务视图负责，二者使用明确参数和回调连接。
- [x] 将节点选择/配对、节点设置/模型检查分别按内聚职责组织；继续保留独立的 [desktop-settings.mjs](../../../../web/desktop-settings.mjs)，不把其录制事务散布到通用状态层。
- [x] 由任务视图显式报告“回答正在编辑”，刷新控制器据此沿用当前暂停规则，移除入口通过全局 CSS 查询推断编辑状态的耦合；失焦后按原有刷新节奏恢复。
- [x] 保留全量列表渲染。本次只隔离数据转换、动作回调和 DOM 更新，不引入通用 store、事件总线、虚拟 DOM 或自制组件框架。
- [x] 将目前使用的剪贴板、确认和输入提示集中为 `web/browser-actions.mjs` 的窄依赖，默认仍调用原有浏览器 API；取消返回值、提示文本与实际副作用顺序保持一致。不增加文件选择、通知或热键注册接口。
- [x] `web/app.js` 收敛为装配与启动入口；渲染继续使用 `textContent` 处理模型、文件和事件内容，保留 CSP。

完成条件：每个视图可在注入动作回调后验证；任务输入、问答、设置、配对和停止节点流程与现状一致，状态所有者清晰且不存在循环依赖。

### 5. 提取快捷输入的 WebView2 桥

完成条件：浏览器宿主 API 只在适配模块出现；快捷输入的原生线程、窗口、注册、挂起/恢复实现及现有安全协议保持原样。

## 规模与完成条件

拆分起点为 `web/app.js` 的 587 行、`desktop-settings.mjs` 的 143 行与快捷输入 `input.js` 的 56 行。它们均未超过文件软上限；拆分依据是状态所有权和测试边界。

重构后入口 90 行，桌面设置 177 行，编辑器 66 行；其余手写模块均小于 200 行。外层工厂 `desktopSettings`、`nodeController`、`nodeSettings`、`taskView` 超过函数 100 行建议：分别聚合一项录制/保存事务、节点及选择状态、一份节点表单及检查代次、一份任务 DOM 与编辑焦点。实际事件与异步处理函数均小于 100 行。保留词法状态归属便于检查回调有效性；将这些状态移到通用 store 或为行数新增层会增加依赖与同步负担，故保留这些内聚闭包，后续相关改动重新评估。

遵循[代码风格](../../code-style.md)：不引入 master class、循环依赖或只转发调用的通用框架；修改后重新统计规模。若继续修改其他超限文件且可安全拆分，按规范先取得对应拆分确认。

完成必须同时满足：

- [x] 六项实施工作及对应回归完成，现有功能、样式、协议、认证和支持范围保持一致。
- [x] 新模块有清晰所有者，订阅/定时器/监听器成对释放，业务去重与未确认结果语义有行为测试。
- [x] 独立运行的构建产物可加载主页面与快捷输入全部资源，浏览器与 WebView2 冒烟分别记录。
- [x] 权威设计与验证入口已同步；所有本地文档链接指向纳入版本控制的文件。
- [x] 验证按 passed、failed、skipped、blocked 分开记录；未执行项不标通过，实现完成、用户验收、提交和发布状态分别报告。

原始日志保存在忽略输出目录，长期文档只维护契约、验证方法和支持边界。
