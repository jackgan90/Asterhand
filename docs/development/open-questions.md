# 后续待验证与待决定事项

| 事项 | 已知边界与验证方法 |
|---|---|
| 物理故障与网络拓扑 | 双 Windows 通信/指令执行已接受；按 [人工验收](../testing/acceptance.md) 补充服务退出、真实断网、重启和具体 NAT 拓扑的逐项证据 |
| Linux 基础节点 | 已交叉编译；需要真实安装、路径权限和进程生命周期测试 |
| macOS | 需要平台构建与设备实测 |
| 手机远程访问 | Web 当前仅 loopback；先决定受认证的远程部署方式，再做设备测试 |
| 原生 resume / 审批 | 运行时契约尚未公布这些能力；普通问题通过受限回调实现，重启人工对账 |
| 多节点高任务量 | 当前串行轮询、单执行槽，无指数退避或自动容量回收；基于实际工作负载评估 |
| Windows Release 签名 | 安装包尚无 Authenticode；需要确定签名和发布流程 |
| 持续集成 | 已有测试与构建脚本，尚未建立 CI workflow |

已确定的技术选择见 [全局设计](../overview/design.md)。新的决定写对应领域 ADR；不要把已接受的技术选择重复作为未决事项。
