# 开发治理需求

状态：已确认，适用于所有后续开发。关联 C07、C08、C10。

| ID | 要求 |
|---|---|
| DEV-01 | docs 按主要领域分层，各领域维护 requirements/design/adr |
| DEV-02 | 每个 feature 强制同步领域文档、计划和验证说明 |
| DEV-03 | 原始需求、已确认决定、待验证假设和实现状态分开 |
| DEV-04 | 文件 1000 行、函数 100 行为软限制，例外需理由 |
| DEV-05 | 新增内容后文件超限且可安全拆分，主动询问用户并获同意后拆分 |
| DEV-06 | 开发 agent 行为规范与产品 runtime 指令 / memory 分开 |
| DEV-07 | 交接不依赖聊天历史，保留版本、已完成、未完成和证据 |
| DEV-08 | 实现、本地提交、远端推送和发布分别依据用户授权执行 |
| DEV-09 | 采用用户提供的 MIT License，源码发布状态与产品二进制发布、用户验收分开记录 |
| DEV-10 | 长期文档独立于聊天和临时环境；功能引用有明确名称，链接目标进入版本控制 |
| DEV-11 | 验证文档说明方法、前提、源码入口和支持边界；不包含临时运行流水、本机路径或忽略目录证据链接 |

工程检查可检查格式和关联，不能自动证明文档准确或替用户完成验收。

代码、测试、锁定依赖、领域设计与操作指南构成同一交付单元。提交、推送和 Release 不由实现状态推断。
