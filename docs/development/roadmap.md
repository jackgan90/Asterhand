## M0 接口验证与基线冻结

验证 Windows 原生 OpenClaw 的安装、会话、流式消息、工具注册、异步任务、提问、审批、取消、查询、重启对账能力。实际调用 DeepSeek 完成小型文件任务及无副作用工具检查；不验证 coding harness。

固定 Go / SQLite 驱动 / Web 工具链 / OpenClaw / provider 版本、OS/架构、正式接口 schema、错误与能力声明。明确 TLS、配对、Web 证书、跨节点人工身份、key 存储和部署用户的实际方案。

出口：接口实验记录、版本清单、可实现的安装方案、已知限制、领域文档更新。缺少关键能力则记录阻塞并提出范围或适配调整，不凭文档名称判定支持。

## M1 单机闭环与可靠性基础

建立 Go 服务和 SQLite；实现 job/attempt/event/interaction、受限文件工具、OpenClaw adapter、薄聊天与任务页、本机 DeepSeek 配置。

同时建立 controller、FakeExecutor、协议代理、可控时钟。首次真实执行就实现启动窗口与重启对账，不拖至 M3。

出口：V02、本地问答/取消、A03/A04/A13/A14/A17 等关键回归有证据。页面关闭不终止任务；输出包含真实文件验证。

## M2 两机真实协作

实现配对、权限、发送队列、目标能力检查、远端事件与产物读取、跨节点用户交互身份。两台 Windows 运行独立 OpenClaw 与本地凭据。

出口：V03—V05，A 退出后 B 继续、响应丢失重试去重、重连补读。B 的 Web 可独立接手任务。

## M3 安装交付与用户验收

完成 install.ps1 / install.sh、setup / doctor / repair、发布清单、干净环境准备、配置保留和可选登录后启动。安装基础设计在 M0 明确，不到 M3 才发现依赖无法分发。

执行 V01—V06、必要故障矩阵、Linux 基础节点验证和手机 Web 检查。Mac 标记未运行。准备发布说明、操作手册和已知限制。

出口：工程证据齐全、用户能独立完成新节点安装及可见任务验收；用户接受与实际发布另行记录。GitHub Release 的创建和推送遵循授权。
