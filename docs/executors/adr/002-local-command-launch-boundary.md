# 002：本地快捷命令使用独立启动边界

状态：已采用。

## 背景

快捷输入中的本地命令用于反复触发用户预注册脚本。它无需模型配置，不等待脚本结束；用户退出助手后，已启动脚本仍须运行。任务执行器的持久状态、取消和进程树清理与此目标不同。

## 决定

注册库、普通用户进程启动器及快捷输入协议独立于任务执行器和会话运行时。主进程在检查命令 ID 与修订后启动固定 Windows shell，进程不加入输入宿主或任务的 kill-on-close Job。启动后释放进程句柄，不托管日志、结果、停止和恢复。

Web 仅管理注册信息。执行能力只经已验证输入宿主的窄协议提供；模型与远端节点没有该能力。每次用户确认具有独立请求身份，同一宿主会话内重复投递拒绝；未知回执不自动重发。非提权令牌沿用桌面宿主策略，脚本继承该用户的常规系统环境，不继承节点私有运行时环境。

相同脚本、参数、有效工作目录与窗口模式合并为一个命令的多个名称。参数和工作目录影响执行结果，不能仅按脚本路径合并。

## 影响

用户可连续启动多个脚本，数量与资源竞争由用户管理。“已启动”只确认进程创建，脚本内部错误由脚本或终端展示。需要持久进度、取消或结果托管的工作仍走任务服务，不能从本入口推断已获得这些能力。

详细契约、批处理参数边界及维护入口见[本地命令设计](../local-commands.md)，验证见[功能验证](../../development/features/local-quick-commands/validation.md)。
