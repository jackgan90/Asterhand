# 003：托管本地命令的生命周期和日志权威

- 状态：accepted（Windows 实现；验证边界见功能验证说明）。
- 日期：2026-11-02。
- 所属领域：执行器、Web、安装生命周期；EXEC-CMD-06—15、WEB-CMD-09—14。
- 替代关系：局部替代 [002：独立启动边界](002-local-command-launch-boundary.md)对全部本地命令的限定；其独立启动规则继续适用于非托管命令。历史决策原文保留。

## 背景

独立启动满足反复触发本机脚本的需求，但启动后释放句柄，无法提供流式输出、持久结果和执行控制。托管命令需要跟踪进程、限制同命令并发、保留最近日志，支持用户强制停止与可选超时。日志查看需要符合产品风格的独立桌面窗口，窗口关闭不应影响脚本。

## 决定

1. 保留非托管路径，新增按命令 ID 独立管理的托管路径；与任务引擎、模型会话和远端执行协议分离，不共享任务执行槽。
2. 节点主进程拥有执行身份、状态机、计时、进程句柄和持久日志。日志宿主只负责受限读取和当前 run 的显式停止请求，UI 关闭/崩溃不改变执行生命周期。
3. 公共 ExecutionBackend 负责整次执行的归属、双流、强制停止、退出确认和恢复证据。首个 Windows 实现每次执行创建独立 Job 并在启动时绑定，使用普通用户令牌、正常用户环境、标准流重定向和无交互 shell。节点退出终止受管执行，不提供重启续跑和常驻接管代理。
4. 自然结果按脚本退出码判断；用户中断与节点退出记 interrupted，超时记 failed/timeout。所有停止共用进程树清理流程，结果按同一状态机仲裁，不从强杀退出码反推停止原因。
5. 停止和日志读取绑定 command ID/run ID，清理完成前不释放单实例占用，迟到请求不作用于下一次执行。
6. 只保留最近一次日志和结果；配置与运行记录分开保存，原子发布并保留必要恢复标记。运行中禁止修改/删除，托管改非托管保存时清理记录，控件旁提示且不增加弹框。
7. 日志由独立非提权 UI 宿主管理多个原生窗口，继承主题和国际化，受限分块读取；窗口、页面桥和传输使用窄接口，Windows 首个后端为 WebView2。不开放浏览器任意启动、模型或远端命令能力。
8. 注册策略、执行、计时、窗口、传输及必要文件操作的平台差异在边界内封装；状态机、日志格式、停止原因和 UI 业务协议共用。Job/Token/HWND/STA、Windows 扩展名与路径大小写规则不进入公共契约；正常退出码与信号/异常结束分别表达。
9. 平台按能力与环境校验接入。当前仅实现/验收 Windows，macOS/Linux 保持 unsupported；进程组实现不自动获得 Job 等价保证，缺少完整受管停止或宿主死亡清理等必需能力时拒绝托管启动。平台替身与交叉构建只证明边界，不替代原生验收。

## 备选与后果

- 复用任务引擎会引入任务队列、全局执行槽和原有恢复/日志预算，不符合本地命令的独立并发与完整最近日志需求；只借鉴底层进程控制机制。
- 在 UI 进程中持有脚本和日志会让窗口/宿主故障影响执行；由节点管理可以保持关闭窗口后继续运行及日志重建。
- 助手退出后由独立代理继续执行需要额外的进程身份、重连、升级协调和存储权威，本功能选择随节点退出停止。
- stdout/stderr 不能表达任意脚本的业务健康；使用退出码契约，stderr 作为日志，不自动判定失败。
- 强制终止无法回滚已产生副作用，也不能恢复脚本尚未输出的用户态缓冲。清理和持久化失败需要显式状态，不能为了快速解锁而假报停止成功。
- 直接依赖 Windows API 会使未来移植同时侵入核心状态、协议和 UI；窄平台适配把新增平台限制在启动/监督、时钟、窗口、文件操作和构建安装。只在实际差异处建立接口，不增加通用插件框架，也不提前引入其他平台依赖。
