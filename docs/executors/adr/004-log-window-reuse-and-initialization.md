# ADR-EXEC-004：日志窗口复用与异步初始化

状态：采用。替代 [ADR-EXEC-003](003-managed-local-command-lifecycle.md) 中“关闭最后一个日志窗口即释放宿主”的窗口资源约定；命令执行、日志权威与停止语义继续有效。

## 背景

每次关闭后销毁 WebView2，会使反复查看日志持续承担冷启动成本。原生窗口隐藏到页面握手完成才显示，使加载和错误反馈都依赖浏览器准备好；初始化失败再串行等待浏览器退出，会使请求先到期并隐藏真正错误。固定窗口坐标也不能满足多屏使用。

## 决定

- 原生窗口先显示加载占位，浏览器与页面在可见窗口内异步初始化；打开回执确认原生窗口显示，页面失败单独呈现。
- 用户关闭仅隐藏查看界面，隐藏后暂停刷新并尽可能挂起浏览器。按命令 ID 复用，最多保留四个隐藏窗口，以最近使用顺序回收；创建及收尾中的原生窗口总数最多十六个。
- 初始化失败和渲染故障不等待清理才反馈。旧窗口异步清理；显式重开使用新窗口代次和独立 UI profile，旧事件不能删除或更新新窗口。
- 宿主通信超时使对应连接失效，后续打开建立新连接；后台回收及节点退出收尾仍有界。
- 原生窗口与浏览器确认释放后清理独占的代次 profile；释放未确认时保留目录并淘汰日志宿主，通过其独立 Job 完成确认。退休失败保留到应用退出结果，不能被后续连接替换掩盖。
- 输入宿主在原生点击入口采集屏幕定位提示。日志宿主按当前工作区解析提示，不跨进程传递 HWND；缺少提示时从触发时的前台屏幕回退。
- 页面与脚本执行继续隔离。缓存、重建、宿主退出及初始化错误均不重启或停止脚本。

## 影响与验证

少量隐藏窗口换取常用日志的即时恢复；缓存上限及有界退休防止无限累积。首次显示加载提示与最终内容就绪分开，错误窗口允许通过再次显式打开恢复。WebView2 的内部调度不作为窗口出现的前提。

协议、几何和宿主恢复测试与真实 Windows 桌面用例共同验证；多屏/DPI 和用户验收按[验证说明](../../development/features/log-window-responsiveness-and-placement/validation.md)独立记录。
