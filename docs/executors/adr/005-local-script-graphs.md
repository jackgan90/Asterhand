# 005：本地命令的静态脚本图

- 状态：accepted（实现与验证见功能计划）。
- 日期：2026-11-02。
- 所属领域：执行器与 Web。

## 背景

单脚本命令无法直接表达多个脚本的串行、并行和汇合。已有托管后端提供进程范围、退出证据、停止和日志能力，可用于各脚本节点。

## 决定

1. 增加归本地命令所有的静态 DAG，仅支持本机用户主动触发。全局排除的通用工作流仍不提供跨节点图调度。
2. start/end 为结构节点；脚本节点等待全部前置成功。图调度归节点主进程，复用 ExecutionBackend，不进入持久任务引擎的执行槽。
3. 图运行与节点执行具有独立身份，节点不是命令注册条目。旧单脚本路径保持兼容，复用底层管理能力，不通过注册虚假命令来调度图。
4. 执行证据与错误策略分开，首版只有 abort：任一失败阻止新启动并强制停止活跃节点，确认清理和日志收尾后结束。未来警告策略同时设计依赖满足条件，不伪造成功。
5. 最近运行日志按节点标记并保留独立解码上下文，UI 使用有界摘要；旧配置和日志可读，配置升级后旧程序拒绝新 schema。
6. 外部脚本文件不复制，运行快照只固定配置；边不隐式传数据。首版不提供重试、重启续跑、回滚、资源锁和清理节点。

## 后果与验证

避免引入外部工作流服务及部署依赖，保留现有普通用户执行和 UI 隔离。新增复杂度集中于失败/启动竞争、持久化身份、并行日志和图编辑。以可控后端验证调度与恢复，Windows 真实进程验证受管停止和输出，前端测试及实体界面验证编辑与日志体验。
