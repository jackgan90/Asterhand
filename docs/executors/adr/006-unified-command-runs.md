# 006：统一脚本图命令与多实例记录

- 状态：accepted；实现和验证状态见[计划](../../development/features/unified-command-runs/plan.md)。
- 日期：2026-11-03。
- 替代关系：替代 [002](002-local-command-launch-boundary.md)的非托管启动、[003](003-managed-local-command-lifecycle.md)的类型、单实例固定限制及每次启动替换日志决定，以及 [005](005-local-script-graphs.md) 的单脚本/图分类与迁移决定；窗口生命周期仍沿用 [004](004-log-window-reuse-and-initialization.md)。

## 决定与原因

命令统一保存脚本图并由节点执行。一个脚本是开始、脚本、结束三节点图，复用相同调度、停止、恢复和日志。去掉类型、独立终端和按单脚本配置合并名称，避免多套行为和隐式改变命令身份。名称、别名全库唯一，不判断图的结构等价。

并发成为命令布尔属性，默认禁止；允许时每次接纳生成独立运行 ID，每个图节点执行也有独立身份。图内并行度、本机脚本执行名额与命令实例数量分别约束不同资源。取消只影响指定实例，停止全部明确指定用户当时看到的实例集合。

最近执行由接纳序号决定，结束先后不改变它。一次连续忙碌期间及其结束后的保留期是一轮；全部实例收尾后再次接纳才换轮。当前轮结果和日志全部可读，新轮原子发布后清理上一轮。拒绝接纳不清理，崩溃恢复先核对已发布运行身份，不自动重跑。容量保护拒绝新增或停止输出超限的实例，明确标记原因和日志不完整。

采用新注册和运行存储版本，不迁移早期测试数据、不保留失效占位。开发环境由操作步骤清理已停止的旧命令数据；产品不自动删除不认识的文件。

交互只预留执行器的可选能力接口和输出类型。未来节点可选择文本输入或终端会话，身份仍绑定某次节点执行，输入通道由节点主进程持有。本次无输入 UI/协议、终端模拟和输入日志；不让所有执行器实现空的交互方法。

## 后果

原单脚本也使用全局图节点执行名额和整图超时语义；注册界面默认建好最小图，减少操作成本。当前轮会临时保留多份日志，故同时限制实例、记录和存储量。完整交互终端未来需实现平台和渲染后端，不能将纯文本日志读取当作终端仿真。
