# 托管本地命令设计

状态：Windows 首个实现。本文定义托管本地命令契约；非托管行为以[本地命令设计](local-commands.md)为准。范围、实施步骤及验收见[功能计划](../development/features/managed-local-commands/plan.md)，架构取舍见[托管边界 ADR](adr/003-managed-local-command-lifecycle.md)。

首个实现与验收平台为 Windows；命令模型、状态机、日志格式、超时语义和 UI 业务协议为跨平台契约。Windows shell、Job Object、令牌、WebView2 与原生句柄仅是当前平台适配实现，不构成未来 macOS/Linux 的公共接口。其他平台完成自身适配和原生验收前保持明确不支持。

## 类型与注册

- 增加 `execution_mode`：`unmanaged`（非托管）和 `managed`（托管）。已有注册和新建表单默认非托管。
- 非托管保留当前独立启动、允许重复并发、后台/终端选择以及助手退出后继续的行为。
- 托管由本机平台适配器选择已支持的脚本解释器，以普通交互用户身份及该用户正常环境执行，不继承节点私有运行时凭据。公共要求为非交互、关闭 stdin、无额外终端窗口。Windows 首版使用固定系统 shell 与非提权令牌，隐藏后台/终端选择，不使用 `cmd /k` 或 PowerShell `-NoExit`。
- Windows 首版支持本机 `.bat`、`.cmd`、Windows PowerShell 5.1 `.ps1`，沿用当前 Windows 路径和参数规则。支持脚本种类、路径规范化/比较和解释器参数编排归平台策略；公共参数始终为字符串数组，不拼接任意 shell 表达式。保留未来平台的脚本类型扩展点，本轮不启用 `.sh` 或其他新执行器。
- 托管注册增加可选 `timeout_seconds`，缺省/空值为无超时。表单使用数值和秒/分钟/小时单位，保存为整数秒；拒绝零、负数、非整数秒和安全换算溢出。具体数值校验必须同时满足 JSON 数值与运行时计时表示范围。非托管保存时归一为空，重新改为托管默认无超时。
- 运行中禁止编辑、删除和切换类型，包括启动准备、停止和日志收尾阶段；后端校验为权威，前端禁用相应操作。脚本文件在应用外被修改不属于注册编辑锁，运行记录保留已使用的配置快照。
- 配置去重包含执行类型，托管还包含超时等影响执行语义的设置；托管的窗口字段归一为后台。相同配置的新注册可合并名称，保留目标命令的执行记录；涉及已有托管命令 ID 消失的编辑合并明确拒绝，避免隐式丢失日志或改变互斥归属。
- 显式升级注册 schema，旧记录迁移为非托管；旧程序遇到新 schema 应拒绝读取，避免把托管误当独立启动。配置变更仍使用库修订和命令修订。

## 身份、并发与状态

命令 ID 是互斥和记录归属单位；主名和别名共用一个执行槽。不同命令可同时运行，包括同一路径但参数不同的注册。托管执行不占用任务引擎的全局执行槽。

每次被接纳的执行生成独立 `run_id`，保存命令 ID、配置修订及快照、开始/结束时间、超时预算、执行阶段、结果原因、退出码和日志完整性。列表原有 `state` 表示文件可用性，应另设运行状态字段，不复用同一个枚举表达两类事实。

平台完成证据区分正常退出、信号终止/其他异常和结果未知。退出码为可选字段，仅自然正常退出且退出码为 0 才满足脚本成功条件；POSIX 信号终止不得伪造为正常 0，也不统一编码成未经声明的 `128 + signal`。平台原始码/信号可附作诊断，业务结果仍使用公共 succeeded/failed/interrupted 及停止原因。时间戳使用平台无关的 UTC 表示，持续时长独立于日历时间。

| 情况 | 展示 | 持久化语义 |
|---|---|---|
| 从未执行 | `[托管]`，无执行结果 | 无最近执行记录 |
| 已接纳且尚未收尾 | `[托管] 正在执行` | 内部可区分 starting/running/draining；不声明业务健康或百分比 |
| 已接纳停止请求，尚未完成清理 | `[托管] 正在停止` | stopping 是过渡阶段，记录停止原因，仍禁止启动 |
| 自然结束、入口脚本退出码 0，日志保存成功 | `[托管] 执行完毕` | succeeded |
| 非零退出、启动失败、超时或托管基础设施失败 | `[托管] 执行出错` | failed，保存具体原因 |
| 用户强制停止或节点退出引起停止 | `[托管] 执行中断` | interrupted，区分 user_stop/node_shutdown |
| 异常退出后发现未完成记录 | `[托管] 执行中断` | unexpected_shutdown；详情标明最终脚本结果未确认 |

正常成功/失败按入口脚本退出码判定，stderr 有内容不改变状态。脚本负责汇总其调用程序的结果并返回适当退出码。手动中断、超时等控制原因优先于强制终止产生的退出码，不能把中断误报为普通非零失败，也不能被随后收到的 0 覆盖。日志完整性是独立字段；已有中断或超时原因不被附带的日志清理错误覆盖。

互斥覆盖预检查后的启动接纳、实际运行、停止和最终日志提交；只有确认进程树结束且收尾完成才释放。重复启动、过期修订等拒绝不替换最近记录。预检查通过并接纳新执行后，新的启动失败也属于最近一次执行。日志文件准备失败、执行尚未被接纳时保留旧记录并返回启动错误。

## 统一停止流程

手动中断、执行超时、节点退出和捕获/存储故障使用同一个运行控制器，分别传递 `user_stop`、`timeout`、`node_shutdown`、`log_io_error` 等原因，不为每个入口建立另一套进程控制逻辑。

1. 校验命令 ID 和 `run_id`；定位后端持有的不透明执行对象，不按裸 PID 或进程名终止。Windows 对象内部持有进程/Job 句柄。
2. 在每次执行的串行状态转换中检查是否已结束或已在停止；已结束返回权威结果，同一次停止重复投递返回同一状态。
3. 锁定首次有效停止原因并记录停止意图，停止继续启动子流程，调用平台强制终止。持久化故障要报告，不能阻止必要的进程终止；无法落盘的原因在恢复时按未完成记录处理。
4. 确认受管进程树实际结束，继续读取管道中已有输出，完成日志和终态持久化，释放本命令执行槽。

完成、手动停止、超时、退出和 I/O 故障均经同一状态机仲裁：已确认的自然完成保持结果；停止原因一旦被接纳，后续退出通知不能改写它。超时判断使用执行所属预算，迟到计时回调和旧窗口请求只能命中原 `run_id`。每次终态只提交一次，测试必须覆盖不同事件顺序。

公共停止对象是本次执行的完整受管范围，入口脚本退出但受管后代仍运行时保持执行占用。手动停止直接强制终止，不先发送交互式 Ctrl+C，也不提供暂停/恢复。Windows 使用每次执行独占的 Job Object 和创建时绑定，持有进程句柄，不允许普通子进程脱离，停止与超时作用于整个 Job。通过其他系统服务间接启动的进程不属于本功能的托管保证，脚本应等待其业务子进程并汇总结果。后续平台必须验证自身的受管范围、退出确认和宿主死亡清理能力，不能仅以根进程已退出报告整个执行结束。

终止 API 返回只表示请求已发出；确认进程树退出前不得显示中断完成或允许重启。清理等待必须有界，超过内部清理预算显示“停止尚未确认”并保留占用，继续核对，不伪造终态。内部清理预算与用户配置的执行超时分离。Windows 强制终止可能等待尚未完成的 I/O，见[进程终止说明](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-terminateprocess)及[Job 终止说明](https://learn.microsoft.com/en-us/windows/win32/api/jobapi2/nf-jobapi2-terminatejobobject)。

强制停止保留已经发生的文件等外部副作用，不执行回滚。已经写入重定向管道的日志继续收齐；脚本用户态缓冲中尚未写出的内容无法补回。日志窗口记录停止请求及实际结束时间，让用户区分停止动作和清理完成。

## 执行超时

- 超时属于命令注册属性，每次执行接纳时快照固定；不动态修改运行中的预算。
- 计时从受管进程获准开始执行开始，包含等待子进程和正常 I/O 等运行时间；启动前校验与日志窗口创建时间不计入。
- 按整次执行总时长判断，不按 CPU 时间、日志静默时间计时，也不因新输出、隐藏窗口或切换页面重置。
- 采用包含系统睡眠/休眠时间的经过时长；睡眠期间不唤醒系统执行终止，恢复后立即复核，到期则停止仍在运行的执行。计时适配使用不受手动调时/时间同步影响的时钟，Windows 可使用 `QueryInterruptTime` 类计时；计时器只负责唤醒复核，不能单靠一次 `time.After` 推断跨睡眠预算。依据见[Windows interrupt time](https://learn.microsoft.com/en-us/windows/win32/sysinfo/interrupt-time)。
- 受管进程树确认退出后停止执行计时，日志排空与持久化适用单独收尾预算，不把脚本按时结束后的慢磁盘写入标为执行超时。完成/到期边界按统一状态机仲裁，不承诺实时系统级别的截止精度。
- 超时锁定为 `failed/timeout`，强制停止整棵受管进程树，保留截至结束的日志，详情显示配置时限和实际耗时；不重试，不自动重新启动。
- 无超时允许长时间运行；用户可通过停止按钮中断。

## 节点退出与恢复

运行管理器归节点主进程持有，与快捷输入宿主和日志宿主的窗口生命周期分离。关闭或重建任一 UI 不停止脚本、不重置预算。

接入现有应用 `RequestStop`/`Close`：退出检查包含托管命令，统一关闭命令启动/配置变更准入，再对活跃执行发出 `node_shutdown`，等待进程清理和日志持久化，最后释放存储及宿主。既有退出确认链路使用托管忙状态；取消退出不得导致一部分服务已关闭准入。已经确定的 timeout/user_stop 等原因不被退出覆盖。

现有 IPC 启动请求的短 context 仅限制准入处理，不能成为脚本生命周期或用户超时。接纳后运行、计时和日志由节点级运行控制器接管，UI 请求结束不取消执行。

节点崩溃后的受管进程收回归执行后端负责，Windows 使用 kill-on-close Job。其他平台须分别验证宿主死亡时的清理机制，不能把正常退出回调当作崩溃保证。重启恢复从日志和元数据核对终态、停止意图与未完成记录。无终态且无法确认脚本结果时显示执行中断及未确认原因；若已有可靠的 timeout 等停止意图则保留该原因。旧进程清理未确认时拒绝同命令再次启动，由对应后端使用含创建/启动代次的身份核对，避免 PID 复用；平台恢复证据不可理解时保留未知，不猜测、不终止外部进程。任何恢复都不自动重跑，进程结束也不表示外部副作用已撤回。

## 最近一次日志与持久化

注册配置继续使用 `local-commands.json`；最近执行元数据和追加式日志置于节点数据目录下独立的命令运行区域，按稳定命令 ID 归属。配置修订不因日志输出或状态刷新而改变。

- stdout/stderr 分别并发读取，分块处理无换行和超长行；记录流来源、单调递增的帧位置、接收时间与原始字节。保证各流内部顺序，合并视图按接收顺序显示。
- 日志先进入持久化路径，再供窗口增量补读；窗口关闭或消费缓慢不停止捕获。采集、写盘、传输及 DOM 均使用有界缓冲；磁盘保存完整本次日志，不套用任务执行器的 1 MiB 截断，也不静默丢弃旧片段。
- 磁盘不足或捕获失败触发托管失败和进程清理，保留可恢复部分，标记 `log_complete=false`。元数据写盘失败必须报告，不返回虚假的保存成功；恢复时保留异常数据以供读取和诊断。
- 每个命令只保留最近一次执行。替换时使用独立 `run_id` 与原子发布，避免旧读请求读到新内容；事务临时文件在恢复后清理，不形成历史备份。拒绝的启动请求保留原记录。
- 日志按 `command_id + run_id + cursor` 分块读取。旧 run 的请求在被替换后返回明确的代次变化，不把新的字节拼到旧日志。记录完成、删除或切换类型时使相关窗口及缓存失效。
- 正常完成后能从首字节读到末尾，关闭/重开和节点重启后结果一致。中断和超时同样能读到捕获的完整前缀及管道尾部。崩溃/断电只保证可恢复的已落盘内容，并说明结果或日志完整性未确认。
- 默认只渲染纯文本，不把脚本输出当 HTML、Markdown、链接操作或控制指令。每个日志帧持久化两条流在 UTF-8、GBK、Big5、UTF-16 LE 下的有限解码上下文及 BOM 状态；GBK 按浏览器[Encoding Standard](https://encoding.spec.whatwg.org/#gb18030-decoder)的 GB18030 解码状态处理四字节前缀和无效序列重消费。随机翻页先恢复上下文，顺序增量读取沿用解码器，跨帧和跨页残字节均可续接。输出编码选择、PowerShell 5.1 重定向格式及中文代码页通过真实 fixture 确定默认策略，保留显式编码选择能力，不按单个数据块猜测编码。
- 管理结果、停止原因和系统事件保存国际化键/参数；原始脚本输出不翻译。日志不进入模型、聊天历史或远端协议。

托管改为非托管时，控件旁提示“保存为非托管后，将删除该命令最近一次执行日志和结果”，不增加确认弹框；仅改变尚未保存的选择或取消编辑不删除。正式保存时清理结果和日志，删除注册也做同样清理，保留原脚本。命令变更锁、持久清理意图及恢复逻辑协调配置提交和文件删除；关闭日志读取句柄并使窗口内容失效，成功响应需确认清理完成。配置中的 `pending_cleanup` 与类型变更或删除原子提交；逐个清理完成后才移除该列表。即使运行目录中的删除标记发布失败，配置仍保留清理意图；重启及再次改为托管前先完成清理，失败明确报错并继续阻止恢复旧记录。

## 独立日志窗口与操作入口

日志窗口是 Asterhand 的独立顶层桌面窗口，使用项目主题、字体和国际化资源，具有应用图标、系统窗口切换入口、拖动、大小调整及平台提供的放大/最小化能力。Windows 首版使用 WebView2、任务栏和最大化/最小化窗口；未来平台的窗口和渲染后端独立选型，公共 UI 不直接依赖 WebView2。它不是命令行窗口、浏览器标签页或快捷输入内嵌区域。

独立非提权日志 UI 宿主管理多个窗口，与快捷输入 UI 进程隔离；按需启动，无窗口时释放资源。每条命令最多一个日志窗口，重复打开激活已有窗口，不同命令可以同时查看。宿主重建后从节点读取权威状态和日志，不持有执行锁、进程句柄或节点凭据。

快捷列表和 Web 注册列表均显示类型及运行状态，提供查看日志和停止入口；日志窗口也提供停止按钮。停止请求携带命令 ID 和当前 `run_id`，按钮明确表示强制停止，直接执行，不新增确认弹框。过渡期按钮禁用并显示正在停止；回执未知时读取权威状态，不推断停止成功，也不发送无代次的停止请求。停止、查看日志和执行是独立点击区域，停止操作不冒泡触发启动，Enter 不随运行状态改成停止动作。

启动时不自动弹窗。日志窗口顶部显示名称、状态、开始/结束时间、耗时、超时设置及退出码/原因，正文区分 stdout/stderr；默认跟随末尾，向上滚动后暂停跟随，可回到最新。大日志使用固定大小分页与有限 DOM 窗口，提供最早/上一页/下一页/回到最新，所有历史片段均可访问。窗口关闭只关闭查看界面；重新执行时已打开窗口明确切换到新 run，清空旧视图并显示新的开始时间。

通过窄 IPC 增加状态读取、日志分块读取、打开窗口和停止能力；HTTP 管理入口复用本机会话、Origin/CSRF，并对停止/打开窗口使用受保护的 POST。仍不增加 HTTP 启动、模型调用或远端执行路由。UI 不提交 PID、原生执行句柄或任意磁盘日志路径。消息协议与传输介质分开，继承句柄、文件描述符或本机连接的建立由平台宿主启动器负责。日志页同时限制为最多 64 帧、32 KiB 原始字节，并计算元数据、base64 与逐帧 JSON 开销，保持响应低于 96 KiB，留出 128 KiB IPC 帧的封装余量。宿主限制读取 worker 数，拥挤时按请求返回 busy，停止请求使用独立容量；合法并发不关闭宿主。页面在翻页和定时刷新交错时保持后续轮询，显示窗口同时限制字符数和 DOM 节点数。

## 平台边界与最小接口

### 公共核心和依赖方向

公共核心负责注册业务规则、每命令互斥、run 身份、状态仲裁、停止原因、超时预算、日志存储格式与读取游标。平台通过应用装配层注入窄接口；只有装配层及平台文件选择实现。运行控制器不导入 `quickinput`、Windows API、具体 WebView 或任务执行器，也不散布 `runtime.GOOS` 分支。Windows 代码按构建标签隔离，macOS/Linux 首版提供明确 unsupported 的适配入口；不提供看似成功的空停止实现。

以下为设计级接口职责，具体 Go 类型在实现时按消费者最小需要定义；不引入插件发现、通用 DI 框架或万能 Platform 对象。

| 边界 | 公共契约 | 平台私有内容 |
|---|---|---|
| `CommandPolicy` | 脚本种类/窗口模式能力、路径与参数校验、规范化执行配置及路径等价判断 | Windows 扩展名、UNC/设备路径/ADS、批处理引号；未来 Unix 解释器、执行权限及文件系统路径规则 |
| `ExecutionBackend` / `Execution` | `Start` 接收脚本路径、参数数组、工作目录和非交互要求；返回双流读取端、开始时点与不透明执行对象；提供幂等 `ForceStop`、可取消等待的 `Wait`、结束后资源释放及基于证据的 `Reconcile` | Job/进程句柄、令牌、环境构建、原生参数转义；未来进程组/监督机制/系统能力 |
| `ExecutionClock` | 读取含睡眠的单调经过时长、安排可取消唤醒/恢复复核；日历时间只作显示和记录 | Windows interrupt time；其他平台相应计时和恢复通知机制 |
| `LogWindowHost` | 按命令 ID 打开/激活/关闭窗口、主题/语言更新和宿主状态；窗口通过公共消息读取日志/停止当前 run | WebView2/COM/HWND、前台授权、DPI/任务栏；未来平台的渲染器、Dock/窗口管理器与主线程规则 |
| `HostTransport` / 页面 bridge | 有界双向消息、来源/版本/代次验证、关闭通知；页面只使用 `send/subscribe` | Windows 继承管道句柄和 `chrome.webview`，未来平台的端点继承及页面原生桥 |
| 日志存储文件操作 | 复用共享日志格式与 RunStore，仅把原子发布、同步、私有目录保护及清理的必要系统差异放入窄文件操作函数 | Windows ACL/共享删除规则，Unix 权限/目录同步及文件系统差异 |

`Start` 成功表示该执行的管理关系已在用户脚本运行前建立；脚本很快结束也必须返回可观察结果，不能丢失完成事件。接纳 context 结束只取消未交接的启动，不能让已创建进程失去所有者；失败返回须清理已创建资源，清理未知则保留管理对象并阻止重启。平台可以采用不同原生创建步骤，公共层不要求“挂起线程后 ResumeThread”这一 Windows 操作序列。

`ForceStop` 请求终止整次受管执行；停止意图和业务结果由公共核心确定，后端只返回执行证据。`Wait` 的完成必须覆盖受管范围已经静止，而非仅根进程退出；日志读取端继续供核心排空。等待 context 超时表示此次等待结束，不释放占用或隐式终止进程。平台执行句柄和证据的拥有者、关闭次序在 adapter 内统一，不向 UI/公共模型泄露 `exec.Cmd`、HANDLE、Token、PID/PGID 或信号发送入口。

恢复数据使用带平台/格式版本的不透明身份记录，保存在执行元数据中且由本机对应后端校验；UI 只见命令/run 身份和结果。平台原生错误归一为稳定业务错误码和国际化参数，原生错误附作诊断，不参与公共状态判断。注册记录属于当前节点，不承诺把 Windows 路径复制到另一平台即可执行。

### 注册策略、计时和能力声明

[命令模型](../../internal/localcommands/command.go)将 `.bat/.cmd/.ps1` 限制、ADS 检查、批处理参数禁引号和路径比较委托给 Windows `CommandPolicy`，公共层保留名称规则、字段容量、类型/超时、ID/修订和互斥逻辑。保留现有 Windows 行为；命令名大小写不敏感仍是产品规则，路径大小写比较则由所在文件系统/平台策略决定，不预设整个 macOS 都不区分大小写。

参数始终保持独立 argv 数据，平台在启动边界生成原生调用；解释器来自受支持的本机策略，不通过 UI 放开任意 shell 表达式。输出默认编码及宿主特有输出格式由后端提供元数据，公共日志保留字节和分块解码契约，不将 Windows 代码页规则固化到存储格式。

计时接口在所有平台都要求含睡眠且不会因日历调时倒退。Windows 实现使用 `QueryInterruptTime`；Linux 的 `CLOCK_BOOTTIME` 和 macOS 的连续计时源仅为后续适配依据，尚未接入。不同平台计时器/电源通知负责唤醒复核同一预算；单调时点不跨系统重启使用。依据见[Linux 时钟语义](https://docs.kernel.org/core-api/timekeeping.html)和[Apple 连续时钟](https://developer.apple.com/documentation/kernel/1646199-mach_continuous_time)。

能力与当前可用性分开：声明受支持脚本类型、非托管窗口模式、完整受管停止/宿主死亡清理、所需计时语义和独立日志窗口；启动前探测当前身份、会话、桌面/依赖及权限。所有托管执行必需能力齐备后才接纳，缺失明确报告原因，不自动降级为非托管或只停止根进程；不配置超时的执行不设置执行截止时间；控制器仍定期复核停止等待状态。日志窗口能力独立暴露，窗口不可用不改变已运行脚本的状态，其他可用入口仍能停止。前端根据能力呈现类型、时间及文件选择过滤，不用 OS 名称分支拼接口。

### 后续平台接入边界

现有[Unix 任务执行辅助](../../internal/executor/process_unix.go)采用进程组和 SIGKILL；它只能作为实现线索，不能证明符合本功能的受管后代范围、宿主崩溃收回和可信退出确认契约。未来 Linux 可以调研具备权限前提的 cgroup/监督能力，macOS 必须独立验证监督与进程生命周期方案；本轮不锁定实现、不安装新服务，也不声明进程组天然等价于 Windows Job。Linux cgroup 树的终止与空状态机制参见[内核文档](https://docs.kernel.org/admin-guide/cgroup-v2.html)。任何适配如果无法满足必需保证，保持该能力不支持；降低产品保证须作为单独设计决定。

桌面 HTML/CSS/日志视图、国际化和消息模型可复用，页面通过注入 bridge 访问原生能力，不直接调用 `window.chrome.webview`。窗口 UI 线程模型、渲染引擎和应用打包按平台实现；STA 只属于 Windows。公共窗口契约表达“可从系统窗口入口找回、用户可调整尺寸”，任务栏、Dock 或窗口管理器细节留在平台层。复用现有[宿主窄接口](../../internal/quickinput/host_process.go)与[页面桥隔离](../../internal/quickinput/assets/webview2-bridge.mjs)的做法，不把日志宿主变成快捷输入控制器的附属模块。

安装按[目标注册表](../../packaging/release-targets.json)提供对应宿主可执行物/应用包、运行依赖和完整性元数据；公共包校验依据组件身份和目标信息，不写死 `.exe`、WebView2 或 PowerShell 安装步骤。Windows 当前产物和安装流程保持原要求，macOS/Linux 仍禁用发布，接入后独立完成权限、进程、窗口、睡眠、文件耐久性和安装验收。

## 模块与实现接线

| 模块 | 计划职责和现有入口 |
|---|---|
| 注册库 | 在[命令模型](../../internal/localcommands/command.go)和[注册库](../../internal/localcommands/registry.go)扩展类型、超时、迁移、去重和运行期变更保护；将脚本/路径/参数系统规则委托给 CommandPolicy |
| 运行控制器 | 在 `internal/localcommands` 内新增按 run 管理的准入、状态机、停止、计时和收尾职责；[现有服务](../../internal/localcommands/service.go)负责分派两类启动 |
| 平台执行适配 | 注入 ExecutionBackend 与 ExecutionClock；Windows 保留[非托管启动器](../../internal/localcommands/launch_windows.go)，新增受管进程/Job/管道实现，借鉴[宿主创建时绑定](../../internal/quickinput/host_process_windows.go)及[普通用户令牌](../../internal/quickinput/host_token_windows.go)，仅提取相关低层能力而不让核心依赖整个 quickinput |
| 执行记录 | 独立元数据、追加日志、分块读取、替换/删除与恢复；不把原任务数据库的预算和恢复语义强加给本地命令 |
| 应用生命周期 | 接入[退出准入](../../internal/app/lifecycle.go)和[应用装配与 Close](../../internal/app/app.go)，统一停止与等待；避免在持有全局锁时等待进程或磁盘 |
| API/IPC | 扩展[管理 API](../../internal/app/commands_api.go)、[命令协议](../../internal/localcommands/wire/protocol.go)与独立日志宿主协议，保持来源校验和有界能力 |
| UI | 扩展[注册表单](../../web/local-commands.mjs)和[快捷列表](../../internal/quickinput/assets/command-ui.mjs)，新增平台无关日志视图与 LogWindowHost/bridge，首个后端为 Windows/WebView2，不复制整个聊天控制器 |
| 构建安装 | 日志宿主及资源接入[应用构建](../../scripts/build-application.ps1)、包校验、版本/源码摘要、快速本地安装、国际化守卫和许可分发 |

日志宿主与各脚本执行具有独立管理范围，Windows 分别使用不同 Job，UI 崩溃不终止脚本。不直接复用任务执行器的 `startManaged`：其启动顺序和运行时假设服务于现有模型执行，任意脚本需要在首次执行前完成平台要求的归属绑定、身份校验和管道设置。

## 待验证技术点

设计不以这些点已通过为前提：普通/管理员节点下的受限令牌与标准句柄继承、父子进程全部退出确认、Windows 睡眠后的超时复核、PowerShell 5.1 输出编码、日志故障恢复与独立多窗口资源释放。具体测试入口和验收矩阵见[功能计划](../development/features/managed-local-commands/plan.md)。

平台边界通过公共核心的替身契约测试及导入/构建约束验证；macOS/Linux 交叉编译只验证接口隔离。后续平台的真实进程托管、UI 引擎与权限行为在其适配交付中单独验证，本功能的 Windows 验收不扩大其他平台支持矩阵。
