# 本地命令执行、日志与恢复

所有命令由节点管理；不存在非托管类型。注册和图分别见[本地命令](local-commands.md)、[脚本图](script-graphs.md)。实施及验证见[统一命令计划](../development/features/unified-command-runs/plan.md)，决定见[统一命令 ADR](adr/006-unified-command-runs.md)。Windows 为首个后端，其他平台未验收前不启用。

## 身份与接纳

命令 ID 归集配置和日志，主名及别名共享限制。每次接纳有独立 run ID、单调接纳序号和配置快照；每个脚本节点执行另有独立执行 ID。不同命令即使图内容相同仍独立，不自动合并。文件可用性与执行状态分开。

allow_concurrent 默认 false，同命令从接纳、准备、运行、停止到日志收尾保持互斥；true 允许多个实例，最多 8 个活跃实例/命令、本机最多 32 个活跃实例。超限拒绝，不建立命令启动队列。图节点等待共享执行名额按脚本图设计处理。恢复清理未确认的命令拒绝新接纳，即使允许并发。存在任一恢复未确认的节点时暂停本机新脚本节点调度，其他命令可在实例容量内接纳并显示等待；全部确认后恢复调度，避免旧进程与新脚本合计超过八个名额。配置编辑和删除要求该命令所有实例都已结束。

每实例独立保存开始/结束时间、经过时长、阶段、结果、原因、日志完整性和节点事实。starting/running/stopping/draining 为活动阶段；succeeded/failed/interrupted 为结果。入口正常退出码 0、受管范围全部退出且日志保存成功才满足节点成功条件；stderr 不决定失败。图汇总所有节点结果。未知结果明确标记，不能伪造退出码。

## 统一停止流程

用户停止、超时、节点退出和存储/捕获失败都进入本实例状态机。停止请求指定 command ID 与 run ID；持久化停止意图后强制停止该实例所有活跃节点，确认进程范围结束、排空日志、保存终态后释放占用。重复停止幂等，已结束保持事实；首次已接纳的停止原因不被后续退出码或关闭原因覆盖。停止未确认显示 cleanup_pending，继续核对。

停止全部必须携带点击时的 run ID 集合（最多 8 项），后端先校验全部身份再执行，集合之外的新实例不受影响；已结束且仍保留的实例返回其结果。旧轮已清理的 ID 返回明确过期错误，不用最新实例替代。停止和启动在管理器锁下决定接纳顺序。

图内失败采用 abort，只停止本实例，其他实例继续。超时为 failed/timeout，用户/节点关闭为 interrupted/user_stop 或 node_shutdown。强制停止不回滚文件副作用；系统服务间接启动的进程不在受管保证内。Windows 每个脚本节点用创建时绑定的普通用户 Job，不允许普通子进程脱离；入口结束但后代尚存仍占用名额。

## 超时与节点退出

整图超时从执行管理器接纳后调度开始计算，包含依赖及共享名额等待；节点超时从进程开始计时。包含睡眠/休眠，使用不受日历修改影响的时钟，恢复后复核；已确认进程结束后的日志排空使用独立预算。默认无超时，不自动重试。

节点主进程拥有执行和日志，与快捷输入、日志窗口生命周期无关。退出先关闭启动和配置准入，再停止全部活跃实例并等待收尾。UI 请求 context 只约束准入，不持有执行生命期。窗口关闭/重建不停止脚本。崩溃通过平台监督收回进程，重启逐个核对所有已发布未完成节点身份；保留已知停止原因，否则 unexpected_shutdown，日志完整性未确认，不续跑、不按裸 PID 或进程名清理。

## 当前轮次与最近记录

同命令从首次接纳到全部实例结束构成一次连续运行，结束后保留记录的期间仍属于该轮；全部实例完成后下一次成功接纳才开始下一轮。在同轮内追加实例不会删除此前结果。最近记录由最后接纳顺序确定，不能由时间戳或结束顺序推断。旧实例晚结束只能更新自己的记录。

当前轮全部日志和结果保留可读，包括已结束实例。仅最后接纳者作为最近记录；其他是延迟清理的临时记录，正常重启也保留到下一轮，避免重启成为额外删除触发点。删除命令会清理全部命令运行数据，保留脚本文件。

运行区按 command ID 保存 current.json 索引（版本、轮次、顺序 run ID 列表和最近 ID），每个 run 用自己的 JSON 与追加日志。新记录和空日志先持久化，再原子发布索引；索引成功就是接纳点。新轮发布后清理上一轮。任何接纳前失败保持旧索引和旧日志；接纳后进程创建失败也成为最近记录。清理失败保留明确待清理状态、阻止继续接纳，并在重启或下次操作重试，不撤回已经发布的实例。恢复只执行索引公布的记录，不把未发布文件当作已运行实例；清理未引用残留时只处理已知命名和类型的文件。

每轮最多 64 个实例；达到上限时拒绝继续追加，已有实例正常完成，全部结束后可开始新轮。每实例日志最多 256 MiB、同命令当前轮合计最多 1 GiB（包含帧开销）；达到输出预算时停止导致超限的实例，保留已捕获前缀并标记 failed/log_limit、log_complete=false，不静默截断，也不主动联动停止其他实例；共享轮预算耗尽后，其他实例如再次输出则各自触发相同失败，不再输出者仍可正常结束。日志预算属于执行监督故障，整图直接记 failed/log_limit，导致超限的节点同样保留 log_limit。已有数据达到轮预算时拒绝新接纳；下一轮有新的预算。磁盘 I/O 故障采用同样的可见失败与清理流程。

终态写盘失败保留实例占用与错误状态并重试收尾，不把未持久的终态当作允许修改配置或删除恢复证据的条件。删除注册时持久 pending_cleanup 意图与配置原子提交，重启先完成清理；清理失败报告并保留恢复信息。

恢复遇到损坏记录、索引或缺失日志时，报告错误并禁用新接纳，继续检查其他记录和命令；已验证的节点执行身份仍需核对和收尾。缺失日志不使已验证的进程身份失效。装载失败的组保留原索引及所有文件，不对部分装载结果执行旧文件回收；未知身份不猜测、不重新启动。

## 日志读取与窗口

stdout/stderr 并发采集并追加原始字节，帧包含节点来源、流、接收时间和有限解码上下文；每流内部有序，合并表示采集顺序。合并分屏按行而非按帧标注来源：程序常把一行文本和换行分成两帧写出，其他来源可能插在中间；每个来源（节点 + 流）各自维护未结束的行，被其他来源打断后在新行带来源标签继续，只用于结束该行的换行不再显示为空行。标签直接写入每个数据块的文本，DOM 元素数量仍按数据块计，受每页帧数和字符预算约束，不随行数增长。原始字节不变。关闭窗口不停止写盘，任何缓冲和 DOM 都有界。保留 UTF-8、GBK/GB18030、Big5、UTF-16 LE 解码和 BOM 处理，独立分屏/分页恢复各节点解码状态。

预算耗尽或存储故障后，管道排空仍可能读到尚未保存的输出。每个实际丢弃字节的节点及整图都标记日志不完整，节点分屏也必须显示缺失提示；保留最先确认的停止原因。

读取绑定 command ID + run ID + node ID（可省略表示本实例合并）+ cursor。旧轮被清理后返回过期，不拼接新日志。每页最多 64 帧、32 KiB 原始日志，整个 IPC 响应小于 96 KiB，为 128 KiB 帧留余量；节点筛选每次最多扫描 1 MiB/4096 帧，允许空页推进。状态列表只传有界运行摘要，详细节点状态按 run ID 单独获取，不把 64 个最大图快照打包进一次响应。

每命令一个独立日志窗口，关闭隐藏并暂停刷新；沿用最多四个隐藏窗口、十六个创建/清理中窗口，以及[异步初始化与定位](adr/004-log-window-reuse-and-initialization.md)。启动不自动弹窗；打开或重开读取当前轮全部实例。每次打开（新建、复用或从最小化恢复）都先确认窗口已显示，再请求成为前台：从快捷面板打开时，发起点击的面板宿主先放行前台切换，日志窗口直接成为前台；从浏览器打开时请求经节点服务转发，Windows 可能拒绝激活，此时窗口保持显示并闪烁任务栏，直到用户切换过去。不通过关联其他线程输入队列强行激活，避免前台程序卡住时日志窗口线程随之阻塞。

查看方式为“全部 / 运行中 / 自选”三段切换：全部显示所选实例的合并日志；运行中按运行实例/节点稳定顺序自动展开前 8 屏；自选时点击节点切换显示，可跨实例固定最多 8 屏，固定选择不会被新实例覆盖，达到上限时提示。只有一次运行时不显示实例选择。每屏独立分页、滚动和跟随：默认跟随最新输出，用户向上滚动后暂停并浮出“回到最新”，页首/页尾按需提供“更早的输出 / 后续输出”。编码为窗口级设置，作用于所有分屏，各分屏仍独立恢复解码状态。运行中分屏可停止本次执行，停止节点分屏同样停止所属整图。无活跃节点时“运行中”明确显示空态，完成记录仍可自选。

新实例出现不重置既有屏，主题/语言切换保留选择和阅读位置；新轮清理后使旧轮缓存失效，默认显示新实例。列表汇总活跃数、失败/中断数及最近结果，最新成功不能遮蔽其他仍在运行或失败的实例。列表停止全部与日志/启动区域独立，Enter 始终为启动。IPC 与 HTTP 沿用本机认证、Origin/CSRF 与窄能力，不接收 PID、任意路径或执行字符串。只渲染纯文本，不执行日志中的指令。

## 平台边界与最小接口

CommandPolicy 验证本地脚本与参数；ScriptSpec 只描述某脚本节点的启动信息，不带命令类型。ExecutionBackend.Start 返回持有整次节点受管范围的 Execution，提供输出、Wait、ForceStop、Close；ExecutionClock 提供跨睡眠经过时长。Windows 负责普通用户令牌、固定系统解释器、Job、句柄和文件替换，公共调度不依赖 UI。

交互能力用可选接口表示：执行对象声明是否支持文本输入，支持者提供带 context 的写入及关闭输入；未来终端能力独立提供尺寸/控制，输出描述区分双流文本与终端流。当前只提供非交互、关闭 stdin、无控制台、双流文本；不实现空的输入方法，不开放输入协议或 UI，不启用终端。未来输入必须绑定具体节点执行身份，设有界排队、取消和重复请求保护，不随窗口重建重发，输入默认不写入日志。等待输入仍占用执行名额并继续计时，改变该策略需另行设计。
