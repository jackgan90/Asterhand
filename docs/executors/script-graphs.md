# 本地脚本图设计

本地命令可关联单脚本或一个静态 DAG。图属于命令，节点配置独立保存；从其他单脚本命令复制配置不会建立实时引用。公共调度与 Windows 执行后端分离，首版平台与[托管命令](managed-local-commands.md)一致。

## 图与注册

注册 schema 3 增加 `kind=script|graph` 和可选 `graph`。旧 schema 1/2 迁移为 script，保留托管/非托管属性。graph 必须 managed，其顶层脚本字段归一为空；命令超时表示整图超时。图不按脚本路径自动合并，命令名称仍全库唯一。

图最多 64 个节点（含开始和结束）、512 条边。每个节点有稳定 ID、类型和显示坐标；脚本节点另有名称、脚本路径、参数数组、工作目录、可选超时和 `failure_policy=abort`。策略独立于执行结果，首版拒绝未知或其他策略。参数和路径使用现有平台校验，不接受 shell 表达式。开始/结束节点不运行脚本。

必须恰好一个 start、一个 end，start 无前置、end 无后继，至少一个脚本节点；每个节点都从 start 可达并能到达 end。拒绝环、自连、重复边、重复 ID 和不存在的端点。画布坐标只影响布局。服务端保存和执行时均校验；运行中禁止编辑、删除和切换内容类型。

脚本配置错误保留原始校验消息键及参数，并通过 `message_args.graph_node` 标识出错步骤。命令表单展示时组合步骤名称与当前语言的原因，切换语言仍能完整重译，不将本地化后的原因固化到配置错误中。

每次启动固定图和节点配置。注册不复制脚本及其依赖文件；外部文件仍由用户管理，运行期间不应改写。启动图前检查所有脚本及工作目录，每个节点实际启动前再次检查，缺失/不可用按节点启动失败处理。图只保证配置快照，不声称冻结外部脚本内容或隔离其他程序对文件的写入。

## 调度与结果

整图运行 ID、图内节点 ID 和节点执行 ID 分开。节点执行身份在创建进程之前持久保存，Windows 后端按其身份建立独立 Job。图调度器由主进程持有，UI 生命周期不影响运行。

start 在运行开始时成功；所有前置成功的节点进入 ready。图并发为 1—16，默认 4；本机所有图节点共享 8 个执行名额，不改变现有独立单脚本命令的并发规则。就绪节点按图中保存的顺序选取，名额不足继续等待；不承诺并行节点实际开始顺序或实时公平调度。节点超时从进程获准开始计时；整图超时从图接纳后开始，包含等待依赖/名额。均使用包含系统睡眠的单调时钟。

正常节点成功要求受管进程范围全部退出、入口退出码 0、日志捕获与保存完成。stderr 不直接改变结果。脚本自行等待业务子进程并汇总退出码；外部服务间接启动的进程不属于受管保证。

原始执行证据、节点结果和失败处理策略分开。首版任一节点失败即采用 abort：锁定失败节点和原因、关闭新启动准入、停止所有活跃脚本，未启动节点标为 skipped，连带停止节点记 interrupted/graph_aborted。已经成功的节点保留成功。根结果为 failed/node_failed，具体失败在节点记录中；用户取消和节点退出根结果为 interrupted，整图超时为 failed/timeout。日志/存储/执行监督故障不能被未来脚本警告策略忽略。

已经预留名额、保存节点执行身份，但尚未交给执行后端的节点仍算未启动；此时接受停止也记 skipped。真正尝试启动后发生的启动错误保留 failed/start_failed。

停止与启动接纳、完成、超时在同一图状态锁下仲裁。发出停止不等于结束，直到所有受管范围静止且日志收尾完成才释放命令占用。失败时由控制器结束整图，不等待 end 满足依赖；end 在正常成功时完成，失败时 skipped。清理脚本、回滚和始终执行的 finally 节点不在首版范围。

未来可新增警告策略，但必须分别定义整图是否继续、失败前置是否满足后继条件，以及后继所需产物缺失时的行为。不能把失败事实改成成功，或仅加 ignore 布尔值就默认放行所有后继。

## 数据与恢复

边只表达执行依赖，不隐式传递变量、环境或 stdout。节点通过显式路径、参数和用户脚本管理的文件交换数据。无边不证明资源无冲突；同时修改同一文件/仓库时用户应串行连接。首版无资源锁和数据输出表达式。

命令只保留最近一次整图运行，包含所有节点结果和日志。重启核对全部已公布、尚未确认完成的节点执行身份；确认清理前仍禁止再次运行。已完成节点保留事实，未完成节点标记中断及结果未知，待执行节点不再启动。不自动续跑、重试或撤销副作用；重新运行生成新的整图和节点执行身份。

运行元数据统一限制为 4 MiB，保存前检查并在重开时有界读取；该容量覆盖 64 个节点、512 条边、最大路径和参数在 JSON 转义后的配置与节点结果。保存失败保留原记录，不允许先写出超限记录再在重启时拒绝读取。这个私有存储上限不增加 UI 或 IPC 的消息容量。

## 日志与界面

图日志在一次运行中合并追加，每帧带节点来源、stdout/stderr、接收时间和原始字节；各节点各流独立维护解码状态。合并顺序表示采集顺序，不代表并行脚本内部事件的全局因果顺序。分页恢复各节点解码上下文，兼容旧单脚本日志格式；持久元数据保留配置快照，UI 响应只携带有界的运行摘要。

日志页保留图内节点 ID，省略渲染不使用的平台节点执行 ID；完整状态和持久记录仍保留后者。分页预算包含运行摘要、base64 后的原始日志和本页实际出现节点的解码上下文；仅在整帧及其上下文都放得下时才推进游标。页响应小于 96 KiB，给 128 KiB IPC 帧保留封装空间；最大图与最大合法节点名称也必须能逐页读出全部日志。

独立日志窗口使用一个下拉面板选择查看模式：“合并全部日志”显示合并流；“自动展开运行节点”按节点分屏，仅显示 starting/running/stopping/draining 的脚本节点，finished 后移除；节点复选列表进入固定多选模式，已结束的选中节点仍保留。两种自动选项及固定多选互斥，取消最后一个勾选显示选择提示；没有活跃节点时自动模式显示空态。Start/End 保留状态展示，不进入日志选择列表。顶部整图结果和失败原因不随分屏移除。

分屏按图顺序排列为响应式网格，各自维护分页、解码、阅读位置和跟随状态；暂停一屏不影响其他屏。状态列表、选择项及分屏标题使用一致的状态颜色和文字，区分正常完成、失败、中断和未执行。切换语言/主题保留选择和阅读状态；新运行丢弃旧请求和缓存，恢复合并模式。每条命令仍只管理一个日志窗口，关闭窗口不停止捕获。

节点分屏按需从同一持久日志读取，不能只过滤当前合并页。`read_log`/`tail_log` 接受可选 `node_id`，仅允许当前运行的脚本节点；`read_log` 的 `before` 表示读取游标之前的节点页。游标仍为原文件字节偏移，上一页请求使用当前页起点，下一页使用结束偏移。每次最多扫描 1 MiB 或 4096 帧，受原始页/帧及 96 KiB 响应预算限制；扫描跨过无关节点时可返回空页及推进后的游标，前端分批继续寻找。节点页携带自身解码上下文，读取请求并发和分屏缓存均有上限，不改变日志格式和执行结果。

图编辑器位于 Web 命令表单，提供添加/删除脚本节点、可拖动节点、连线/删除连线、属性编辑及从单脚本命令复制配置。开始/结束不可删除，选中它们时隐藏脚本属性区域，连线操作仍按图规则可用；选中脚本时恢复属性区域。保存前显示图结构问题。仅快捷输入显式确认可以启动；不增加 Web、模型或远端启动能力。
