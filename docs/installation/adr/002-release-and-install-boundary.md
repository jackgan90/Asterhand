# ADR-002：版本化发布与安装配置分离

- 状态：accepted
- 日期：2026-10-25
- 替代：[薄引导与环境准备](001-bootstrap-and-setup.md) 中由 setup 同时准备环境与配置的边界。

## 决策

安装脚本从同一个固定 GitHub Release 下载清单和平台包，验证摘要、大小与组件健康后激活程序；所需 Microsoft VC++ x64 运行库和 Tailscale 从固定的供应商地址取得并检查摘要及签名。安装默认完成全部前置组件和原生模块加载检查后退出，不启动服务、不登录网络、不要求模型凭据。

发布由仓库内一个入口完成。平台注册表连接各平台构建器与安装入口，当前只发布 Windows 完整包。发布先建立草稿，上传并逐项校验附件，最后按请求发布 prerelease 或 stable。脚本不覆盖已公开的版本。单独测试仓库隔离开发期发布；GitHub Draft 是可见性状态，不是独立测试环境。

## 原因与后果

新节点不需要开发工具，安装与用户配置可以独立验收。平台包较大，但用户免于本机解析 npm 依赖；锁文件和许可证随包保存。Tailscale 为系统服务，仍需 Windows 管理员授权，其登录属于后续设置。

TLS、公开仓库和同一 Release 的摘要提供来源与传输完整性；尚未部署独立代码签名，不宣称摘要能抵抗发布账户被攻陷。

Linux/macOS 保留接入契约，启用前需要相应 builder、installer 与原生安装证据。运行时或 provider 升级仍遵守 [依赖维护流程](../../../packaging/upgrade.md)，发布流程不替代真实模型验收。
