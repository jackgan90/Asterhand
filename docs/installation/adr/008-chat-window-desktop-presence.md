# ADR 008：聊天窗口的桌面入口与原生移动

- 状态：accepted，实施与验证状态见[聊天桌面体验计划](../../development/features/chat-desktop-experience/plan.md)。
- 继承：[独立非提权宿主](007-quick-input-process-isolation.md)的进程、权限和恢复边界。
- 替代：原快捷输入/持续聊天的未固定失焦隐藏和无任务栏入口策略。历史原因保留在原功能文档，当前行为以领域设计为准。

## 决策

聊天窗口默认失焦保持显示，使用普通非置顶窗口行为，移除固定按钮。用户通过 Esc、全局快捷键或系统关闭窗口显式隐藏；隐藏不停止聊天、不退出节点。系统最小化保留运行入口，显式隐藏移除运行入口，后台回复完成不激活窗口。

复用现有 UI 宿主的唯一聊天窗口提供任务栏入口和应用图标，不创建代理窗口或第二个启动服务。系统入口负责激活/恢复，快捷键负责 toggle，两个动作分开。已有节点托盘继续管理节点，与聊天窗口生命周期独立。

标题的品牌/空白区声明为拖动区，交互控件排除；移动由系统原生窗口机制完成。平台实现负责工作区、DPI、用户位置与内容尺寸，首次放置和后续 resize 分开；本次宿主生命周期内记住各屏位置，不写入桌面设置或节点协议。

平台公共层只表达显示、隐藏、激活、拖动区域及有效布局语义。Windows 使用顶层应用窗口与 WebView2 非客户区支持；macOS 后续适配应用级 Dock 和原生激活；Linux 后续适配窗口管理器/合成器，不将 Win32 句柄、窗口样式、绝对移动或任务栏的逐窗口行为作为公共契约。未实现平台仍明确 unsupported。

## 原因与后果

失焦立即隐藏会使系统入口随之消失，阻碍在其他应用工作后通过任务栏返回聊天。显式隐藏让窗口与系统入口保持一致，减少“固定”模式的理解成本。原生拖动保留系统输入语义，避免前端高频桥接屏幕坐标；窗口边界仍由宿主限制。

新增任务栏可见性后，必须覆盖最小化、恢复、系统关闭、激活、Explorer 重建及宿主异常退出；显示器和 DPI 改变时保留可操作区域。桌面 OS 的入口粒度不同，应在未来平台实现时验证其映射，不通过公共层假定所有平台都有 Windows Taskbar。
