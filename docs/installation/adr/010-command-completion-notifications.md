# 010：本地命令使用独立桌面通知展示器

- 状态：accepted，实施与验证状态见[功能计划](../../development/features/local-command-completion-notifications/plan.md)。
- 适用：本地命令执行完成的桌面提醒，保留[非提权宿主](007-quick-input-process-isolation.md)的权限和同版本校验。

## 决定

采用随应用分发的自绘通知内容，以同一主题控制背景、动画与多个通知的排列。Windows 使用专用非提权宿主模式，与快捷输入和日志窗口独立；节点进程管理公共通知队列，运行管理器只发布完成事实，不依赖桌面能力。

平台接口传递有界展示数据、外观和用户操作，不暴露 Win32 句柄、路径或任意原生调用。macOS/Linux 后续实现该接口并分别验证；缺少展示器不影响本地命令执行和结果读取。

## 原因与后果

主题背景、进入/退出及补位动画需要由应用统一控制；系统原生通知的内容模板不能作为本功能的自定义渲染器。复用已有宿主与 WebView2 避免增加新的 UI 框架，等待队列不依赖网页计时器，多个调用入口共享同一行为。

应用负责工作区/DPI、可访问性、休眠/锁屏、不抢焦点、队列容量与故障恢复。卡片不进入 Windows 通知中心，不自动继承系统勿扰策略；此限制必须公开说明。运行事实留在既有存储，通知缓存不跨节点重启保存，避免补播旧结果。
