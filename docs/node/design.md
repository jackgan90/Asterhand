# 节点设计

范围：TLS 配对、本机登录、Tailscale 引导与可信元数据同步；平台和网络验证边界见 [支持矩阵](../testing/platforms.md)。

## 身份与能力

Node 保存稳定随机 node_id、显示名、endpoint、协议版本、能力和更新时间。凭据用于认证该身份，IP 和自然语言自称不能证明身份。

能力按组件声明：任务服务、OpenClaw 助手、文件工具、未来执行器。状态区分未安装、待配置、待登录、检查失败、就绪、暂不可用。仅真正就绪的能力接受新任务。

Peer 保存目标 node_id、地址、固定证书信任信息、credential_ref 与授权范围。配置不嵌入明文 key。

## 配对与 Web 信任

1. B 的本地已认证用户开启短期配对窗口，展示地址和一次性配对码。
2. A 用户添加 B，校验目标身份并确认授权范围。
3. 建立节点身份与证书信任的绑定，生成独立凭据；配对码过期失效，重试绑定相同握手请求；当前未实现配对速率限制。
4. 撤销 peer 后拒绝其后续访问，记录审计事件。已在 B 执行的任务按 B 本地策略处理，不把撤销直接当成已取消。

首次信任通过从 B 本机页面带外取得的邀请建立。邀请携带的证书是 A 的固定信任根，后续通信校验节点身份，不关闭 TLS 校验；完整契约见下文。

浏览器信任与节点间证书固定是两条链路：安装向导必须提供可用的本机 / LAN Web 访问方案和证书说明。不能默认手机或浏览器自动信任节点自签证书，也不能把“忽略证书错误”当作验收方案。

## 人工身份与 peer 身份

用户在本地 Web 登录；浏览器请求需要会话认证、CSRF / Origin 等基本校验。远端批准由 B 校验绑定用户、attempt、操作和有效期的授权证据。

A 的普通 peer token 不能直接声称“人类已批准”。远端审批需要独立的用户身份绑定和单次授权协议；该能力尚未实现，因此不开放。

## 项目与路径

project_id 映射由 B 本地维护。任务中的自然语言绝对路径先解析到已注册授权范围；未注册路径拒绝或请求本地配置，不自动扩大范围。

目录边界检查要处理相对路径、盘符、UNC、大小写、符号链接和 Windows junction。执行和读取产物时均校验最终路径，不能只靠字符串前缀。

首版提供用户会话内启动与可选登录后启动；开机未登录运行及桌面工具会话分离不作首版硬保证。Everything 等后续连接器按自身实际用户会话要求部署。

## 本机退出与托盘

本机快捷输入与任务配置分离。启动后异步准备独立 STA 面板，注册归托盘线程；冲突或面板错误不请求节点退出。节点进入停止屏障时先关闭桌面变更与呼出、终止录制；完成已接收请求及任务收尾后，在托盘消息循环仍可处理注销时释放热键和面板，再关闭存储并移除托盘。面板 WM_CLOSE 只隐藏，释放失败保留具体状态；不按进程名停止共享 WebView2。恢复与线程边界见[快捷输入方案](../development/features/global-hotkey-quick-input/plan.md)。

Windows 节点在当前用户交互会话内提供系统托盘，所有正常退出入口共享停止接收、取消运行上下文、关闭本机 Web 与 peer 服务、等待执行和持久化结束的过程。托盘退出在本机有在途执行时确认一次，退出期间保留“正在退出”状态，完成后移除图标。Web 停止、Ctrl+C 和注销/关机复用同一生命周期；系统会话结束不弹阻塞确认。锁屏不触发退出。

退出只停止 Asterhand 和其拥有的执行进程，Tailscale 与其他节点继续运行，身份、凭据和配对保留。其他节点通过既有周期探测观察离线；已关闭服务不再接受调用。启动器只承担启动，不作为额外常驻服务，托盘与节点同进程。桌面入口及系统消息支持见 [安装设计](../installation/design.md)。

## 可达性

保存最后成功通信时间与探测结果；UI 展示缓存新鲜度。探测失败不将远端 job 改为 failed，也不释放 B 的工作区占用。

标准跨 NAT 路径采用 Tailscale，install.ps1 检测已有客户端或引导固定版本安装和登录；不自建 NAT 穿透。管理员安装和窄范围防火墙操作分别提示，见 ADR-NODE-002。

## 信任与访问契约

Web 仅监听 127.0.0.1:17432；浏览器用启动链接中的随机 token 建立 12 小时 HttpOnly / SameSiteStrict 会话，写请求校验 Origin、CSRF 和 Host。远程设备不直接打开该 Web；B 上独立操作在 B 本机进行。手机远程访问入口尚未交付。

节点 API 默认监听 TCP 17433、TLS 最低 1.3。邀请包含 node_id、endpoint、自签 ECDSA 证书、一次性随机码和 10 分钟期限；A 从 B 本机页面带外取得邀请，以邀请证书为唯一信任根并校验 node_id，不跳过证书验证。可信邀请来源是首次身份确认前提。

握手重试绑定完整请求摘要；相同重试返回相同凭据，改变身份数据拒绝。已撤销 peer 不能用旧邀请恢复授权，新邀请才可重新配对。出站凭据和待握手凭据由 DPAPI 密封，入站仅存摘要。当前无配对速率限制或独立审计 UI；随机码不可枚举，仍应只向可信个人设备分享。

peer 授权针对本机 workspace 项目；只有任务 origin 能读取或回答该任务。普通回答记录 peer 身份，不提供远端人工审批；待核对关闭只允许 B 本机会话。撤销不终止已经接收的任务。

节点信息每次探测成功缓存状态和时间，离线可按最后配置排队；最终仍由 B 校验权限及启动期限。Tailscale BackendState/IPv4 用于配置建议，实际 HTTPS 请求决定在线状态。

## 配对元数据与监听

节点在线表示认证通信可达；`capabilities.chat` 和 `capabilities.model_tasks` 表示当前本地必要配置条件，字段为 available/code/detail，不承诺外部模型 API 在线。项目授权单独返回并在目标执行处校验。旧 ready 保持手动模型工具诊断通过的含义；新 UI 仅对没有 capabilities 的旧节点使用 ready 后备规则。离线缓存是最后确认条件，最终准入由目标节点决定。基础节点和配对不要求模型凭据，托盘显示节点运行状态。

公开能力诊断（`Availability`）、网络提示（`network.Status`）与节点 HTTP 错误响应在保留原有 `code`/`detail`/`error` 兜底文本的同时，可选附带 `message_key` 与非敏感 `message_args`，新旧版本跨节点通信天然忽略未知扩展字段并安全回退原文。全新初始化节点在 `config.json` 中记录 `name_default: true` 并按系统语言写入初始名称，未编辑名称保存其他配置时不清除默认标记；升级前已有配置一律保留原持久名称。内置 `"workspace"` 项目通过 `name_custom` 区分默认展示译名与用户自定义名称，保存节点设置时按项目 `ID` 保留既有自定义名称。

取舍见 [ADR-NODE-003](adr/003-verified-peer-metadata.md)。

节点探测在 TLS 固定证书之外核对响应 node_id；有效信息更新显示名。已配对节点每 20 秒向原 peer 地址发送本机 ID 与 endpoint 通知，接收方先校验已有 peer 凭据及声明 ID，再用原固定证书和原出站凭据回查候选地址。确认响应身份及公布地址一致后，仅在原记录上原子修改 name/endpoint；项目范围、密封 token、证书、撤销位均保留。不可达、身份不符、已撤销或验证途中证书变化均拒绝更新；双方同时失去可达地址仍需要用户重新配置或配对，不做全网发现。

节点信息探测与元数据回查使用 10 秒总时限，外层元数据通知使用 15 秒，容纳回查及往返开销。实机 Tailscale 冷连接曾出现 2.85 秒 TLS/HTTP 响应；旧 2 秒探测会误报暂不可达。时限内仍校验完整身份，超时保留最后确认信息并在后续周期重试，不将 Tailscale Connected 直接视为应用在线。

旧 peer 未实现该通知端点时，既有提交/查询仍工作，升级后会重试同步。同步不主动重发任务。节点信息探测可通过仍可达的旧地址发现新地址，再验证后采用。

节点 Web 始终仅 loopback。peer_listen 可在本机设置中修改；保存后显示是否需要重启，不静默热切换。Tailscale 配置选择具体本机 Tailscale IP，避免把旧单机测试的 loopback 监听带入双机验收。远端配对前拒绝显然只能本机访问的公布地址或监听；回环隔离测试仍受原身份校验保护。

## 会话目标与可替换通信

[本机持续聊天](../development/features/local-node-chat/plan.md)只开放当前节点默认助手，首版没有新的 peer 聊天端点。领域对象与可靠性语义见[持续会话设计](../assistant/conversations.md)。

会话客户端显式传 node_id/role_id/conversation_id，目标解析仅把当前已认证节点作为首版合法目标。“本机”是 UI 标签，不能表示全机唯一服务。地址、端口和显示名可变，绑定身份保持；会话目录、缓存、游标和运行时路径按节点实例隔离。当前按数据目录的启动锁基础保留，多节点安装/发现和统一热键协调另行设计。

本地路径通过受限宿主 IPC 和会话服务接口，不复用广权限 Web 登录 token 给 UI。主进程校验来源、会话绑定和操作能力；UI 提供的原生 session/path/URL 不参与授权。未来在同机访问另一节点仍需验证其身份与会话权限。

未来远程实现相同会话语义，经认证节点信道访问目标节点的会话服务；harness 管理端口不对 peer/浏览器开放。既有配对只提供身份信任基础，聊天的角色准入、会话读取/发送/停止分别授权；不从配对、模型输出或普通 peer 身份推导人工审批。撤销阻止后续访问并关闭相关订阅，已经接受的运行按目标策略处理。

目标节点是历史与运行状态权威，入口只保存引用和必要缓存。入口退出/断网不取消目标已接受轮次；恢复按原 ID 和目标对账，快照/游标补读并有界退避。失联是连接状态，不是失败终态。未来 `@节点/角色` 经候选选择解析稳定 ID，重名显示所属节点，不支持按文本猜测后自动换目标。

远程协议具体传输、身份映射与兼容版本留待远程聊天 feature 实测定稿；本次只验证本机路径及抽象 fixture，不把它算作双机聊天验收或扩大手机访问范围。
