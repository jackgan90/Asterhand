# 后续能力方向

状态：保留原始需求的设计线索，全部不是首版完成条件。具体实施前另建 feature 并重新验证。

## Coding harness 与项目工作区

按实际需求选择 OpenCode、Claude Code、Codex、Antigravity 等适配器。使用正式 API / SDK / headless 接口，能力声明明确，避免解析易变终端文本。不假设各执行器支持等价取消或恢复。

编码项目可使用独立 Git worktree，从固定版本开始，记录基线、diff、新增文件、验证与产物；worktree 是文件布局隔离，权限依赖 OS / harness。合并和推送单独授权。订阅认证遵循对应工具正式路径，不复制其他工具 token。

## 多仓库更新

保留项目 manifest：仓库 ID、VCS、路径、远端、固定目标、依赖顺序、submodule/LFS、脏工作区和验证策略。VCS 可能包含 Git、SVN，实施前核对。

流程为检查、固定目标、记录恢复点、隔离准备、验证、按策略更新、逐仓记录结果。多仓库没有共同原子提交；本地改动、未推送提交、已推送结果和外部副作用需要不同补偿策略。

## Scheduler

每个 schedule 有明确 owner、时区、目标、计划时刻和并发策略；去重键为 `(schedule_id, scheduled_fire_time)`。离线策略区分 skip、run_once、replay_each，仓库更新优先评估 run_once。没有自动跨节点接管。

## Memory 与 skills

用户偏好、角色知识、项目知识分域，原始会话与活跃数据库默认本地。索引是可重建数据；凭据不共享。不能通过普通双向文件同步共同修改活跃 SQLite 或 runtime home。

可迁移记录包含稳定 ID、用户明示/模型推断、来源、范围、版本、替代/纠正/删除关系。用户纠正有优先性，删除需传播到副本与索引，避免仅凭本机时间 last-write-wins。

Coding memory manager 先处理项目约定、任务检查点、未解决项、commit/diff/worktree 与会话引用；特定工具记忆文件由专用 adapter 管理，不写未公开的活跃数据库。

自进化定义为记录结果和纠正 → 形成候选经验/skill → 样例验证 → 版本发布 → 观察与回滚。首版不自动训练模型、修改核心代码或扩大权限。

## 多角色与动态 placement

角色包包含行为、工具、memory scope、provider/model、权限、预算和所需能力；角色定义与设备绝对路径分离。

后续新任务按工具/OS/权限/项目硬约束，再考虑数据局部性、预计在线时间、槽位和成本。云端 LLM 下主要调度工具与数据环境，本地计算负载另行评估。运行中 job 不自动迁移。

## 渠道与网络

微信作为用户渠道，内部继续使用任务协议；同一 bot 账号明确渠道 owner，避免重复消费。按实际插件版本验证发送者允许列表和配对，不假设插件自动继承全部访问控制。

通知优先需要回答、决策、失败和恢复；普通进度留任务页。手机 Web、后台推送和原生应用是独立能力。可评估 ntfy、Headscale、iroh、A2A 等，先确认实际缺口再集成。
