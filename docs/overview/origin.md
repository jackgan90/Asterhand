以下保留用户最初描述的内容，用于后续需求追溯。原文中的产品名称和能力认识属于用户背景表达，不作为本项目已验证的技术依赖。

> 我在构思个人用分布式agent助手系统的架构。我希望在我日常使用的终端上部署agent助手，agent由llm驱动，各agent之间可以互相沟通。这些终端有windows pc/macbook/android手机/iOS手机/Linux服务器。单个终端上的agent定位是一个可理解自然语言的多功能助手。我可以对它发出指令，例如：更新游戏项目所有仓库。它可以编写脚本，将游戏项目涉及的所有仓库更新到目标状态，并处理好冲突、回滚等情况。在有必要时，我还可以命令其他在线节点的agent做远程任务。
>
> 我知道openclaw和hermes agent这两个广受欢迎的开源项目都可以完成我上面的要求，同时还有一些厂商已经推出了个人助手产品，如Grok bot,OpenAI的dot，Anthropic的Duet等。原则上，我倾向于使用开源项目作为主力，因为那样不会绑定在单一的生态上。关于这个助手系统，我有这样的预期使用情景：多个终端不一定同时全部在线，但一旦在线，各节点之间应当能进行通信。此外，最好不要有“中心节点”的设定。即使Linux服务器可视为较稳定的持久节点，但不应假设所有agent的管理和通信都以它为中转节点。通信的作用是远程任务派发和执行。例如，我可以在A节点上让B节点实现一个网站开发功能。B节点借助节点内工具，例如codex桥阶层/headless claude code等，委托coding harness做开发。最好B节点的开发过程还可以通知到A节点，这样A节点就能监控B节点的开发进度。对于单节点内应用，我还会把agent视为通用助手。例如，windows上的everything可以快速搜索电脑上制定名字的文件，对类似的搜索需求，我可以通过agent用自然语言描述我的搜索目标：帮我全盘搜索名为test.txt的文件，并将结果返回。agent还可以做：coding harness memory manager，repository update sheduler等等。也就是说，它成为一个工具的统一入口，很多任务我不必直接使用对应软件，只通过agent就能实现我想要的功能。驱动agent的llm provider可配置， 我目前预期的是默认为它们配置deepseek api，因为它足够快，且便宜，但不排除接入coding plan subscription account。我还希望我的agent们有多个角色。它们可能位于同一个节点，也可能在不同节点，并根据实际在线节点动态分配计算资源。这些角色类似于：coder(专门写代码)，language teacher(教我英语、日语)、financial advisor、news collector等等。agent可以支持skill/memory等。支持自进化。我希望它们随着我不断使用，越来越聪明和得心应手。我还希望agent能接入我常用的通信软件，如微信。我还不确定的一个点是：我是直接用openclaw/hermes agent，还是自己再做一层薄的ochestrate layer,由我的ochestrate layer调度这些agents。我想实现的很多，上面只描述了我当前能想到的需求，可能有些潜在需求我一时之间没想清楚。请你基于我的描述，给我推荐一个稳健的架构。如果有现成的已经实现了类似功能的开源项目，可参考并列出对应的项目。
