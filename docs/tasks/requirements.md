# 任务需求

状态：已确认设计要求，实现契约见本领域 design.md，平台边界见测试文档。关联 R05、R08、R09、C03。

| ID | 要求 |
|---|---|
| TASK-01 | 执行节点事务持久接收后才确认；发起节点保留发送队列 |
| TASK-02 | 同请求同内容返回原任务，不同内容冲突；未知结果只向原目标重试 |
| TASK-03 | 发起端和页面断开不终止已接收任务；执行节点固定 owner |
| TASK-04 | 任务快照和持久事件支持断线补读、去重和游标缺口处理 |
| TASK-05 | 问答与审批关联到准确 attempt 和执行器实例，防重复和过期回答 |
| TASK-06 | 取消请求登记与实际停止分开；终态需要执行证据 |
| TASK-07 | 重启先对账，无法确认进入 reconciliation_required，不盲目重启 |
| TASK-08 | 区分执行结果、机器验证与用户验收，输出真实文件与检查结果 |
| TASK-09 | 工作区独占、队列期限、资源预算和日志上限明确 |
| TASK-10 | 清理日志不删除必要的去重记录，迟到提交和取消不会意外启动任务 |

明确 TASK-05/06/07/09 的边界：取消登记后问答不得覆盖；普通事件耗尽必须拒绝新副作用，并保留有界的证据、终态、取消和恢复通道；重复控制请求不得耗尽预留空间。收尾持久化失败必须阻止后续执行，已满容量的旧节点仍能进入待核对。

自动化标准见 [A01—A30](../testing/matrix.md)，产品操作见 [V01—V06](../testing/acceptance.md)。

实现事务接收、固定 owner、outbox、单 attempt、单执行槽、普通问答、取消、持久事件与重启待核对。当前 interaction 一次一个，原生审批/resume 未开放；详情和数值见 design.md 的 契约。
