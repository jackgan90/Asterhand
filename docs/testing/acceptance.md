# 首版人工验收

本文定义可重复执行的 V01—V06 人工验收规程。每次验收使用对应版本的构建与环境，支持范围见 [平台矩阵](platforms.md)。操作规程不充当逐项执行结果。

## 准备

两台可互通的 Windows，A 已运行兼容版本；B 可为全新节点。由本地向导选定专用验收目录，不使用重要仓库。A、B 各有有效 DeepSeek 配置；首版无需 coding harness，第三方运行时必要依赖由安装器处理，用户无需手动准备开发工具链。

每次验收使用新目录或新文件名，避免把上次结果误认为本次产物。登记两机系统、架构、版本、模型、节点 ID 和验收时间。

## V01 新节点安装与配置

1. 在全新 Windows 仅下载仓库固定入口 install.ps1 并执行，默认选择最新稳定 Release；另用 Version / ReleaseTag 验证指定版本，确认无需预装 Go、Git、Node 或 npm。没有稳定版时应明确失败，不能自动选择预发布版。未发布候选可使用兼容脚本与同一构建的清单、ZIP，但应另记匿名下载为未验证。
2. 自动识别环境并补齐运行依赖与 Tailscale，选择创建或跳过桌面图标，完成后退出。确认没有登录 Tailscale、启动节点或生成模型配置。记录 UAC 与重启要求。随后手动完成 Tailscale 登录，双击桌面图标、固定 AsterhandLauncher.exe 或执行 start.ps1 打开 Web 向导，确认托盘出现且原生入口没有控制台窗口。
3. 设置节点名、DeepSeek key / 模型、授权目录，运行模型与无副作用工具检查。
4. 启动 B，在 A 的 Web 使用 B 地址与一次性码配对。
5. 确认 B 在线且文件任务能力就绪。
6. 正常退出 B 后重复运行安装入口，再启动 B，确认身份、配对、目录和模型配置保留。验证升级保留实际桌面图标状态，手动删除后默认不重建，登录后启动选择独立且不弹浏览器；节点仍运行时安装拒绝激活。

安装通过：单脚本补齐全部组件、组件健康检查成功，结束时仍待用户配置。配置与业务通过：实际可访问 Web、模型配置有效、节点配对成功，重装未丢失配置。安装、配置、模型和两机业务分别记录；Windows 托管运行器不能替代桌面系统 UAC/重启体验。

## V02 B 本机自然语言创建

在 B 的页面输入：“在验收项目下新建 local-hello.txt，内容为 hello world。”

通过：出现真实 job 和执行记录；在 B 资源管理器打开文件，内容精确为 UTF-8 `hello world`，无隐式 BOM 或换行；结果显示实际路径和读取验证。必须实际使用 OpenClaw + DeepSeek。

## V03 A 派发给 B

在 A 选择 B，输入：“让节点 B 在验收项目下新建 hello-world.txt，内容为 hello world。”

通过：A 显示 B 已接收、执行中、完成；B 无需手动输入命令；两边能查同一任务，B 资源管理器可打开真实文件。A 本机授权目录没有误生成该文件。

## V04 A 下线，B 继续

启用隔离验收配置中的 30 秒确定性执行延迟，提交创建 offline-hello.txt 的请求。延迟由验收工具控制，不让模型用自然语言猜时间。

看到 B 已持久接收后，关闭 A 的助手和节点服务或切断 A 网络。在 B 确认延迟结束后文件创建。恢复 A，重新打开任务页。

通过：B 在 A 离线期间完成；A 自动取得最终状态及遗漏事件；只执行一次。单独关浏览器只能证明页面独立，不能替代本场景。

## V05 远程问答

在 A 输入：“让节点 B 创建一个文本文件，先问我文件名，收到回答后再写入 hello world。”

等待 B 生成任务问题，在 A 表单回答 greeting.txt；刷新页面并重复提交同一答案。

通过：回答前无文件，回答后 B 仅创建一次；问题关联正确 job/attempt，重复回答不再次执行。问答是本项验收内容，权限审批另由工程用例验证。

## V06 重启与对账可见性

在受控任务执行中重启 B 的节点服务，重新打开 B / A 任务页。

通过：任务记录保留，展示对账后的真实状态或明确的“需要核对”；无未授权第二次启动。能恢复的路径必须有执行证据；不能确认时给出现场与处理入口，不伪装完成或无缝续跑。

## 桌面启动与退出补充

按 [桌面验证说明](../development/features/windows-desktop-lifecycle/validation.md) 分别验证重复/并发入口、无桌面图标启动、浏览器关闭与锁屏继续、托盘忙时取消和确认退出、端口与子进程释放、日志诊断、Explorer 重启、不同 DPI 与注销收尾。V04 使用托盘退出 A 可同时覆盖远端任务继续；V06 使用托盘确认退出 B 可覆盖本机在途任务持久化待核对。工程自动化与真实桌面、两机模型验证分别登记。

## 结果登记

快捷输入按[进程隔离验证](../development/features/quick-input-process-isolation/validation.md)单独登记：真实工具窗口的实体键盘/IME、普通用户与管理员权限矩阵、UI 故障后的已接受草稿恢复，以及节点异常退出后的自有进程树清理。它不调用模型，不能代替 V02—V06 的真实任务验收；程序构建与自动化测试也不代替桌面专项验收。

每个场景记录观察结果、文件证据、关键 UI 截图或事件、通过 / 失败及原因。最终由用户确认是否接受。取消、审批、磁盘失败、幂等冲突等按 [自动化矩阵](matrix.md) 提供工程证据。
