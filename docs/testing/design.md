# 测试框架设计

状态：已有可执行 Go 测试和本机真实模型验证；尚未添加 CI workflow。完整故障注入框架仍是后续设计。

## 分层与运行条件

| 层级 | 环境与工具 | 内容 | 时机 |
|---|---|---|---|
| 状态与存储 | Go testing，单机无 key | 状态迁移、事务、幂等、交互、迁移、期限 | 相关修改 |
| 单机多节点 | Windows 独立 A/B/C 进程 | HTTP、SQLite、SSE、断线、重试、崩溃 | 日常回归 |
| 跨 OS | Windows + WSL2 / Linux | 路径、权限、网络、进程、部署 | 平台代码变化 |
| Adapter 契约 | 协议 fixture + 真实 OpenClaw | 消息、工具、问答、审批、取消、恢复限制 | adapter / 依赖变化 |
| Web | Playwright | 安装向导、聊天派发、任务卡片、回答、重连 | 相关 UI 变化 |
| 真实产品 | 两 Windows + DeepSeek | [安装、文件、离线与交互验收](acceptance.md) | 功能验收 / 发布前 |
| 安装 | 干净 VM 或独立测试环境 | 新安装、已有依赖、中断重试、升级边界 | 发布前 |

基础命令为 go test ./... 和 go vet ./...，完整门槛由 scripts/verify-dependencies.ps1 编排；依赖锁定见 packaging/dependencies.json。功能验证方法见 [助手基础](../development/features/windows-assistant/validation.md) 与 [双节点交互](../development/features/two-node-usability/validation.md)。

## Test controller

控制器创建临时根目录，为节点分配独立身份、配置、数据库、授权目录、运行时 home 和动态端口。提供启动、停止、等待检查点、断链和证据收集。

清理只针对本次创建的根目录和进程；保留失败证据。不能复用真实个人 OpenClaw home 或用户目录。单机节点隔离是逻辑隔离，需要验证 OS 权限边界时使用 VM / WSL，并明确宿主挂载权限。

## FakeExecutor 与 fixture

按场景脚本确定地产生执行、进度、问答、审批、失败、挂起、取消确认和查询结果；提供独立子进程形式验证进程退出和残留。

单元测试可使用内存 fake，故障测试使用真实进程和 SQLite。OpenClaw 协议 fixture 应来自已验证版本的脱敏交互，并与真实 adapter 契约测试交叉验证，防止实现与模拟器共同漂移。

真实模型行为有变化时，产品测试断言文件字节、工具调用和状态等可观察结果，不断言模型必须逐字输出固定句子。记录模型与配置。

## 故障注入

协议代理按检查点故意丢弃持久接收后的响应、延迟请求、切断 SSE 或阻断单向链路。它作用于应用消息边界，不依赖 TCP 随机丢包碰运气。

进程故障分别注入 A 服务、B 服务、B runtime、工具子进程；明确是正常退出、强制结束还是整机重启。不可混称“断线”。

可控时钟验证排队、交互期限、重试退避和时间偏差。真实进程测试使用明确 ready / committed 等信号，固定 sleep 仅用于用户可操作的隔离验收演示，不作为自动化同步机制。

磁盘写失败、事务失败、日志过量、慢客户端、取消与完成竞争、审批失效都需覆盖。详见 [矩阵](matrix.md)。

## 可用性与发布门槛

测试用例声明 requires：OS / 架构、runtime、网络、凭据、真机数、是否消耗模型额度。controller 预检查后运行；缺少条件记录 skipped 或 blocked 及原因。

passed / failed / skipped / blocked 为执行状态；计划未执行的用例用 not_run，避免将未开始误报为跳过。

日常回归不强制所有设备在线。发布配置列明必测用例和平台：必测不可用则阻止发布，不能把 skipped 算成功。真实模型测试显式选择并设置预算，普通测试不调用计费 API。

## 证据与检查

执行记录包含 commit、OS/架构、工具版本、模型、用例、实际命令、结果与失败/跳过原因。长期文档按 [验证说明模板](../development/templates/validation.md) 描述前提、测试入口和预期行为。

原始执行数据保存在忽略目录，发布所需证据随对应版本发布物归档。功能文档不得包含本机路径、临时流水或仅本机可见的证据链接。

拟实现 CI：格式、相关 Go 测试、契约校验、文档链接、feature 关联和代码规模提醒。文档准确性由审查确认，行数超限由理由与拆分确认流程处理，不机械拒绝构建。

当前多节点集成测试在一个测试进程内运行独立 App/SQLite/HTTP/TLS 实例，A 退出测试关闭完整 App；Windows 进程树测试另外启动真实父子进程。尚未有协议故障代理、可控时钟或整机崩溃测试，不将这些计划项计为通过。

## 契约与升级门槛

增加提供者中立契约：异名 fixture 的受保护路径与目录别名拒绝、逐一包目标分派及失败传播、通用依赖集合/未知安装技术拒绝、旧配置迁移与 JSON 快照隔离、CLI 无效选择在持久化前拒绝、设置接口保护全部 adapter 目录。真实模型仍使用生产唯一实现；旧候选升级必须保留身份、凭据字节和工作数据，未支持提供者不计为已验证。

模型契约覆盖当前模型列表、未知 provider、跨 provider 模型与未支持 endpoint。配置契约覆盖 flat model 迁移、原位 DPAPI 保留、凭据引用路径拒绝、不同引用隔离；设置 API 测试保证拒绝发生在凭据写入前、设置修改使就绪失效且不返回密钥。

runtime 契约用真实子进程 fixture 验证 JSON 成功/失败/无效输出、凭据脱敏、运行中取消、stdin 阻塞取消；工具模式同时在 Go 配置和 JS 注册测试中检查。现有 OS 进程树及任务服务问答/恢复测试保留。原生 resume/审批/事件能力声明为 false，Fake 不参与真实模型通过判定。

统一入口 `scripts/verify-dependencies.ps1`；真实层 `verify-live.ps1` 通过本机 API 执行 probe、文件、执行阶段问答、等待问答时取消，检查实际文件字节与持久产物摘要。每次使用唯一文件名并保留证据；失败只取消本次创建任务。安装层 `test-install.ps1` 使用合成凭据检查旧候选到新候选的数据保留，绝不复制用户模型 key。

报告绑定源码、依赖清单、lock 摘要；未运行条件标 skipped，全部必要工程层通过才允许 upgrade_ready=true。这是本机候选工程状态，双 Windows/NAT、用户验收和发布仍单独记录。

## 审计回归

Web 维护性回归分为可注入客户端与生命周期、模拟 DOM 操作序列、真实嵌入资源和真实宿主四层。任务 pending/答案去重由业务控制器测试，连接资源用可控事件源与时钟验证；主输入与回答焦点保护由操作序列和浏览器分别确认。资源测试从 HTML 沿静态 import 检查完整闭包，主 Web 验证 GET/HEAD/MIME/nosniff，浮层验证原生 GET 白名单与禁网。独立 fixture 使用真实 App/SQLite/TLS 和 FakeExecutor，单独 opt-in，不调用模型、不读现有节点数据；[可执行方法与浏览器步骤](../development/features/web-ui-maintainability/validation.md)明确各层证据和未验证平台边界。

安装入口专项回归见 [路径解析说明](../development/features/installer-path-resolution/plan.md)：PS5.1 内先 Set-Location，再人为设置不同的进程 CurrentDirectory，使用真实 ZIP 验证相对包/清单/程序/数据路径。绝对路径测试不能覆盖此交互式安装行为。test-install-paths.ps1 负责该场景，已接入 test-install.ps1，随完整安装/升级门槛运行。

- 真实 SQLite 填到普通日志边界，完成最后一次文件写入后仍有产物证据，后续写入/委派在副作用前拒绝；控制日志保留硬上限。
- 用 SQLite 触发器注入事件提交失败，确认 operation 与任务产物一起回滚；恢复旧已完成操作的分步证据，满日志节点真实 App 重启进入待核对并可处置。
- 重复取消、答案和文件结果不会消耗收尾空间；持久化失败从执行循环返回，停止节点和后续调度。
- 确定性构造问答请求/答案交付与取消的交错，断言取消仍为权威状态；现有普通问答、重复/不同回答和过期 attempt 契约继续执行。
- 配置通过保存、重新打开、发现、验证失效检查，覆盖显式自定义路径、显式完整其他包、旧自定义路径、旧完整包与新自动包迁移。执行选项/模型变化、缺少旧验证摘要必须重新 probe，不相关 runtime 选项不影响当前验证。
- Windows PS5.1 新装、重复与上一兼容版本升级分别执行。付费模型、两机/NAT 与平台实测按实际执行状态记录。

## 双机交互回归

快捷输入覆盖本地配置事务故障、注册冲突、录制租约、草稿版本与字节边界、认证 API、静态模块入包、真实 WebView2 与隔离供应商安装边界。桌面测试须显式启用；普通回归不将桌面 skipped 计为通过。入口和成本预算见[快捷输入验证](../development/features/global-hotkey-quick-input/validation.md)。

Go 用真实 HTTP/TLS 双实例验证改名不撤销模型就绪、单向地址通知恢复、身份/固定证书/撤销/不可达地址拒绝以及监听变更提示。MIME 测试强制 Windows 风格的 text/plain 文件关联，覆盖 GET/HEAD 和 nosniff；慢连接测试覆盖 2.2 秒信息响应与 6 秒元数据回查。JS 验证新远端任务在 18 条历史本机任务之前、路由转执行保持排序并去重，以及空输入/未就绪/实际提交中的按钮状态。真实双机升级后的双向任务和名字传播仍单独验收，单机 fixture 不替代该结果。
