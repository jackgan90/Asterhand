# 测试需求

TEST-NTF-01：完成通知必须覆盖默认开关兼容、显式关闭、公共操作和草稿、最终保存后一次性发布、主动停止过滤、有限排队与汇总、悬停/桌面中断计时、迟到事件、原运行日志定位和宿主独立退出。原生动画、焦点、多屏/DPI 与辅助功能按[完成通知验证说明](../development/features/local-command-completion-notifications/validation.md)单独验证，替身不算桌面验收。

## 自动化验证要求

- TEST-AUTO-01：公共操作、CLI/MCP 定义与日常 UI 覆盖登记一致，缺失或 schema 漂移阻断交付；静态登记不能替代行为验证。
- TEST-AUTO-02：使用三入口验证相同业务结果及拒绝，覆盖接纳丢响应、进程崩溃、过期/清理、并发编辑、停止竞争、批次部分完成和有界资源。
- TEST-AUTO-03：真实 Windows 进程/本机通道和实际 MCP 客户端验证，模型及双机任务按条件独立验收，不借 fixture 宣称产品支持。

可复现步骤与已有测试依据见[自动化验证说明](../development/features/agent-automation/validation.md)。

## 持续聊天验证

下列要求对应[本机持续聊天](../development/features/local-node-chat/plan.md)，工程测试、原生运行时和桌面验证已提供独立入口；实际模型与人工验收单列。

| ID | 要求 |
|---|---|
| TEST-CHAT-01 | 先验证锁定运行时的会话、收据、历史、安全与生命周期门槛，再以真实模型及故障注入覆盖发送、持久化、取消和恢复；fixture 不替代原生证据 |
| TEST-CHAT-02 | 验证桌面交互、资源有界与原任务/安装回归；UI 和 Gateway 成本分开，已有失败预算保持可见；抽象 fixture 不作为新 harness、多节点产品或远程聊天交付证明 |
| TEST-CHAT-03 | 提示词验证区分支持声明与实际模型输入；完整覆盖、补充、不支持及失效均有原生证据。发送即时展示、身份合并、输入法边界和可见正文截断分别验证，实体输入法与合成事件分开记录 |

范围：单元测试、单机多节点、适配器契约、安装与真实产品验收。关联 C03、C09、TASK-01—TASK-10。

| ID | 要求 |
|---|---|
| TEST-01 | 单台 Windows、无模型 key 可运行核心状态与多节点故障回归 |
| TEST-02 | 真实网络、数据库和进程边界测试，不只测同进程 mock |
| TEST-03 | FakeExecutor、协议代理、可控时钟和明确检查点支持可复现故障 |
| TEST-04 | 真 OpenClaw + DeepSeek 验证不得被模拟成功替代 |
| TEST-05 | 两台 Windows 完成可见文件、问答和断线验收 |
| TEST-06 | 平台按能力和可用性分层，记录跳过原因与支持级别 |
| TEST-07 | 发布必测项缺失阻止发布，日常可跳过非必需外部环境 |
| TEST-08 | 干净环境安装、重装保留配置和已有环境兼容需要测试 |
| TEST-09 | 真实运行报告包含版本、环境、用例、结果和证据 |

首版不要求 coding harness 测试。新增适配器后才引入其协议 fixture 与真实兼容性门槛。

日常测试使用 Go testing、真实临时 SQLite/HTTP/TLS 和进程 fixture，不调用计费模型；真实 DeepSeek 由本机表单配置后独立验收。报告列出已运行子场景与未运行矩阵项，不将模拟双节点算作物理双 Windows 验收。
