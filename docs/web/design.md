# Web 设计

当前实现为 HTML/CSS/原生 ES module 内嵌 Go，无前端构建运行依赖。文末“持续聊天面板”定义快捷输入中的会话展示，源码已接入。

## 本地快捷命令入口

[脚本图编辑器](../executors/script-graphs.md)作为命令表单的独立组件，使用原生 ES module、HTML 节点及 SVG 连线；图模型负责前端结构校验，后端重复校验为权威。运行中禁止修改，图强制托管；Start/End 隐藏脚本属性区域。日志窗口用统一选择面板管理合并、运行节点自动分屏和固定多选；单屏控制器独立读取、分页、解码和跟随，窗口控制器刷新运行状态并限制请求并发。节点状态样式由稳定状态映射产生，显示模型不参与进程调度；保留现有受限 IPC 和国际化行为。

Web 的本地命令管理使用独立模块和同源认证 API，快捷输入命令列表使用独立搜索/视图模块与窄 IPC，不复用聊天提交或任务队列。路径、参数与凭据不由快捷输入页面提供；页面只能选择已注册 ID 和修订。配置入口支持主进程构造的固定本机深链接。行为与数据权威见[本地命令设计](../executors/local-commands.md)。

### 托管命令和日志窗口

日志读取器分别维护读取在途和界面加载状态：已有内容的自动补读保持串行，不禁用工具栏；初次加载、主动翻页和编码切换才显示加载并防重复。用户主动操作可以替代自动补读，旧代次响应不能覆盖新选择。工具栏仅在文字或实际可用状态变化时更新，避免自动轮询引起按钮闪烁或焦点丢失，见[日志工具栏稳定性计划](../development/features/log-toolbar-refresh-stability/plan.md)。

日志窗口的打开先确认原生窗口显示，浏览器和页面异步初始化；关闭后有界复用，隐藏暂停刷新，初始化错误保留可见反馈并支持显式重建。快捷输入通过原生层采集点击时的屏幕提示，首次打开及已有窗口再次打开均优先位于该屏工作区。自动列表刷新保留操作错误，下一次主动操作开始时清除。具体生命周期、资源上限和定位契约见[托管命令设计](../executors/managed-local-commands.md#独立日志窗口与操作入口)。

[托管命令计划](../development/features/managed-local-commands/plan.md)对应的注册表单增加类型和可选超时，列表分开展示类型、文件可用性与运行结果；运行中通过独立停止控件请求中断，停止、日志与启动的点击/键盘行为分开。运行状态刷新不得覆盖正在编辑的表单或触发配置修订变化。

日志使用独立非提权 UI 宿主的顶层窗口，继承主题、字体、语言与应用图标，提供系统窗口入口、大小调整和多命令窗口；Windows 首个后端为 WebView2 与任务栏，其他平台的渲染器和系统窗口行为由对应宿主实现。每条命令只开一个窗口，重复打开激活已有窗口；关闭只释放查看资源。正文按 run ID/游标分块读取、增量解码并以纯文本显示，大日志按需渲染，保留历史可达性和滚动位置；主题/语言变化不重置日志、选区或跟随状态。停止操作绑定当前执行 ID，等待权威状态，超时与中断后继续可读日志。

日志宿主不持有节点凭据和进程执行权威；受限 IPC 承载读取、停止及窗口管理，Web 管理操作复用本机会话与 Origin/CSRF。日志帧和在途请求有界，不能使停止请求饥饿。完整契约和故障恢复见[托管命令设计](../executors/managed-local-commands.md)。

公共日志页面只调用注入的 send/subscribe bridge，不直接访问 WebView2 API；原生窗口、UI 线程、激活/DPI 与传输介质通过窄宿主接口隔离。表单根据后端能力显示受支持类型、窗口模式和文件过滤规则，不按 Windows/macOS/Linux 名称硬编码业务流程。替身 bridge 和不同平台能力组合使用同一 UI 契约测试；具体平台原生窗口验证独立进行。

## 维护性重构的职责边界

本次按[维护性计划](../development/features/web-ui-maintainability/plan.md)整理现有职责，功能、认证、接口、样式和支持平台保持原契约。主入口只装配依赖；同源客户端实例持有 CSRF 与登录会话，不生成业务 ID，也不重试写入。页面生命周期拥有事件流、节点刷新计时器和会话代次；任务控制器拥有任务快照、提交互斥与答案 ID，任务视图报告回答编辑状态。节点与配对控制器持有选择状态，节点设置控制器持有表单读取与模型检查轮询，桌面设置继续独立持有录制租约与操作 ID。

认证事务在客户端实例内串行完成，普通请求等待认证的 Cookie/CSRF 对成对落地；已发送登录即使所属页面失效也要完成该配对，再处理下一次认证。过期且尚未发送的认证可以跳过；该调度不自动重试业务写入。桌面设置的互斥归具体页面代次和事务身份，恢复时主动读取并按 last_operation/修订号核对未知保存，未确认时复用原 operation_id，旧完成不解除新事务的锁。通知停止时同时清理计时器并隐藏旧内容。

页面离开时关闭订阅并使旧读取结果失效；前进/后退缓存恢复时重新读取并恢复一次订阅。只读取消不改变服务端任务，未确认的提交继续保留 `asterhand-pending`；桌面录制通过明确租约取消和服务端到期收尾。通知视图单独清理隐藏计时器。浏览器确认、提示与复制通过窄依赖注入，继续调用原有浏览器 API。

快捷输入桥只包装 WebView2 消息收发及释放。主进程拥有权威内存草稿和修订号；编辑器拥有临时文本、IME 与有界待确认编辑，独立 UI 宿主转发已完成的文本。桥模块随独立浮层资源入包和白名单加载，不依赖主 Web 客户端，不增加宿主权限。

## 视觉与文案

管理页与快捷面板共用星核（深色）/霜蓝（浅色）设计变量：深空底色、青色强调、紫色光晕和渐隐网格；主按钮、状态圆点、弹窗与面板保持一致。页面主题跟随快捷输入设置中的面板主题：登录后读取 `/api/desktop/settings` 的 `desired.theme_id`，保存桌面设置后立即应用，并在浏览器本地缓存以减少下次打开时的闪烁。读取失败保留上次主题，不影响其他功能。

文案面向普通用户：界面使用“设备 / 本机 / 工作目录”，任务状态使用短词（排队中、执行中、等你回答、已完成、对方未接收、状态待确认）。协议与实现细节默认收起而非删除：设置中的运行环境、节点 ID、数据目录和停止本机服务位于“高级”折叠区；任务详情先显示状态、执行、验证与用户确认，任务 ID、尝试次数和原始事件位于“技术记录”；文件摘要放入悬停提示。后端返回的错误原因按原文显示。

设置弹窗分为常规、模型、快捷输入、网络与高级四页，仅通过 CSS 切换显示，节点设置与桌面设置仍是两个独立表单，保存语义不变。节点表单跨三页，提交时若必填项位于隐藏页，先切换到该页再由浏览器提示。

## 运行期国际化与无损语言切换

运行期多语言由 `internal/i18n/locales/manifest.json` 语言注册表与 `<id>.json` 词表统一驱动，架构决策见 [ADR-002](adr/002-runtime-internationalization-framework.md)，实施与回归范围见[国际化计划](../development/features/internationalization-framework/plan.md)。Go 端通过 `//go:embed` 内嵌词表；`scripts/sync-i18n.mjs` 从同一词表确定性生成只读 ES module `web/i18n-catalog.mjs` 与 `internal/quickinput/assets/i18n-catalog.mjs`，不发起运行时词表网络请求，保持 `connect-src 'none'` 与静态模块闭包契约。

语言状态分为四层：
1. **持久偏好（`desired.locale`）**：存于 `desktop-settings.json`（`"auto"` 或注册表语言 `id`，旧文件缺省归一化为 `"auto"`）。
2. **节点有效语言（`effective_locale`）**：具体语言直接生效；`"auto"` 按节点操作系统用户 UI 语言执行三级匹配（精确标签 → 语言族前缀 → `default_fallback` 即 `en-US`）。托盘、快捷输入宿主与启动器统一采用节点有效语言。
3. **Web 生效语言**：已获取节点状态时，`desired.locale != "auto"` 采用配置值；`"auto"` 且节点 `system_locale_detected == true` 采用节点有效语言（系统优先）；仅当 `"auto"` 且 `system_locale_detected == false` 时次选浏览器 `navigator.languages`，并通过 `X-Asterhand-Locale` 请求头同步当次 API 错误响应语言。
4. **首帧提示与未登录覆盖**：`localStorage`（`asterhand-locale`）仅作首帧防闪提示，`/health` 与 `/api/desktop/settings` 返回后立即校准；未登录页手动切换写入当前标签页 `sessionStorage`，仅作用于登录前视图与 `/api/login`，登录成功后以服务端持久偏好为准。

语言更新走专用接口 `POST /api/desktop/locale`（请求体 `{operation_id, expected_revision, locale}`），与 `Apply` 共用互斥锁、操作幂等表与原子写盘，独立维护 `last_locale_operation`，在写盘前核对 `expected_revision`（不符返回 `409` 并附最新状态），不检查交互桌面或热键注册器、不初始化 WebView2、不取消录制租约。原 `POST /api/desktop/settings` 的 `locale` 为可选字段，缺省保留原语言。桌面设置维护非语言基线 `formBaseline`：语言切换不重置未提交开关/按键/主题草稿，仅当无挂起 `pending` 且服务端非语言字段与 `formBaseline` 一致时推进 `formBaseline.revision`，确保跨页面并发修改仍触发 `409` 保护；响应丢失时保留 `{operation_id, expected_revision, locale}` 与 `GET /api/desktop/settings` 对账，迟到旧请求由服务端 `expected_revision` 拦截。

静态文案使用 `data-i18n`、`data-i18n-placeholder`、`data-i18n-aria-label`、`data-i18n-title` 与 `textContent` 绑定，禁止 `innerHTML`。切换语言时各视图执行局部 `relocalize()`：任务视图保留未提交回答草稿与输入焦点/选区并原位刷新已打开的详情摘要；节点设置、桌面设置与本地命令保留未保存编辑与 `dirty` 状态（全新节点的默认设备名在未手动修改前随语言展示译文，整表单保存回传 `name_edited: false` 不误清 `name_default`）；聊天渲染器保留语言无关的 Markdown/KaTeX 正文 `body` 与消息签名缓存，仅原位更新角色标签、时间、送达提示、分片按钮与代码块复制标签，并通知 `composer-layout` 重算收起态高度。公开错误与状态优先按 `message_key`/`error_key` 本地化，缺失或未知键回退服务端兜底文本。

## 页面结构

```text
Asterhand                         当前连接：Windows A

节点                             对话 / 任务
● Windows A（本机）              执行节点：[Windows B]
● Windows B
○ Linux                          用户：创建 hello-world.txt

任务                             任务卡片
本机任务                         执行节点：Windows B
我发起的远程任务                 状态：已接收 / 执行中 / ...
                                 最新进度、更新时间
                                 查看详情 / 取消

                                 消息输入框 / 发送
```

只实现薄聊天界面和任务面板，OpenClaw 提供会话与工具循环。浏览器连接当前节点；节点服务负责远程通信，浏览器关闭不承担取消语义。

## 对话与任务关联

当前任务入口的对话表现由入口节点任务记录组织，消息引用稳定 job_id 和 owner_node_id。助手发起提交后 UI 绑定返回的任务，而非将自然语言“完成了”当作任务终态。持续会话按[会话设计](../assistant/conversations.md)由目标节点的 harness 保存正文，不沿用任务记录作为聊天历史。

本机任务也走同一持久任务路径，支持独立验证。用户选择目标或通过文字明确指定；有歧义才询问。已经派发的任务保持原 owner，改变当前选择器不修改已有任务。

普通问题可以在会话中回答；远端执行问题必须渲染任务 interaction 表单，防止回答进入错误会话。

## 多节点视图

| 场景 | 行为 |
|---|---|
| A 正常在线 | 本机对话、任务、A 发起的远端任务 |
| B 查看本机 | B 的对话、执行任务和必要的远端任务说明 |
| 同时在 A、B 回答 | B 原子接受一次有效回答，另一处刷新真实状态 |
| B 不可达 | A 标注连接中断、缓存状态和最后更新时间 |
| A 下线 | 用户访问 B 的地址，独立登录后处理任务 |
| A 重连 | 根据水位补读 B 进度，更新原卡片 |

首版不聚合全网所有对话或自动同步聊天记录。B 能看到任务目标和必要上下文，不自动获得 A 的完整会话。

## 交互与结果

详情展示问答、审批、取消请求状态、恢复待核对、真实文件路径和内容预览。人工审批同时显示实际操作与范围，不能用问答按钮代替权限授权。

读取内容经 artifact/project 授权，限制大小；渲染文件、日志和模型文本时按不可信内容转义，避免执行其中的 HTML / 脚本。

文件完成显示实际读取结果和验证状态，用户验收另列。网页预览和 diff 是未来 coding 能力需求，首版无此发布门槛。

## 设置与登录

桌面启动器、托盘“打开 Asterhand”或 CLI `open --home <数据目录>` 使用当前节点的本地登录 token 打开 Web；启动 stdout 和日志不打印登录 token。浏览器关闭后节点继续运行，可从托盘重新打开。桌面图标与登录后启动在安装器独立选择，不在 Web 内修改系统快捷方式。

本机设置页“停止本机节点”与托盘退出共享收尾路径：先拒绝新接收，再停止本机执行、关闭监听并保存结果。Web 停止保留原确认提示；托盘仅在有执行或模型检查时确认。退出期间托盘显示“正在退出”，收尾完成后移除。远端已接收任务继续，本机中断任务重启后待核对。其他节点列表按既有 20 秒刷新周期观察本机离线。

登录后直接进入主界面，首次启动和诊断过期均不自动打开设置。节点设置由用户显式打开，名称/网络可先保存，模型凭据和文件授权目录按功能配置。远端访问必须建立信任并登录，认证与证书问题按 [节点设计](../node/design.md) 解决。

响应式布局覆盖手机窄屏；后台通知单独后置。关键 UI 流程采用 Playwright 测试，见 [测试设计](../testing/design.md)。

## 交付边界

页面包含设置与真实模型检查、节点列表与配对、任务提交、文件证据、事件详情、普通问题回答、取消及本机核对关闭。提交 request_id 在 sessionStorage 保留到收到确认，重试复用同一请求；远端状态由服务端 outbox 保存。

所有模型、文件和事件文本通过 textContent 渲染；CSP 仅允许自身脚本和样式。任务刷新在回答输入框获得焦点时暂停，避免覆盖正在输入的答案。

选择器区分默认和显式选择，显式目标与自然语言冲突时服务端拒绝变更。离线节点显示最后确认配置；结果标注执行节点、实际路径、大小、完整摘要和截断预览。

当前每次输入是独立任务，不提供长期多轮聊天记忆或原始 token 流。普通问答可通过任务持续进行。审批 UI 未启用；页面响应式布局已实现，手机远程登录和物理设备验证待后续，当前仅本机访问。

设置表单从 /api/settings 的 runtimes/providers 描述构建 agent、provider 和模型选项；后端验证同一选择。首版只显示 OpenClaw 和 DeepSeek，不展示尚未实现的 Hermes 或自定义 endpoint。凭据引用随选中 provider 保存，密钥留空保留、删除显式勾选；保存只报告配置和监听重启信息，不要求模型测试。

节点卡片分别显示在线和模型配置；任务按钮优先读取 `capabilities.model_tasks`，有能力字段时不回退旧 ready，缺失配置展示具体原因。老节点没有 capabilities 时沿用旧诊断门槛并提示验证或升级。离线目标用最后确认配置排队，目标节点负责最终准入。可选“测试模型与工具”展示未测试/执行中/通过/失败/过期，不把通过说成整个节点就绪，也不自动触发测试。

任务提交只有收到匹配请求 ID、归一化 route 请求摘要、固定拒绝码及 409 的持久拒绝时，才清除本次 pending ID，保留输入草稿，允许用户修复配置后重新提交新 ID。摘要以 Go Request 的固定字段顺序和 JSON 转义计算，跨语言 fixture 防止协议漂移。损坏响应、未知码、摘要不匹配及网络失败保留原 pending ID；迟到结果不能清除后续草稿。远端 outbox 的明确拒绝独立显示“对方未接收”，停止自动投递且不提供取消操作。

## 验收可见性

任务/outbox 先合并去重，再按入口 route 的 created 倒序；执行 job 取代 route 时保留逻辑提交时间和原始目标。收到远端结果不会把新任务移到旧本机任务之后。输入草稿、目标和授权项目不受排序影响。

发送禁用提示区分本机模型配置缺失、目标模型配置缺失、旧节点待验证和缺工作目录；空输入只禁用按钮，正在提交时按钮显示“正在发送…”。仅提交中使用 busy 光标，普通禁用不伪装处理中；刷新节点状态也遵守提交中的互斥。节点卡片展示最后认证确认的名称和具体连接错误。

设置保存返回当前就绪与监听是否需要重启；名称/网络变更保留模型检查，模型、凭据、运行时或授权目录变更清除旧检查状态。Tailscale 按钮同时填写 endpoint 和 peer_listen，页面明确展示监听变更尚未生效及 loopback 只能本机访问。

## 静态模块交付

服务显式为 `.js` 和 `.mjs` 返回 `application/javascript; charset=utf-8`，保留 `X-Content-Type-Options: nosniff`，避免依赖 Windows 文件关联的 MIME 类型。回归同时覆盖 GET/HEAD、模块内容和响应安全头；交付时以实际浏览器加载验证。

## 本机快捷输入

每个录制开始请求、轮询和取消都绑定页面内代次与服务端租约；失焦或结束录制会立即作废旧代次。旧轮询回复和失败不改变新录制，失焦后才返回的开始回复只释放对应租约。新建面板在首次显示前由控制器统一应用保存的主题，故障后的托盘恢复沿用相同初始化边界。主动关闭先隐藏浮层，再等待浏览器资源清理；配置无变化时的回复也反映刚完成的注册清理状态。

面板隐藏时标记 WebView 不可见并尝试挂起；呼出和确认草稿快照时恢复。隐藏期间只保留最新主题 ID，恢复后再通知编辑器，避免累积主题消息。暂停、恢复、快照和迟到回调由窗口代次约束；节点退出期间完成的初始化只清理，不再注册快捷键。

本机快捷输入设置使用独立的桌面配置服务和认证 API，不复用会阻止在途任务期间修改的节点设置事务，不修改模型就绪状态或 peer 元数据。默认 Ctrl+Alt+J，主题为星核/霜蓝；持久化只含快捷键、开关、主题和版本。设置期望值、系统有效注册、面板就绪与清理失败合并为一行状态：生效时显示“已生效 · 组合键”，期望与生效不一致、组合冲突、面板失败或旧注册待清理时显示对应原因；“重试生效”仅在已启用但未生效或待清理时出现。

Windows 面板由独立非提权 UI 进程中的 STA 承载 WebView2，资源为随包静态页面与受限原生桥，不持有通用 Web 登录凭据。主进程保存最多16,000 UTF-8字节的权威内存草稿，接受更新后确认；UI 重建从主进程恢复，主进程退出清空。LF 换行，Enter 发送、Shift+Enter 换行，Esc 隐藏、失焦保持显示；关闭面板不退出节点。主动禁用等待页面快照与主进程接收确认，未完成 IME 不静默销毁；崩溃仅恢复最后已接受文本。主题不替换编辑内容。托盘和设置分别展示期望配置、实际注册、面板准备/恢复/失败状态。来源、导航与资源约束沿用[快捷输入计划](../development/features/global-hotkey-quick-input/plan.md)，跨进程契约和验证见[进程隔离计划](../development/features/quick-input-process-isolation/plan.md)。

## 持续聊天面板

本节定义 WEB-CHAT-01—12 的交互设计；基础会话见[本机持续聊天计划](../development/features/local-node-chat/plan.md)，展示与桌面改进见[聊天桌面体验计划](../development/features/chat-desktop-experience/plan.md)。会话身份、数据保存和恢复状态由[持续会话设计](../assistant/conversations.md)定义，UI 不另建权威消息库。主 Web 任务页保持现有流程。

### 入口与布局

快捷输入拥有独立的“操作意图”，首版仅聊天可用；未来 skill/snippet/选择节点通过新增操作加入，不从任意输入文本猜测并执行。内部目标为稳定 node_id/role_id，首版显示当前节点名和“默认助手”，无需显示尚不可用的角色/节点选择器。

保持同一非提权宿主窗口，收起态展示从单行起步的输入、发送、历史入口和展开按钮；发送后自动扩展为上方消息、下方原输入框。箭头控制消息区可见性及对应输入布局，不清空草稿或改变生成。宽高按工作区/DPI 限制，长消息滚动，不因模型内容无限放大窗口。第一条消息之前也可打开最近对话和历史列表。

收起态由独立 composer-layout 模块用同样式的离屏 textarea 测量实际视觉行数，按 1—10 行增减编辑区和窗口高度；默认不预留空行，内部 extraRows 可调整为 1，空字符串始终一行。稳定滚动条占位避免溢出切换改变折行；超过十行或工作区可用高度时局部滚动。标题、操作、底栏与可见草稿确认区另计高度。展开态撤销收起尺寸覆盖，保留原有 104 px 编辑区和 760 DIP 窗口目标。

收起态默认隐藏滚动条，避免软换行与原生窗口增高之间的短暂溢出闪现。resize 使用单调请求 ID，原生私有桥回送 layout_applied（窗口代次、请求 ID、实际客户区逻辑高度）；只接受当前请求，并等待浏览器 viewport 与确认高度在像素取整容差内匹配。文本超过十行直接启用局部滚动；十行内只有确认限高且正文实际放不下才启用，不用延时猜测窗口是否完成。已确认限高且正文持续溢出时，新尺寸请求不撤销该事实，已有滚动条保持；正文已放得下或匹配的新确认解除限高后清除。展开态撤销该 overflow 覆盖。

布局读取当前可见文本，不写正文、revision 或提交快照。编辑、IME 临时输入、程序清空/回填、模式与辅助区变化、宽度/主题及恢复均触发重算。init 后同步测量并先 resize 再 initialized，保证隐藏宿主可就绪；后续按帧合并，目标高度不变不重复发送。隐藏停止观察与待执行帧，恢复补测；销毁释放测量层与监听。内容期望高度独立于实际 viewport，宿主工作区裁定后只限制可见输入高度，避免反馈循环。重算保留选区；未确认限高且正在扩高时，十行内文本及末尾编辑保持顶部锚定，scroll 事件也不允许提前露出残缺上一行。末尾跟随意图保留到新 viewport 就绪或确认限高后再执行，隐藏/展开/销毁解除锚定。稳定布局的末尾编辑按完整 scrollHeight 跟随，中部编辑保留原生 textarea 的滚动结果，不截断词尾估计光标行。详见[自动高度计划](../development/features/compact-input-auto-height/plan.md)。

尺寸请求的等待状态和末尾跟随意图只由当前 ID 的确认及匹配的 viewport 结束；旧大视口暂时可容纳新文本，不构成当前请求完成。快速清空后重输时，旧缩小即使迟到也不能取消新扩高的顶部锚定，当前分配完成后再跟随末尾。

| 启动或生成中 | 消息按提交顺序缓存在主进程；前端保持同一气泡和回复等待提示，不展示待发数量、准备阶段或撤回按钮；当前生成显示增量和停止按钮 |

| 停止回复 | 只在当前会话已确认接收且轮次未结束时显示；请求停止指定轮次，保留用户消息，不暂停队列，后续消息继续派发；完成竞争以真实结果为准 |
| 发送异常 | 明确拒绝或准备失败在消息旁显示“消息未送达”，接收不明显示“送达待确认”，接收后生成失败显示“回复失败”；不提供取回、撤回、取消发送或继续队列按钮。明确失败自动离队并保留近期失败展示，未知派发只核对原身份 |
| 新对话 / 选择历史 | 显式切换 conversation；有未发送草稿时在面板内确认“保留当前”或“丢弃草稿并切换”。确认绑定草稿修订，输入已变化或仍在 IME 组合时保留草稿并重新选择；确认前不创建新会话 |
| 切换时仍有生成 | 当前轮次和所有待发消息继续归原会话；新会话的发送追加至同一节点队列 |

默认恢复上次选中会话；新安装显示空态。首版最近会话选择可保存为元数据，窗口位置和滚动视图不承诺跨节点重启恢复。会话列表分页，默认按最近活动排序；标题使用创建时间等元数据。新对话改变模型上下文，不删除旧记录。

标题品牌与空白区可拖动，按钮、输入框和消息区排除。原生宿主负责移动和有效布局，本次 UI 生命周期内记住各显示器的位置；首次/跨屏呼出选择目标屏记录或默认位置，同屏重新呼出和内容高度变化保留位置。DPI、工作区与显示器变化时修正尺寸/位置保证标题与输入可操作。窗口系统映射见[桌面入口决策](../installation/adr/008-chat-window-desktop-presence.md)。

输入框无 placeholder，正常编辑不显示草稿生命周期说明；左下角只保留“Esc 隐藏”。发送后立即显示“正在回复”与 400 ms 步长的 1—3 点循环，从初始化、排队、派发到正常生成保持一致。当前会话没有发送时，不因其他会话的后台排队显示等待提示；新建空会话也不展示准备阶段。内部接收状态只用于去重、恢复与调度，不直接映射为正常聊天中的标签或按钮。实际失败保留异常提示，未知送达仍不自动重发；不新增完整的送达状态管理界面。状态依据操作身份、队列修订和结构化轮次；旧轮次历史或迟到队列快照不覆盖新状态。点固定占位且对读屏隐藏，减少动态效果时静态三个点。隐藏停止动画，恢复读取最新状态；当前轮次 completed 清空成功标签。

相同读取合并，历史读取串行并保留选择代次；切换先更新目标和界面，历史异步加载。慢历史读取最多占两个宿主请求槽，队列控制拥有预留容量。队列状态只传身份和状态，宿主重建逐条读取正文，保持 128 KiB IPC 帧上限。发送、取消和恢复不由 UI 重放；节点队列为权威。详见[操作队列计划](../development/features/chat-operation-queue/plan.md)。

### 回复与历史

普通用户/助手消息以可区分的头像或名称、文本、时间和状态显示。渲染文本、Markdown、代码块、数学公式与复制，不提供富文本输入、附件或语音控件。UI 依赖公共消息/事件类型，禁止解析自然语言“完成了”来更新运行或任务状态。

读取历史按数量和字节双重预算；超长单条可展开有界片段。向上滚动读取旧页并保持视口锚点；用户离开底部后不随 token 跳动，提供“回到最新”。按稳定消息/请求身份合并暂态、终态与重读结果，同文不同 ID 不合并。显示与历史保存分离：未保存的部分回复有提示，重新打开以权威记录为准。

折叠输入首次呼出只恢复会话列表与选择元数据；展开聊天、主动历史操作或发送才读取原生正文并按需启动 Gateway。向上分页以稳定消息 ID 和视口偏移保持阅读锚点，包括达到 200 条上限后淘汰窗口尾部的情况。离开最新页或底部时，生成更新只更新状态，不用最新页替换正在阅读的旧消息；点击“回到最新”才主动恢复最新窗口。游标失效时明确提示历史变化并重取最新页。

会话切换、隐藏、页面销毁清理定时器、监听器和订阅代次；主进程不因取消只读订阅而取消轮次。隐藏停止渲染，通过有界状态/快照补读恢复，避免后台 token 队列增长。连接断开显示连接状态，运行结果未知不伪装失败。

### 组件、安全与可扩展性

折叠历史面板时，已知运行中或送达待确认的轮次继续按原有 500 ms 节奏核对状态，不读取/绘制历史正文；终态清空动画并释放发送状态，下次展开再加载最新历史。首次折叠呼出仍只恢复元数据；隐藏整个窗口停止轮询，恢复后继续核对。

数学排版前拒绝用户宏定义与重绑定（`def/gdef/edef/xdef/let/futurelet/newcommand/renewcommand/providecommand`），保留原文；常见数学命令与 KaTeX 内置宏继续支持。单次消息窗口绘制的未缓存公式输入总量最多 8192 个 UTF-16 code unit，失败尝试也消耗预算；消息或窗口输出节点预算耗尽时不再调用排版器。未闭合单美元公式从起点到行尾原样保留，避免流式 Markdown 改写公式符号。

采用现有 WebView2、原生 ES module 与 IME 编辑器；KaTeX 为固定版本的本地静态依赖，不引入前端框架或在线 CDN。`chat-client` 管理封闭请求和回执，`chat-model` 管理有界窗口，`chat-renderer` 安全创建 DOM，数学模块管理公式分词/排版/预算，状态视图管理动画，`chat-ui` 管理选择、发送和可见性；组件替换保留会话客户端契约。隐藏后停止轮询与绘制，恢复时读取权威状态；会话列表每页 50 项，消息窗口最多 200 项/2 MiB。

禁原始 HTML、脚本、嵌入 frame、自动加载远程图片/媒体；链接默认只作文本展示，打开外部链接能力后置。代码仅显示/复制，Markdown 渲染须通过安全语法与节点白名单，不将原文直接拼入 innerHTML。复制使用受限、明确用户动作触发的桥能力，仅传当前可见文本，不开放读剪贴板或通用 native 调用。桥和源校验同时覆盖合法控件与恶意模型输出。

单条超过 32,768 个 UTF-16 code unit 或换行/Markdown 标记超过 256 个时，以可选中、可复制的纯文本展示，限制富文本节点膨胀；原文不丢弃。按钮复制最多 64 KiB，超过时提示使用选择与 Ctrl+C，不静默截断。

数学公式支持 `\( … \)`、`$ … $` 行内及 `\[ … \]`、`$$ … $$` 块级语法；美元语法采用保守边界以避免价格误识别。分词先隔离代码和数学内容，再处理普通 Markdown。闭合公式按源码/模式缓存，流式未闭合、错误及超限内容按原文展示；代码不转换。KaTeX 使用 `trust: false`、独立宏状态及有限展开/尺寸，另限制公式长度/数量、输出节点与缓存规模；不允许链接、外部图片或消息提供的 HTML。排版节点仅由受控渲染器产生，错误内容通过 textContent 展示，原始消息存储与复制不变。长公式局部横向滚动，字体和脚本/CSS 随包加载，CSP 仅增加所需的本地字体支持。

未来 `@节点/角色` 使用明确候选选择和稳定身份，跨机器时保持相同操作布局；连接/等待确认状态准确反映延迟。工具、审批、产物和多媒体通过类型化块扩展，首版不实现对应动作；未知块以安全占位提示，不执行内嵌指令。

## 聊天发送反馈与提示词状态

聊天界面移除提示词注入与应用状态的提示元素和渲染逻辑；底层仍保留观察与轮次元数据，未来 Web 诊断展示单独规划。发送/运行信息使用固定单行状态区，长提示省略，完整内容通过标题保留；状态变化不挤动消息历史。相关发送时序与布局验证见[发送稳定性与完成提醒](../development/features/chat-completion-attention/plan.md)。

发送立即展示有界本地气泡，并同时清空输入区显示，不等待冷连接、创建会话或持久接收回执。编辑器暂时保留该修订的待确认原文，主进程草稿仍可用于 UI 故障恢复；普通快照、展开/折叠与窗口调整不把显示清空误记为用户删除。用户继续编辑后由新草稿及新修订接管（即使再次输入相同文本）；迟到确认或失败恢复均不得覆盖新编辑。明确拒绝或发送前失败时，仅恢复仍属于该操作的原文；未知送达保持气泡核对，不自动恢复成可重发草稿。原生历史到达后按请求/轮次/消息身份合并。正常接收不增加成功标签，异常状态显示在对应用户气泡下；未知送达不自动重发。提示词适配状态仅保留在底层元数据，不进入聊天展示。Enter 发送、Shift+Enter 换行、Ctrl+Enter 保留兼容；IME 组合与候选确认过程优先于发送，重复按键不重复提交。完整读取按钮仅依据可见正文缺失，读取失败保留已有文本。

## 聊天连接状态标签

会话栏在对话 ID 后保留独立状态文本，仅使用连接中、已连接、无法连接。深色主题采用 #EAB308、#22C55E、#F87171，浅色主题采用 #856A00、#15803D、#DC2626，保持黄色、绿色、红色语义及文字可读性。状态通过 role=status 通知读屏，不提供原因 tooltip。连接状态不参与发送按钮准入或改变回复动画。

展开且可见时开始连接，之后每秒读取一次本地连接快照；刷新允许显式重连。折叠或隐藏停止状态读取，恢复立即读取。连接调用与状态轮询串行，迟到回复由可见性代次隔离；不调用模型、不自动重发。首次折叠呼出仍仅恢复会话元数据。
