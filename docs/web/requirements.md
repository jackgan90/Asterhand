# Web 交互需求

状态：已确认首版形式，实现契约见本领域 design.md，平台边界见测试文档。关联 R03、R08、R09、U07、C02。

| ID | 要求 |
|---|---|
| WEB-01 | 每个节点提供同样的统一入口：聊天、节点、任务、配置 |
| WEB-02 | 明确区分当前连接节点与任务执行节点，默认执行本机 |
| WEB-03 | 选择器和自然语言都可指定目标，冲突时澄清 |
| WEB-04 | 卡片显示目标、状态、最后进度，详情支持事件、问答、审批、取消和产物 |
| WEB-05 | A 展示其本地任务及发起的远端任务；B 展示其执行任务，包括 A 发来的任务 |
| WEB-06 | 断线显示最后已知状态；重连补读；刷新不重复提交 |
| WEB-07 | A 下线时可直接登录 B 查看和处理任务，对话历史不自动同步 |
| WEB-08 | 手机使用同一响应式页面，不要求原生 App 或后台主动推送 |
| WEB-09 | 配置密钥使用专用表单，与聊天数据分离 |
| WEB-10 | 本机与远端任务按原提交时间统一排序；路由转执行和刷新保留卡片位置，禁用提交必须显示具体原因 |
| WEB-11 | 本机快捷输入设置独立于模型与任务配置，支持 Ctrl+Alt+J 默认组合、自定义、禁用、恢复默认、录制及主题；保存时与启动时检测实际全局注册冲突，设置只保存在当前节点 |
| WEB-12 | Windows 快捷输入面板支持有界 Unicode 多行草稿、IME、收起恢复和主题切换；主进程保存原生内存草稿，独立 UI 中断后恢复已接受文本，主动销毁等待快照确认；Shift+Enter 换行，Enter 显式发送聊天，草稿不持久化 |

实际用户验收必须在页面完成，不要求手动构造 HTTP 请求或进入运行时 CLI。

WEB-11/12 的 Windows 首版已实现并完成用户验收；隐藏 CPU 性能限制、工程覆盖与专项验证边界见[快捷输入验证](../development/features/global-hotkey-quick-input/validation.md)。

已实现 WEB-01—07/09 的本机与配对任务页面主路径。WEB-04 审批未开放；WEB-08 仅响应式布局，当前 loopback 部署不提供手机远程登录。真实设备支持边界见 [平台矩阵](../testing/platforms.md)。

## 快捷输入的会话面板

以下要求已接入当前源码，验证边界见[本机持续聊天计划](../development/features/local-node-chat/plan.md)。WEB-12 的原文本编辑范围增加显式发送，Shift+Enter 换行、IME、内存草稿和进程隔离规则继续有效。

| ID | 要求 |
|---|---|
| WEB-CHAT-01 | 快捷输入保持多功能入口；发送聊天后自动展开消息区，复用同一输入框，箭头折叠/展开不取消生成，历史入口始终可用 |
| WEB-CHAT-02 | 按钮/Enter/Ctrl+Enter 显式发送，Shift+Enter 换行，IME 组合期间不发送；发送快照与新草稿分开，可靠 ACK 不清空后来编辑 |
| WEB-CHAT-03 | 提供固定显示；未固定失焦隐藏，固定时可切其他应用阅读；Esc/同键隐藏不取消，后台回复不抢焦点，旧消息滚动位置保持 |
| WEB-CHAT-04 | 新对话、简单会话列表、最近一页和更早历史、可见的发送/生成/保存状态、停止按钮；UI 重建从权威历史与运行状态恢复 |
| WEB-CHAT-05 | 文本/Markdown/代码块安全展示并可复制；禁原始 HTML、自动远程资源和危险 URL，不从模型文本推断任务状态；内容块为未来媒体保留类型边界 |

- WEB-CHAT-06：发送后立即显示本地气泡并清空输入区显示，待确认原文保留为有界恢复快照；明确拒绝时仅在用户尚未继续编辑的情况下恢复原文，未知送达保持核对且不自动重发；按稳定身份合并原生历史；正常接收无额外成功标签，拒绝、送达待确认和回复失败分别提示。
- WEB-CHAT-07：Enter 发送、Shift+Enter 换行、Ctrl+Enter 兼容发送；输入法确认候选不发送，Esc 保持隐藏。
- WEB-CHAT-08：仅可见正文未完整时显示完整读取入口；非展示字段的截断不触发按钮，全文读取失败保留原预览。
